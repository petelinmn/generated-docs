## Detail levels

Every topic always has an `overview` — a short version and a map of the levels. Beyond that, a topic is generated up to the required level:

| Level | What | Files |
|---|---|---|
| 1 | Basic theory | `basics.ru.md`, `basics.en.md` |
| 2 | Advanced theory | `advanced.ru.md`, `advanced.en.md` |
| 3 | Expert theory: a near-complete reference for the topic, gotchas, interview questions with answers | `expert.ru.md`, `expert.en.md` |
| 4 | Self-check: quiz and exercises | `quiz.*.md`, `exercises.*.md` |
| 5 | Runnable examples — for non-trivial things | `code/examples/`, `code/solutions/` |
| 6 | Tests — for important things | `code/tests/` |

- At levels 1–4, code lives only inside md, but it is verified by running it before publishing.
- `level N` means all levels up to N; individual levels can be listed: `levels 1,4`.
- Each track has a default level: C# — 6 (exhaustive, with tests), the others — 4.
- A level can be raised at any time: missing levels are added, existing files are not rewritten.

## Structure

```text
generated-docs/
├── README.md               language choice
├── README.ru.md / .en.md   you are here
├── PROGRESS.md             learning progress (checkboxes)
├── PLAN.md                 learning order, stages, backlog
├── CLAUDE.md               generation rules (Claude reads them automatically)
├── _templates/             document templates
├── tools/check-docs.ps1    automatic documentation checks
├── .claude/skills/         the /learn, /quiz-me, /verify commands
└── tracks/<track>/
    ├── overview.ru.md / .en.md   the technology in brief + roadmap
    ├── modules/NN-slug/          topics in learning order
    ├── libraries/<name>/         libraries (tools/ in kubernetes and linux)
    ├── recipes/<feature>/        "how to implement feature X"
    ├── projects/<name>/          final project specs + your solution in src/
    └── review.md                 mistakes from /quiz-me, for review
```

## How to work

1. `/learn python 14 level 2` or `/learn csharp` (the track's default level) — Claude generates the material (`status: draft`).
2. Read the `overview`, then `basics`, `advanced`, `expert` — as far as you need.
3. If there is a `code/` folder: run the examples and tests, change the code and see what breaks.
4. Take the `quiz` or run `/quiz-me python/14-asyncio` for an interactive quiz in the chat. Solve the `exercises`.
5. Need more depth — `/learn python 14 level 4`: expert theory and self-check are added.
6. `/verify tracks/python/modules/14-asyncio` — independent verification → `verified`.
7. Tick `[x]` in [PROGRESS.md](PROGRESS.md).

## Commands

| Command | What it does |
|---|---|
| `/learn <topic> [level N]` | documentation on any topic up to level N, or raising the level of an existing one |
| `/quiz-me <track>/<module>` | interactive quiz: one question at a time, mistakes explained |
| `/verify <path>` | facts, tests, translation, links → `verified` |
| `powershell -NoProfile -ExecutionPolicy Bypass -File tools/check-docs.ps1 [path]` | automatic checks: ru/en pairs, structure, front matter, broken links |
