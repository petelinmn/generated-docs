Сгенерируй учебные материалы. Запрос: $ARGUMENTS

Полные правила — в `CLAUDE.md`. Порядок работы:

1. **Разбери запрос.**
   - Масштаб темы (CLAUDE.md §2): трек, модуль, библиотека или инструмент, рецепт. Найди трек в `tracks/`; если его нет — это новый трек. Номер или slug (`python 14`, `csharp async-await`) ищи в дорожной карте трека.
   - Уровень (CLAUDE.md §1): `level N` / «уровень N» — уровни 1…N; `levels 1,4` — перечисленные. Не указан — `default_level` из overview трека, иначе 4. Уровень 6 требует 5: если просят 6 без 5, добавь 5.

2. **Сравни с тем, что уже есть.**
   - Материала нет — создаёшь его с нуля до нужного уровня.
   - Материал есть — прочитай `levels` в его overview. Создаёшь **только недостающие** уровни. Существующие файлы не переписываешь: только добавляешь в них ссылки на новые уровни.
   - Все запрошенные уровни уже есть — покажи, что есть, и спроси, нужно ли что-то обновить.

3. **Собери контекст:**
   - шаблоны из `_templates/`;
   - overview трека: окружение, дорожная карта, соседние темы — чтобы учесть пререквизиты и не дублировать;
   - если есть соседние готовые модули — их стиль;
   - существующие уровни этого материала — новые уровни на них опираются;
   - **связанные материалы во всех треках**: Grep по `tags:` и заголовкам в `tracks/`. Запиши список — он нужен для перекрёстных ссылок.

4. **Сверь факты** по официальной документации для всего, что зависит от версии: API, флаги, значения по умолчанию, поведение. Зафиксируй версию.

5. **Новый трек** (целая технология):
   - `tracks/<track>/overview.ru.md` и `overview.en.md` по `_templates/track-overview.md`: кратко о технологии, окружение (инструменты, тестовый фреймворк, команды запуска), `default_level`, дорожная карта из трёх частей, библиотеки, рецепты, проекты, связанные треки;
   - все пункты дорожной карты — в `PROGRESS.md` (без отметок);
   - строка о тестовом стеке — в таблицу CLAUDE.md §7;
   - ссылка на трек — в `README.ru.md` и `README.en.md`;
   - артефакты новой технологии — в `.gitignore`;
   - затем модули по порядку дорожной карты (шаг 6): не больше 3 за запуск, если пользователь не сказал иначе. В конце предложи продолжить.

6. **Материал** (модуль, библиотека, рецепт) — создавай нужные уровни в таком порядке:
   1. Уровни 5–6, если нужны: `code/` с примерами для нетривиального, решениями упражнений и тестами для важного. Запусти тесты и добейся зелёного прогона.
   2. Уровни 1–3 (`basics`, `advanced`, `expert`). Код в md уровней 1–4 сначала проверь запуском во временной папке (scratchpad); вывод — из реального запуска. Если есть уровень 5, фрагменты кода берутся из файлов `code/`.
   3. Уровень 4: `quiz` и `exercises`. Решения упражнений с кодом — под спойлерами.
   4. `overview`: краткая версия и таблица «Уровни материала»; поле `levels` во front matter.
   5. Английские версии всех новых документов — полный эквивалентный перевод.
   6. Строки навигации по уровням во всех файлах уровней материала — с учётом новых уровней.
   7. Перекрёстные ссылки в обе стороны (CLAUDE.md §6) в обеих языковых версиях.
   8. Дорожная карта трека (обе версии) и `PROGRESS.md`.
   9. `.gitignore`, если появились новые артефакты.

7. **Самопроверка** по чек-листу CLAUDE.md §13, включая `powershell -NoProfile -ExecutionPolicy Bypass -File tools/check-docs.ps1 <путь к материалу>`. Статус новых файлов — `draft`.

8. **Отчёт:**
   - что создано и до какого уровня;
   - результат проверок: сколько фрагментов проверено запуском, сколько тестов прошло;
   - какие связанные материалы получили ссылки;
   - что не удалось проверить (блоки `⚠️ Проверить`).

   Предложи запустить `/verify` и назови команду повышения уровня, если материал создан не на максимальном.
