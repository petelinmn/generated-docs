# CLAUDE.md

Личная база знаний для изучения технологий: теория, квизы, упражнения, запускаемые примеры и тесты. Контент генерирует Claude по правилам ниже, пользователь изучает его и проверяет на практике.

**Правила универсальны.** Они применяются к любой теме: языку, инструменту, библиотеке, алгоритму, фиче, концепции. Текущие треки (`csharp`, `python`, `javascript`, `typescript`, `kubernetes`, `linux`, `llm`) — только стартовый набор. Новая тема получает материалы по тем же правилам.

## 1. Уровни детализации

Каждая тема генерируется до нужного **уровня детализации**. Уровни 1–4 — только md-файлы: примеры кода находятся внутри документов. Уровни 5–6 добавляют папку `code/`.

| Уровень | Что | Файлы |
|---|---|---|
| — | **Обзор**: краткая версия и карта уровней. Создаётся всегда | `overview.ru.md`, `overview.en.md` |
| 1 | **Базовая теория**: для первого знакомства — зачем, как пользоваться, базовые сценарии | `basics.ru.md`, `basics.en.md` |
| 2 | **Продвинутая теория**: нетривиальные сценарии, best practices, частые ошибки, производительность | `advanced.ru.md`, `advanced.en.md` |
| 3 | **Экспертная теория**: практически полный справочник по теме (80–100% её возможностей), внутреннее устройство, подвохи, вопросы с собеседований с ответами | `expert.ru.md`, `expert.en.md` |
| 4 | **Самопроверка**: квиз и упражнения, решения — в md под спойлером | `quiz.*.md`, `exercises.*.md` |
| 5 | **Запускаемые примеры**: компилируемый код, чтобы легко погрузиться. Только для нетривиального — простейшие вещи остаются в md | `code/examples/`, `code/solutions/` |
| 6 | **Тесты**: юнит-тесты для важных примеров и решений | `code/tests/` |

**Как задаётся уровень**

- `level N` (или «уровень N») означает все уровни от 1 до N. Например, `/learn python 14 level 2` создаёт overview, базовую и продвинутую теорию.
- Можно перечислить уровни явно: `levels 1,4` — только базовая теория и самопроверка. Уровень 6 требует уровня 5: тестам нужен код.
- Уровень не указан → берётся `default_level` из front matter overview трека. Если его нет — уровень 4.
- Текущие значения по умолчанию: `csharp` — 6 (основная специализация, нужна исчерпывающая информация с тестами), `system-design` — 6; остальные треки — 4.

**Повышение уровня**

- Если материал уже существует на более низком уровне, `/learn <тема> level N` **добавляет недостающие уровни**. Существующие файлы при этом не переписываются, только дополняются ссылками.
- Уровни, которые есть у материала, перечислены в front matter его overview: `levels: [1, 2]`. После повышения уровня список обновляется.
- Overview всегда показывает таблицу уровней. Для отсутствующих уровней в таблице указана команда, которая их добавит.

**Требования к уровню 3.** Экспертная теория — это почти исчерпывающий справочник по теме, а не только «продвинутые детали»:

- справочник по всем возможностям темы: синтаксис, варианты, ограничения, значения по умолчанию — в таблицах;
- внутреннее устройство: как это работает на уровне компилятора или runtime;
- подвохи: неочевидное поведение с кодом, реальным результатом и объяснением;
- 10–20 вопросов с собеседований, включая вопросы с подвохом. Ответы — под спойлером;
- компромиссы и альтернативы.

Для трека-языка экспертные файлы всех модулей вместе должны покрывать 80–100% основных возможностей языка.

## 2. Масштаб темы

| Масштаб | Пример запроса | Что создаётся |
|---|---|---|
| Целая технология | «документация по Python», «по Docker» | трек `tracks/<track>/`: overview трека (кратко о технологии + окружение + дорожная карта из трёх частей), затем модули по дорожной карте |
| Тема внутри технологии | «asyncio», «RBAC в Kubernetes» | модуль `tracks/<track>/modules/NN-slug/` |
| Библиотека или инструмент | «httpx», «k9s» | `tracks/<track>/libraries/<name>/`; в инфраструктурных треках — `tools/<name>/` |
| Реализация фичи | «JWT-аутентификация в ASP.NET Core» | рецепт `tracks/<track>/recipes/<feature>/` |
| Концепция вне конкретной технологии | «алгоритмы сортировки», «OAuth 2.0» | модуль в общем треке (`algorithms`, `system-design`, `security`, …); трек создаётся, если его ещё нет |

- Целая технология генерируется порциями: сначала трек, затем модули по порядку дорожной карты — до 3 модулей за запуск, если пользователь не попросил иначе.
- Дорожная карта трека делится на три **части** по сложности тем: `Часть 1. Основы`, `Часть 2. Продвинутые темы`, `Часть 3. Темы для опытных` (en: `Part 1. Fundamentals`, `Part 2. Advanced topics`, `Part 3. Expert topics`). Часть — это место модуля в порядке изучения, а уровень детализации — глубина материала по теме. Это разные вещи.
- Для рецептов уровни 1–3 означают: минимальное рабочее решение → production-ready → масштаб, edge cases, альтернативы.

## 3. Два языка

- Каждый файл документации существует в двух версиях: `<name>.ru.md` и `<name>.en.md`. Правило действует для всех учебных материалов, overview треков и корневого README.
- Версии эквивалентны: те же разделы в том же порядке, тот же код, те же вопросы и ответы. Это полный перевод, а не пересказ. Меняешь одну версию — в том же действии меняй вторую.
- Сразу под заголовком H1 стоит строка-переключатель языка (обычный абзац, не цитата):
  - в `.ru.md`: `🌐 **Русский** · [English](<name>.en.md)`
  - в `.en.md`: `🌐 [Русский](<name>.ru.md) · **English**`
- Ссылки ведут на файлы того же языка: из `.ru.md` — на `.ru.md`, из `.en.md` — на `.en.md`.
- Код одинаков в обеих версиях, комментарии в нём на английском.
- Служебные файлы не дублируются и пишутся на русском: `CLAUDE.md`, `PLAN.md`, `PROGRESS.md`, `.claude/skills/`, `tools/`. Шаблоны в `_templates/` написаны на английском с русскими заголовками в комментариях. Личные файлы пользователя (`notes.md`, `review.md`) пишутся на любом языке.
- Русская версия: английский термин даётся в скобках при первом упоминании — «сборщик мусора (garbage collector, GC)». Устоявшиеся англицизмы (pod, middleware, deployment) не переводятся.

## 4. Обзор и файлы уровней

**`overview` — краткая версия**

- 300–800 слов, читается за 5–10 минут.
- Что это и зачем, 5–7 ключевых идей, один минимальный пример, когда применять и когда нет.
- Таблица «Уровни материала»: ссылка на каждый существующий уровень и команда `/learn …` для отсутствующих.
- Связанные материалы.
- Overview не содержит фактов, которых нет в файлах уровней.

**Файлы уровней 1–3** (`basics`, `advanced`, `expert`):

- Под переключателем языка — строка навигации по уровням со ссылками на существующие файлы.
- Каждый файл самодостаточен на своём уровне и опирается на предыдущие ссылками, а не повторами.
- Если уровень 5 есть, у примеров стоит ссылка на файл в `code/`. Код в md — фрагмент этого файла.
- Если `expert` выходит больше ~8000 слов, тему делят на несколько модулей.

## 5. Точность

Цель — ноль фактических ошибок.

- Не писать по памяти то, что зависит от версии: API, сигнатуры, флаги CLI, значения по умолчанию, поведение. Сверять с официальной документацией, спецификацией или исходным кодом (WebSearch / web-fetch).
- Раздел «Источники» ссылается на конкретные страницы документации, а не на главные страницы сайтов.
- Версия технологии указывается в front matter (`versions`) и в тексте, если от неё зависит поведение.
- **Код в md (уровни 1–4)** проверяется запуском во временной папке (scratchpad) перед публикацией. В репозиторий этот код не попадает. Вывод в тексте — фактический, скопированный из запуска.
- **Код уровней 5–6** лежит в `code/`, все тесты проходят. Фрагменты в md совпадают с файлами в `code/`.
- Подвохи и ответы на вопросы с собеседований проверяются запуском так же, как примеры.
- Ответы квиза выводятся из проверенного текста уровней 1–3.
- Факт, который не удалось проверить, помечается блоком `> ⚠️ Проверить: …` вместо уверенного утверждения. Материал с такими блоками не получает `verified`.
- Статусы: `draft` — сгенерировано и самопроверено; `verified` — прошло независимую проверку `/verify`.

## 6. Перекрёстные ссылки

- Перед написанием материала найди существующие материалы по связанным понятиям **во всех треках**: Grep по `tags:` во front matter, заголовкам и именам папок в `tracks/`.
- При первом упоминании понятия, по которому есть материал, ставь на него inline-ссылку.
- В overview и файлах уровней есть раздел «Связанные материалы»: пререквизиты, следующие шаги, аналоги в других треках (например, C# async/await ↔ Python asyncio, Linux cgroups ↔ Kubernetes requests/limits).
- Ссылки должны быть двусторонними: добавь ссылку на новый материал в «Связанные материалы» напрямую связанных существующих материалов, в обеих языковых версиях.
- Ссылки ставятся только на существующие файлы. Исключение — дорожные карты в overview треков: там допустимы ссылки на ещё не созданные материалы.
- Сайт автоматически выделяет красным (класс `link-planned`, `.vitepress/theme/custom.css`) любую ссылку на несуществующий `.md`-файл во всём репозитории: в дорожных картах, README, PROGRESS. Ссылку на новый материал после его создания ничего не нужно менять: цвет исчезнет сам. Красных ссылок вне дорожных карт быть не должно: это ошибка, её ловит `tools/check-docs.ps1`.
- `tags` — ключевые понятия на английском в kebab-case (`async-await`, `event-loop`, `jwt`). Одно понятие обозначается одинаково во всех треках: по тегам ищутся связи.

## 7. Код и тесты (уровни 5–6)

- Идентификаторы и комментарии в коде — на английском. Комментарии короткие и объясняют «почему», а не «что».
- **Уровень 5:** запускаемые примеры — только для нетривиального: где полезно запустить, поменять и посмотреть, что сломается. Простейший синтаксис остаётся в md. Сюда же входят решения упражнений (`code/solutions/`).
- **Уровень 6:** тесты для важных примеров и решений — тех, где проверка поведения учит или защищает от ошибки. Пример делается проверяемым: возвращает значение или даёт наблюдаемый эффект.
- `code/` каждого материала самодостаточен: свои зависимости, всё запускается одной командой из этой папки.
- Используется стандартный тестовый фреймворк экосистемы. Команды перечислены в разделе «Окружение» overview трека.
- Тесты детерминированы: без сети, текущего времени и случайности. Исключение — интеграционные тесты: они явно помечены и пропускаются, если среда недоступна (нет кластера, нет API-ключа).
- Секреты передаются только через переменные окружения или `.env` (он в `.gitignore`).
- Опасные команды сопровождаются предупреждением и запускаются только в одноразовом окружении: контейнере, VM, кластере kind.

Структура `code/` (имена папок — по соглашениям экосистемы):

```text
code/
├── examples/    уровень 5: запускаемые примеры, нумерация в порядке появления в тексте
├── solutions/   уровень 5: решения упражнений
└── tests/       уровень 6: тесты для examples и solutions
```

Текущие треки:

| Трек | Устройство `code/` | Тесты | Запуск в `code/` |
|---|---|---|---|
| csharp | решение `Code.slnx`: `Examples/` (classlib), `Solutions/` (classlib), `Tests/` (`OutputType=Exe`); `global.json` с `"test": {"runner": "Microsoft.Testing.Platform"}` — без него xUnit v3 в .NET 10+ SDK не запускается (с .NET 11 вместо него можно задать `DOTNET_TEST_RUNNER=Microsoft.Testing.Platform`) | xUnit v3 (`xunit.v3`) | `dotnet test` |
| system-design | как csharp: `Code.slnx`, `Examples/`, `Solutions/`, `Tests/`, `global.json`; примеры на C#/.NET, сеть — только loopback на свободном порту | xUnit v3 (`xunit.v3`) | `dotnet test` |
| python, llm | `pyproject.toml`, `examples/exNN_name.py`, `solutions/`, `tests/test_*.py` (имя модуля Python не может начинаться с цифры) | pytest | `uv run pytest` |
| javascript | `package.json` (`"type": "module"`), `examples/exNN-name.js`, `solutions/`, `tests/*.test.js` | встроенный раннер `node:test` | `npm test` (`node --test`) |
| typescript | `package.json`, `tsconfig.json`, `examples/exNN-name.ts`, `solutions/`, `tests/*.test.ts` | vitest | `npm test` (`vitest run`); типы — `npx tsc --noEmit` |

| kubernetes | `examples/NN-name.yaml`, ресурсы в namespace `learn-NN` | bats: kubeconform + проверка в kind | `bats tests` |
| linux | `examples/NN-name.sh` (`#!/usr/bin/env bash`, `set -euo pipefail`, без замечаний shellcheck) | bats | `bats tests` |
| claude | `pyproject.toml`, `examples/exNN_name.py`, `solutions/`, `tests/test_*.py` | pytest (`uv run pytest`) | `uv run pytest` |
| kafka | как python: `pyproject.toml` (клиент `confluent-kafka`), `examples/exNN_name.py`, `solutions/`, `tests/test_*.py`; брокер — контейнер `apache/kafka:4.3.1` (KRaft) | pytest; тесты с живым брокером помечены `integration` и пропускаются без `localhost:9092` | `uv run pytest` |

Для новой технологии выбери её стандартный тестовый инструмент (Go — `go test`, Rust — `cargo test`, TypeScript — vitest и т. п.), опиши его в overview трека и добавь строку в эту таблицу.

Каждый файл примера начинается с заголовка на английском:

## 8. .gitignore

- Когда появляется новый вид артефактов — результат сборки, кэш, виртуальное окружение, локальные настройки, секреты, — он добавляется в `.gitignore` **в том же действии**, в котором появился. Это касается и новой технологии в треке, и нового инструмента в `code/`.
- Перед завершением работы проверь, что в репозитории нет новых неигнорируемых артефактов: `bin/`, `obj/`, `TestResults/`, `.venv/`, `__pycache__/`, `node_modules/` и т. п.
- Личные файлы пользователя (`notes.md`, `review.md`, `projects/*/src/`) не игнорируются: это его работа.

## 9. Структура и именование

```text
README.md, README.ru.md, README.en.md   точка входа
PROGRESS.md                             прогресс изучения — единственное место с чекбоксами
tools/check-docs.ps1                    автопроверка: пары ru/en, структура, front matter, ссылки, уровни
.vitepress/, package.json               сайт на GitHub Pages (VitePress): `npm ci && npm run docs:build`; публикует .github/workflows/pages.yml
tracks/<track>/
├── overview.ru.md, overview.en.md      кратко о технологии, окружение, дорожная карта
├── modules/NN-slug/                    материал (раздел 1)
├── libraries/<name>/  (или tools/)     материал
├── recipes/<feature>/                  материал
├── projects/<name>/                    overview.ru.md, overview.en.md (ТЗ) + src/ (решение пользователя)
├── cheatsheet.ru.md, cheatsheet.en.md  шпаргалка по треку (по мере изучения)
└── review.md                           ошибки из /quiz-me для повторения
```

Материал (модуль, библиотека, рецепт) — какие файлы есть, зависит от уровня:

```text
NN-slug/
├── overview.ru.md   overview.en.md      всегда
├── basics.ru.md     basics.en.md        уровень 1
├── advanced.ru.md   advanced.en.md      уровень 2
├── expert.ru.md     expert.en.md        уровень 3
├── quiz.ru.md       quiz.en.md          уровень 4
├── exercises.ru.md  exercises.en.md     уровень 4
├── notes.md                             личные заметки пользователя — не трогать
└── code/                                уровни 5–6
```

- Папки и файлы называются латиницей в kebab-case. Модули — `NN-slug`, двузначный номер задаёт порядок. Вставка между модулями — `10a-slug`, чтобы не ломать ссылки.
- Ссылки только относительные.
- В заголовках разделов, на которые ведут ссылки, не должно быть эмодзи: они ломают якоря.
- Обобщённые типы и всё с угловыми скобками в тексте оборачиваются в backticks (`` `List<T>` ``), иначе markdown съест `<T>`.
- Диаграммы — Mermaid, сравнения — таблицы.

Шаблоны написаны на английском. Русская версия повторяет структуру, перевод заголовков дан в комментариях `<!-- ru: … -->`. Служебные комментарии шаблона в итоговые файлы не переносятся. Раздел шаблона можно опустить, если для темы он не имеет смысла, но тогда он опускается в обеих версиях, а порядок остальных разделов сохраняется.

## 11. Front matter

Обязателен во всех `.ru.md` и `.en.md` внутри `tracks/`:

```yaml
---
title: "Asyncio"
lang: ru                  # ru | en
track: python
kind: module              # track | module | library | recipe | project
doc: advanced             # overview | basics | advanced | expert | quiz | exercises
slug: 14-asyncio
part: 2                   # часть дорожной карты: 1 | 2 | 3
tags: [asyncio, event-loop, coroutine]
versions: "Python 3.13"
status: draft             # draft | verified
updated: 2026-11-20
---
```

- В overview материала есть ещё поле `levels: [1, 2, 3, 4, 5, 6]` — какие уровни существуют. `tools/check-docs.ps1` сверяет его с файлами.
- В overview трека есть поле `default_level` — уровень по умолчанию для `/learn` в этом треке.

## 12. Квизы и упражнения (уровень 4)

- Квиз: 10–15 вопросов по существующим уровням теории. Если есть все три: 🟢 базовая ~40%, 🟡 продвинутая ~40%, 🔴 экспертная ~20%.
- Типы вопросов: один верный ответ, несколько верных, «что выведет код», «найди ошибку», открытый вопрос.
- Ответ спрятан в `<details>`: почему верный ответ верен, почему остальные неверны, и ссылка на файл уровня.
- Неверные варианты правдоподобны и отражают типичные заблуждения.
- Вопросы проверяют понимание, а не память на мелочи.
- Упражнения: 3–6 штук с нарастающей сложностью. Подсказка и решение с кодом — под спойлерами. Если есть уровень 5, решение также лежит в `code/solutions/`.

## 13. Чек-лист готовности материала

1. Существуют ровно те уровни, что перечислены в `levels` overview, в обеих языковых версиях, и эти версии эквивалентны.
2. Код уровней 1–4 проверен запуском; тесты уровня 6 проходят. Результат назван в отчёте.
3. Перекрёстные ссылки поставлены в обе стороны.
4. Материал есть в дорожной карте трека (в обеих версиях) и в `PROGRESS.md`, без отметки.
5. `.gitignore` покрывает все новые артефакты.
6. `powershell -NoProfile -ExecutionPolicy Bypass -File tools/check-docs.ps1 <путь>` выдаёт OK.
7. `updated` обновлён.

Чекбоксы в `PROGRESS.md` отмечает только пользователь. Не перезаписывать без запроса `notes.md`, `review.md` и `projects/*/src/`.

## 14. Команды

`.claude/skills/`: `/learn` — генерация и повышение уровня материалов по любой теме; `/quiz-me` — интерактивный квиз; `/verify` — независимая проверка и перевод в `verified`.
