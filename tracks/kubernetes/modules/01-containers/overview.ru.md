# Контейнеры и Docker

🌐 **Русский** · [English](overview.en.md)

## Коротко

Контейнер — обычный процесс Linux, который ядро изолирует от остальных (namespaces) и ограничивает по ресурсам (cgroups). Это не виртуальная машина: ядро общее с хостом. Образ (image) — неизменяемый набор слоёв с файлами приложения и метаданными запуска; из одного образа запускают сколько угодно контейнеров. Kubernetes запускает именно образы, поэтому без понимания Dockerfile, слоёв и реестров дальше не продвинуться.

## Ключевые идеи

- **Образ ≠ контейнер.** Образ — шаблон только для чтения, контейнер — его запущенный экземпляр с тонким слоем для записи. Всё, что контейнер записал, исчезает вместе с ним, если не вынесено в volume.
- **Образ состоит из слоёв.** Каждая инструкция `RUN`, `COPY`, `ADD` создаёт слой. Слои кэшируются и переиспользуются, поэтому порядок инструкций в Dockerfile влияет на скорость сборки.
- **Слой нельзя «удалить».** `RUN rm` в следующем слое лишь скрывает файл: образ с удалённым файлом в 20 МБ весит на 20 МБ больше базового.
- **Multi-stage сборка** отделяет инструменты сборки от рантайма: образ приложения на Go уменьшился с 516 МБ до 12.8 МБ.
- **Тег изменяем, digest — нет.** `app:1.0` может сегодня указывать на один образ, а завтра на другой; `app@sha256:…` — всегда на один и тот же.
- **Реестр** хранит образы; имя образа — `реестр/репозиторий:тег`. Kubernetes скачивает образы из реестра на ноды.
- **Приложение для контейнера** — один процесс в foreground, логи в stdout/stderr, конфигурация через переменные окружения, корректная реакция на `SIGTERM`.

## Минимальный пример

```dockerfile
# syntax=docker/dockerfile:1
FROM golang:1.24-alpine AS build
WORKDIR /src
COPY go.mod ./
COPY *.go ./
RUN CGO_ENABLED=0 go build -o /hello .

FROM scratch
COPY --from=build /hello /hello
EXPOSE 8080
ENTRYPOINT ["/hello"]
```

```text
$ docker build -t hello:multi .
$ docker run -d --name h1 -p 18080:8080 hello:multi
$ curl -s localhost:18080
Hello from 74d74856967e
```

Подробно, с исходным кодом приложения, — в [базовой теории](basics.ru.md).

## Когда применять, а когда нет

- ✅ Любое серверное приложение, которое должно одинаково запускаться на ноутбуке, в CI и в кластере.
- ✅ Изоляция зависимостей: разные версии рантаймов на одном хосте.
- ❌ Приложению нужно своё ядро или драйверы ядра: контейнер использует ядро хоста.
- ❌ Хранение данных «внутри» контейнера: после удаления контейнера они пропадут.
- ❌ Контейнер как граница безопасности для недоверенного кода: изоляция слабее, чем у виртуальной машины.
