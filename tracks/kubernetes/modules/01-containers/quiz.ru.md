# Квиз: контейнеры и Docker

🌐 **Русский** · [English](quiz.en.md)

> Сначала ответь сам, потом раскрывай ответ. Отметка показывает, из какого уровня вопрос: 🟢 [базовая теория](basics.ru.md) · 🟡 [продвинутая](advanced.ru.md) · 🔴 [экспертная](expert.ru.md).

## 1. 🟢 Что происходит с файлом, который контейнер записал в `/tmp`, после `docker rm`?

- A) Файл сохраняется в образе
- B) Файл исчезает вместе с контейнером
- C) Файл сохраняется в анонимном volume
- D) Файл копируется на хост

<details><summary>Ответ</summary>

**B.** Контейнер пишет в тонкий слой для записи поверх образа, и он удаляется вместе с контейнером. Образ неизменяем (A неверно). Volume появляется только если его объявили (C), на хост ничего не копируется (D). Чтобы данные пережили контейнер, используют volume.
→ [Базовая теория](basics.ru.md#данные-слой-для-записи-и-volume)

</details>

## 2. 🟢 Что верно про образ и контейнер?

- A) Образ — запущенный экземпляр, контейнер — шаблон
- B) Из одного образа можно запустить много контейнеров
- C) Контейнер содержит собственное ядро Linux
- D) Образ можно изменить, пока контейнер из него запущен

<details><summary>Ответ</summary>

**B.** Образ — неизменяемый шаблон, контейнер — его экземпляр (A перепутано). Ядро у контейнера общее с хостом (C неверно). Образ неизменяем (D неверно).
→ [Базовая теория](basics.ru.md#образ-и-контейнер)

</details>

## 3. 🟢 Откроет ли `EXPOSE 8080` в Dockerfile порт на хосте при `docker run` без флагов?

- A) Да, на порту 8080
- B) Да, на случайном порту
- C) Нет, порт не опубликован
- D) Да, но только для localhost

<details><summary>Ответ</summary>

**C.** `EXPOSE` лишь документирует порт. В опыте `docker port` для контейнера без `-p` вывел пустой результат. Порт публикуют `-p хост:контейнер`; `-P` публикует все `EXPOSE`-порты на случайные порты хоста.
→ [Экспертная теория](expert.ru.md#подвох-expose-не-публикует-порт)

</details>

## 4. 🟢 Как правильно упорядочить `COPY` в Dockerfile для быстрой пересборки?

- A) Сначала `COPY . .`, потом установка зависимостей
- B) Сначала манифест зависимостей и их установка, потом исходники
- C) Порядок не влияет на скорость
- D) Сначала самые часто меняющиеся файлы

<details><summary>Ответ</summary>

**B.** Кэш сбрасывается с первого изменившегося шага. Редко меняющееся ставят раньше. В опыте после правки `main.go` шаги `WORKDIR` и `COPY go.mod` взяты из кэша, пересобраны только `COPY *.go` и компиляция. Варианты A и D дают обратное, C неверно.
→ [Базовая теория](basics.ru.md#слои-и-кэш)

</details>

## 5. 🟡 Что выведут эти команды?

```dockerfile
FROM alpine:3.22
ENTRYPOINT ["echo", "entry"]
CMD ["default-arg"]
```

```bash
docker run --rm t:cmd
docker run --rm t:cmd custom-arg
```

- A) `entry default-arg` и `entry custom-arg`
- B) `default-arg` и `custom-arg`
- C) `entry default-arg` и `custom-arg`
- D) `entry` и `entry`

<details><summary>Ответ</summary>

```text
entry default-arg
entry custom-arg
```

**A.** `ENTRYPOINT` остаётся, аргументы после имени образа заменяют `CMD`. Вариант C был бы верен для образа только с `CMD`: тогда вся команда заменяется.
→ [Продвинутая теория](advanced.ru.md#entrypoint-и-cmd)

</details>

## 6. 🟡 Почему `docker stop` контейнера с `CMD ["sleep", "300"]` занял около 10 секунд, а с флагом `--init` — треть секунды?

- A) `sleep` долго освобождает ресурсы
- B) PID 1 не получает действий по умолчанию для сигналов, `sleep` игнорирует `SIGTERM`, и через 10 с приходит `SIGKILL`; `--init` пересылает сигнал
- C) Флаг `--init` ускоряет сеть
- D) Docker всегда ждёт 10 секунд

<details><summary>Ответ</summary>

**B.** В опыте 10.392 с против 0.336 с. Приложение на Go из примера остановилось за 0.45 с без `--init`: его рантайм обрабатывает `SIGTERM`. Вариант D неверен.
→ [Продвинутая теория](advanced.ru.md#pid-1-и-sigterm)

</details>

## 7. 🟡 Выберите все верные утверждения о слоях

- [ ] A) `RUN rm файл` в отдельном слое уменьшает образ
- [ ] B) Multi-stage позволяет не включать компилятор в финальный образ
- [ ] C) Значение `ARG` не попадает в `docker history`
- [ ] D) `.dockerignore` уменьшает контекст сборки

<details><summary>Ответ</summary>

**B, D.** A неверно: слой с файлом остаётся (образ 32.8 МБ против 12.8 МБ). C неверно: история показывает `RUN |1 TOKEN=abc …`. B верно: образ 516 МБ → 12.8 МБ. D верно: контекст 5 МБ → 111 байт.
→ [Продвинутая теория](advanced.ru.md)

</details>

## 8. 🟡 Что выведет `docker exec h1 sh -c ls`, если `h1` запущен из образа на `scratch`?

- A) Список файлов с `hello`
- B) Пустой вывод
- C) Ошибку: `exec: "sh": executable file not found in $PATH`
- D) Контейнер перезапустится

<details><summary>Ответ</summary>

**C.** В образе один файл `/hello`, оболочки нет. Для отладки подключают эфемерный контейнер (модуль 21).
→ [Экспертная теория](expert.ru.md#подвох-в-образе-на-scratch-нет-shell)

</details>

## 9. 🔴 Найди ошибку

```dockerfile
FROM alpine:3.22
ARG TOKEN
RUN wget --header "Authorization: $TOKEN" https://example.com/pkg.tgz
```

Образ собирают командой `docker build --build-arg TOKEN=abc .` и публикуют. В чём проблема?

<details><summary>Ответ</summary>

Значение `abc` записано в историю слоя (`RUN |1 TOKEN=abc …`) и доступно любому, кто скачает образ: `docker history --no-trunc`. Исправление: передавать секрет как секрет сборки.

```dockerfile
RUN --mount=type=secret,id=token \
    wget --header "Authorization: $(cat /run/secrets/token)" https://example.com/pkg.tgz
```

```bash
docker build --secret id=token,env=TOKEN .
```

Секрет монтируется только на время инструкции и в слой не попадает.
→ [Экспертная теория](expert.ru.md#подвох-arg-виден-в-истории-образа)

</details>

## 10. 🔴 Открытый вопрос

Образ `app:latest` загружен на ноду kind командой `kind load docker-image`, но под с `image: app:latest` остаётся в `ErrImagePull`. Объясни причину и предложи два способа исправить.

<details><summary>Ключевые пункты ответа</summary>

- Для тега `latest` (или без тега) `imagePullPolicy` по умолчанию `Always`: kubelet идёт в реестр, а образа там нет.
- Исправление 1: явный тег (`app:1.0`) и `imagePullPolicy: IfNotPresent`, затем `kind load docker-image app:1.0`.
- Исправление 2: опубликовать образ в реестр, доступный нодам кластера, и тогда `Always` отработает штатно.
- Побочный вывод: `latest` не говорит, какая версия запущена, это плохая практика и вне kind.

</details>

→ [Экспертная теория](expert.ru.md#подвох-latest-в-kubernetes)
