# Основы shell: квиз

🌐 **Русский** · [English](quiz.en.md)

> Сначала ответьте сами, затем раскройте ответ. 🟢 [базовый](basics.ru.md) · 🟡 [продвинутый](advanced.ru.md) · 🔴 [экспертный](expert.ru.md).

## 1. 🟢 Что означает код возврата 0?

- A) Команда не найдена
- B) Команда прервана
- C) Успех
- D) Ложь

<details><summary>Ответ</summary>

**C.** В shell ноль — успех, всё остальное — неудача. «Не найдено» — 127.
→ [Базовая теория](basics.ru.md)

</details>

## 2. 🟢 Что выведет `echo 'hi $USER'`?

- A) `hi $USER`
- B) `hi ` и имя пользователя
- C) Пустую строку
- D) Ошибку

<details><summary>Ответ</summary>

**A.** В одинарных кавычках ничего не раскрывается; имя подставилось бы в двойных.
→ [Базовая теория](basics.ru.md)

</details>

## 3. 🟢 Какой поток попадает в `|`?

- A) stdout и stderr
- B) Только stderr
- C) stdin
- D) Только stdout

<details><summary>Ответ</summary>

**D.** Для обоих нужно `2>&1 |` или `|&`.
→ [Базовая теория](basics.ru.md)

</details>

## 4. 🟢 Как узнать, встроенная ли команда?

- A) `echo $?`
- B) `type имя`
- C) `man -f имя`
- D) `ls имя`

<details><summary>Ответ</summary>

**B.** `type` знает об алиасах, функциях и встроенных командах. `man -f` ищет страницы справки.
→ [Базовая теория](basics.ru.md)

</details>

## 5. 🟢 Когда выполнится `b` в `a || b`?

- A) Параллельно с `a`
- B) Когда `a` завершилась неудачно
- C) Когда `a` успешна
- D) Всегда

<details><summary>Ответ</summary>

**B.** `&&` — после успеха, `||` — после неудачи.
→ [Базовая теория](basics.ru.md)

</details>

## 6. 🟡 Куда попадут ошибки в `cmd 2>&1 > f`?

- A) В файл `f`
- B) В `/dev/null`
- C) Пропадут
- D) Туда, куда stdout указывал до этого (обычно на экран)

<details><summary>Ответ</summary>

**D.** Перенаправления выполняются слева направо.
→ [Продвинутая теория](advanced.ru.md)

</details>

## 7. 🟡 Почему `sudo echo x > /etc/f` не работает?

- A) Файл открывает shell без прав root
- B) `sudo` не умеет `echo`
- C) `/etc` только для чтения
- D) Нужен `sudo -s` из-за кавычек

<details><summary>Ответ</summary>

**A.** Решение: `echo x | sudo tee /etc/f`.
→ [Продвинутая теория](advanced.ru.md)

</details>

## 8. 🟡 Что напечатает `B=2 true; echo "[$B]"` (B раньше не задавалась)?

- A) `[$B]`
- B) Ошибку
- C) `[]`
- D) `[2]`

<details><summary>Ответ</summary>

**C.** Присваивание перед командой действует только на окружение этой команды.
→ [Продвинутая теория](advanced.ru.md)

</details>

## 9. 🔴 Что выведет `x=3; echo {1..$x}`?

- A) `1 2 3`
- B) `{1..$x}`
- C) Ничего
- D) `{1..3}`

<details><summary>Ответ</summary>

**D.** Фигурные скобки раскрываются раньше переменных: в тот момент это не диапазон чисел.
→ [Экспертная теория](expert.ru.md)

</details>

## 10. 🔴 Счётчик увеличивают в `cmd | while read ...`. Что будет после цикла в скрипте без особых опций?

- A) Ошибка
- B) Прежнее значение: цикл работал в подпроцессе
- C) Число строк
- D) Всегда 0, даже если раньше было 5

<details><summary>Ответ</summary>

**B.** Изменения подпроцесса не возвращаются. Помогает `done < <(cmd)`.
→ [Экспертная теория](expert.ru.md)

</details>

## 11. 🟡 Выберите верные утверждения о `*`.

- [ ] A) Раскрывается и в двойных кавычках
- [ ] B) Без совпадений всегда даёт пустой список
- [ ] C) Раскрывается shell до запуска команды
- [ ] D) Не включает скрытые файлы по умолчанию

<details><summary>Ответ</summary>

**C, D.** В кавычках шаблон буквален, а без совпадений остаётся как есть (если не включён `nullglob`).
→ [Продвинутая теория](advanced.ru.md)

</details>

## 12. 🔴 Открытый вопрос: объясните по шагам, что делает shell с `grep -c "$pat" *.log > report 2>&1`.

<details><summary>Ответ</summary>

Ключевые пункты: разбор на слова с учётом кавычек; подстановка `$pat` без деления на слова; раскрытие `*.log` в имена; перенаправление stdout в `report`, затем stderr туда же; поиск `grep` в `PATH`, запуск; код возврата в `$?`.
→ [Экспертная теория](expert.ru.md)

</details>
