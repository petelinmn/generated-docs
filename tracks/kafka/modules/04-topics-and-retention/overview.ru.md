# Темы, хранение и компактация

🌐 **Русский** · [English](overview.en.md)

## Коротко

Записи в Kafka удаляет не чтение, а политика очистки темы. По умолчанию это **срок хранения** (`retention.ms`, в образе 168 ч): журнал состоит из сегментов, и удаляются целые сегменты. Альтернатива — **компактация** (`cleanup.policy=compact`): остаётся последнее значение каждого ключа, ключ удаляют записью `None` (tombstone). Число партиций можно увеличить, но уменьшить нельзя, и увеличение меняет отображение ключей.

## Ключевые идеи

- **Сегменты — единица удаления;** срок — верхняя граница: в опыте журнал опустел целиком, включая последние записи.
- **Смещения не переиспользуются:** после очистки нумерация продолжается.
- **`kafka-delete-records.sh`** сдвигает `low_watermark`.
- **`segment.bytes` не меньше 1 МиБ.**
- **Компактация** сохраняет смещения (с пропусками); активный сегмент не очищается.
- **Tombstone** — запись с ключом и значением `None`; потребитель обрабатывает его как удаление.
- **Добавление партиций:** часть ключей меняет партицию; старый производитель не сразу узнаёт о новых.

## Минимальный пример

```python
fresh("ret", retention_ms=4000, segment_ms=1500)   # topic with a 4 s retention
```

Всё запускалось на настоящем Apache Kafka 4.3.1 в Docker с ускоренными проверками очистки (см. [базовую теорию](basics.ru.md)).

## Когда применять и когда нет

| Задача | Политика |
|---|---|
| История событий за период | `delete` и `retention.ms` |
| Текущее состояние по ключу | `compact` |
| Нужно «вечное» хранение | хранилище вне Kafka |

- ❌ Не рассчитывайте, что последняя запись переживёт срок.
- ❌ Не добавляйте партиции без оценки влияния на порядок по ключам.
