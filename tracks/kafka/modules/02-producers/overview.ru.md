# Производители

🌐 **Русский** · [English](overview.en.md)

## Коротко

Производитель выбирает партицию записи (по явному номеру, по хешу ключа или сам), собирает записи в пакеты и отправляет их лидеру партиции. Надёжность задают `acks` и идемпотентность, задержку и пропускную способность — `linger.ms` и сжатие. Результат каждой записи приходит в обратном вызове.

## Ключевые идеи

- **Партиция:** явная > хеш ключа > выбор клиента; без ключа нет порядка и равномерности.
- **`acks`:** `0` — не ждать (смещение неизвестно), `1` — лидер, `all` — лидер и синхронные реплики.
- **`produce` асинхронна:** результат — в `on_delivery`, нужен `flush()`; ошибки: `MSG_SIZE_TOO_LARGE` при `produce`, `_MSG_TIMED_OUT` в обратном вызове.
- **Идемпотентность** требует `acks=all`; иначе `_INVALID_ARG`.
- **`linger.ms`** добавляет задержку (≈100 мс при `100`).
- **Сжатие** применяется к пакету; на реальных данных выигрыш в разы.

## Минимальный пример

```python
p = Producer({"bootstrap.servers": "localhost:9092", "acks": "all", "enable.idempotence": True})
p.produce("orders", key=b"user1", value=b"order-1", on_delivery=lambda err, msg: print(err, msg.offset()))
p.flush()
```

Всё запускалось на настоящем Apache Kafka 4.3.1 в Docker (см. [базовую теорию](basics.ru.md)).

## Когда применять и когда нет

| Задача | Настройка |
|---|---|
| Порядок записей клиента | ключ — идентификатор клиента |
| Нельзя терять и дублировать | `acks=all`, идемпотентность, проверка `err` |
| Низкая задержка | малый `linger.ms` |
| Экономия диска и сети | сжатие `lz4`/`zstd` |

- ❌ Не используйте `acks=0` для важных данных.
- ❌ Не забывайте `flush()` и проверку `err`.
