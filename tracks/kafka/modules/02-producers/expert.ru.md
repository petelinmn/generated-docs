# Производители: экспертный уровень

🌐 **Русский** · [English](expert.en.md)

**Уровни:** [overview](overview.ru.md) · [1. Основы](basics.ru.md) · [2. Продвинутый](advanced.ru.md) · **3. Эксперт** · [4. Квиз](quiz.ru.md)

Опирается на [базовую](basics.ru.md) и [продвинутую](advanced.ru.md) теорию. «Проверено» означает наблюдалось на одном брокере Apache Kafka 4.3.1 с `confluent-kafka` 2.16.2.

## Справочник

### Параметры клиента

| Параметр | Назначение | Проверено |
|---|---|---|
| `bootstrap.servers` | адреса для первого подключения | да |
| `acks` (`0`, `1`, `all`) | подтверждения брокера | да |
| `enable.idempotence` | идемпотентная отправка; требует `acks=all` | да (отказ при `acks=1`) |
| `linger.ms` | ожидание наполнения пакета | да (задержка ≈ значение) |
| `batch.size` | размер пакета | выставлялся, эффект не изолирован |
| `compression.type` (`none`, `gzip`, `snappy`, `lz4`, `zstd`) | сжатие пакетов | да |
| `message.timeout.ms` | срок доставки записи; по истечении `_MSG_TIMED_OUT` | да |
| `message.max.bytes` | максимальный размер записи на клиенте | косвенно (2 МБ отвергнуто) |
| `retries`, `retry.backoff.ms`, `delivery.timeout.ms`, `max.in.flight.requests.per.connection`, `transactional.id`, `partitioner` | повторы, порядок, транзакции, выбор партиции | не проверялись |

### API

| Элемент | Поведение | Проверено |
|---|---|---|
| `produce(topic, value=, key=, partition=, headers=, timestamp=, on_delivery=)` | постановка в очередь клиента | основные аргументы — да |
| `flush(timeout)` | ожидание отправки; возвращает число записей, оставшихся в очереди | `flush` — да |
| `poll(timeout)` | запуск обратных вызовов | да |
| ошибка в обратном вызове | `KafkaError` с `name()` и `str()` | да |

### Ошибки (проверено)

| Ситуация | Где проявляется | Код/имя |
|---|---|---|
| запись больше лимита | при `produce` | `MSG_SIZE_TOO_LARGE` (код 10) |
| брокер недоступен | в обратном вызове по таймауту | `_MSG_TIMED_OUT` |
| `enable.idempotence=True` и `acks=1` | при создании `Producer` | `_INVALID_ARG` |

### Измеренные соотношения (одна машина)

| Опыт | Результат |
|---|---|
| 20 000 записей, `acks` 0 / 1 / all | 0,15 / 0,16 / 0,13 с (разницы нет) |
| задержка одной записи, `linger.ms` 0 / 100 | ≈1 мс / ≈110 мс |
| сжатие 37 МБ повторяющихся данных | none 37,2; gzip 0,2; snappy 1,9; lz4 0,3; zstd 0,1 МБ |

## Внутреннее устройство

- **Очередь клиента и фоновый поток.** `produce` кладёт запись в очередь; отдельный поток собирает пакеты по партициям и отправляет их лидерам.
- **Пакет — единица сжатия и отправки.** Сжимается весь пакет; потому записи с повторяющимся содержимым сжимаются лучше (в опыте — на порядки).
- **Подтверждение приходит на пакет:** смещения записей пакета идут подряд.
- **Идемпотентность держится на номерах записей** (producer id и порядковые номера на партицию): брокер видит повтор и не добавляет его.

> ⚠️ Проверить: детали идемпотентности (PID, эпохи, номера последовательностей), размер пакета по умолчанию, алгоритм «липкого» выбора партиции без ключа и влияние `max.in.flight` на порядок описаны по документации и здесь не проверялись.

## Подвохи

### 1. `acks=0` не знает смещения

В отчёте доставки смещение `None` (проверено); потеря записи незаметна.

### 2. `produce` не отправляет

Нужны `flush()`/`poll()`.

### 3. Без ключа нет порядка и равномерности

Распределение непредсказуемо (проверено: две партиции из трёх).

### 4. Идемпотентность и `acks`

`enable.idempotence=True` с `acks=1` отвергается при создании (проверено).

### 5. Большая запись

Отвергается сразу при `produce` (проверено, 2 МБ); лимит есть и на брокере.

### 6. `linger.ms` — это задержка

Задержка записи при `linger.ms=100` — около 110 мс (проверено).

### 7. Сжатие на тестовых данных

Повторяющиеся данные сжимаются нереалистично хорошо (проверено): до 0,1 МБ из 37 МБ.

## Компромиссы и альтернативы

| Выбор | Плюсы | Минусы |
|---|---|---|
| `acks=all` + идемпотентность | сохранность и отсутствие дубликатов повторов | больше задержка и нагрузка |
| `acks=1` | быстрее | потеря при отказе лидера до репликации |
| `acks=0` | максимум скорости | потери без следа |
| больше `linger.ms` | больше полных пакетов | рост задержки |
| сжатие | меньше диска и сети | нагрузка на процессор |

## Вопросы с собеседований

<details><summary>1. Как производитель выбирает партицию?</summary>

Явная `partition`, иначе хеш ключа; без ключа — распределяет клиент.

→ [Основы](basics.ru.md#как-выбирается-партиция)

</details>

<details><summary>2. Что означают `acks=0/1/all`?</summary>

Не ждать, ждать лидера, ждать лидера и все синхронные реплики.

→ [Основы](basics.ru.md#подтверждения-брокера-acks)

</details>

<details><summary>3. Подвох: при `acks=0` в отчёте доставки смещение?</summary>

`None`: брокер не подтверждает.

→ [Подвох 1](#1-acks0-не-знает-смещения)

</details>

<details><summary>4. Зачем идемпотентный производитель?</summary>

Чтобы повторы отправки не создавали дубликатов записей в партиции.

→ [Продвинутая теория](advanced.ru.md#идемпотентный-производитель)

</details>

<details><summary>5. Подвох: можно ли включить идемпотентность с `acks=1`?</summary>

Нет: `_INVALID_ARG`, нужен `all`.

→ [Подвох 4](#4-идемпотентность-и-acks)

</details>

<details><summary>6. Что делает `linger.ms`?</summary>

Задаёт, сколько клиент ждёт наполнения пакета; увеличивает задержку доставки.

→ [Продвинутая теория](advanced.ru.md#пакеты-и-задержка-lingerms)

</details>

<details><summary>7. Зачем сжатие и чем оно платит?</summary>

Экономит диск и сеть; платит процессором. Сжимается пакет целиком.

→ [Продвинутая теория](advanced.ru.md#сжатие)

</details>

<details><summary>8. Что произойдёт при недоступном брокере?</summary>

После `message.timeout.ms` обратный вызов получит `_MSG_TIMED_OUT`.

→ [Основы](basics.ru.md#ошибки)

</details>

<details><summary>9. Подвох: `produce` вернулась без ошибки. Дошла ли запись?</summary>

Неизвестно до обратного вызова; нужны `flush()`/`poll()` и проверка `err`.

→ [Подвох 2](#2-produce-не-отправляет)

</details>

<details><summary>10. Как сохранить порядок записей одного клиента?</summary>

Использовать ключ (идентификатор клиента): записи одного ключа в одной партиции.

→ [Основы](basics.ru.md#как-выбирается-партиция)

</details>

<details><summary>11. Подвох: реалистичны ли цифры сжатия из опыта?</summary>

Нет: данные были крайне повторяющимися; на реальных данных выигрыш в разы.

→ [Подвох 7](#7-сжатие-на-тестовых-данных)

</details>

<details><summary>12. Что проверить в обратном вызове?</summary>

`err`: при ошибке запись не доставлена; её повторяют или сигнализируют.

→ [Основы](basics.ru.md#обратный-вызов-доставки)

</details>

## Шпаргалка

```text
Producer({"bootstrap.servers":..., "acks":"all", "enable.idempotence":True, "compression.type":"lz4", "linger.ms":5})
produce(topic, key=, value=, on_delivery=cb) ; poll() ; flush()        # cb(err, msg): err is None on success
partition: explicit > hash(key) > client-chosen (no key)
errors: MSG_SIZE_TOO_LARGE (at produce) ; _MSG_TIMED_OUT (callback) ; idempotence needs acks=all
```

- Ключ для порядка, `acks=all` и идемпотентность для надёжности.
- Проверяйте `err`, вызывайте `flush()`.
