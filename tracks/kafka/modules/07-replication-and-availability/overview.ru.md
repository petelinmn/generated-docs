# Репликация и доступность

🌐 **Русский** · [English](overview.en.md)

## Коротко

У каждой партиции есть **лидер** и **фолловеры** (копии на других брокерах); число копий — коэффициент репликации (RF). Синхронные реплики образуют **ISR**; при отказе лидера новым становится реплика из ISR. Надёжность записи определяют `acks=all` и `min.insync.replicas`: при RF=3 и `min.insync.replicas=2` кластер переживает потерю одного брокера без остановки записи. Метаданные ведёт кворум контроллеров KRaft.

## Ключевые идеи

- **Запись и чтение идут через лидера;** фолловеры копируют.
- **Отказ лидера:** новый лидер из ISR за секунды (в тесте брокер 1 из ISR `[1, 2]`).
- **`acks=all` + `min.insync.replicas=2`:** при двух отказах запись не принимается (`_MSG_TIMED_OUT`); `acks=1` проходит, но не защищена.
- **ISR восстанавливается** после запуска брокеров; **лидеры не обязательно возвращаются** к предпочтительным.
- **Без большинства контроллеров** метаданные не меняются (создание темы — таймаут).
- **RF=3** для важных тем; контроллеры в рабочей системе — отдельные.
- **Здоровье:** `--under-replicated-partitions` пуст.

## Минимальный пример

```bash
kafka-topics.sh --bootstrap-server kafka1:19092 --create --topic rep --partitions 3 --replication-factor 3 --config min.insync.replicas=2
```

Всё запускалось на настоящем кластере из трёх брокеров Apache Kafka 4.3.1 в Docker (см. [базовую теорию](basics.ru.md)).

## Когда применять и когда нет

| Задача | Настройка |
|---|---|
| Важные данные | RF=3, `min.insync.replicas=2`, `acks=all` |
| Максимальная скорость, допустима потеря | `acks=1` |
| Единственный брокер для разработки | RF=1 |

- ❌ Не считайте RF=3 защитой от потери двух брокеров.
- ❌ Не перезапускайте несколько брокеров сразу.
