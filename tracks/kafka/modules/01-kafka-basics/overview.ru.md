# Основы Kafka

🌐 **Русский** · [English](overview.en.md)

## Коротко

Kafka хранит записи в **журнале**: тема делится на партиции, каждая партиция — упорядоченная последовательность записей с возрастающими **смещениями**. Производитель дописывает записи, потребитель читает их, помня свою позицию; чтение ничего не удаляет, поэтому одни и те же данные читают многие независимые группы и перечитывают при необходимости.

## Ключевые идеи

- **Журнал, а не очередь:** запись остаётся до окончания срока хранения (по умолчанию 168 ч).
- **Тема → партиции:** порядок гарантирован только внутри партиции; партиции можно добавлять, но не убирать.
- **Ключ определяет партицию:** записи с одним ключом в одной партиции.
- **`produce` асинхронна:** результат — в обратном вызове, нужен `flush()`.
- **Позиция группы хранится в Kafka** (`__consumer_offsets`); `auto.offset.reset` действует, только если позиции нет.
- **KRaft:** метаданные хранит встроенный кворум контроллеров, без ZooKeeper.
- **Автосоздание тем включено** в этом образе: опечатка создаёт новую тему.

## Минимальный пример

```python
p = Producer({"bootstrap.servers": "localhost:9092"})
p.produce("orders", key=b"user1", value=b"order-1")
p.flush()
```

Всё запускалось на настоящем Apache Kafka 4.3.1 в Docker (см. [базовую теорию](basics.ru.md)).

## Когда применять и когда нет

| Задача | Kafka |
|---|---|
| Поток событий с повторным чтением и многими читателями | подходит |
| Журнал изменений, аудит, интеграция систем | подходит |
| Сложная маршрутизация и удаление после обработки | рассмотрите очередь ([RabbitMQ](../../../rabbitmq/overview.ru.md)) |

- ❌ Не ждите порядка по всей теме.
- ❌ Не полагайтесь на автосоздание тем в рабочей системе.
