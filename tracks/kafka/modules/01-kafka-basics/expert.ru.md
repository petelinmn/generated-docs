# Основы Kafka: экспертный уровень

🌐 **Русский** · [English](expert.en.md)

**Уровни:** [overview](overview.ru.md) · [1. Основы](basics.ru.md) · [2. Продвинутый](advanced.ru.md) · **3. Эксперт** · [4. Квиз](quiz.ru.md)

Опирается на [базовую](basics.ru.md) и [продвинутую](advanced.ru.md) теорию. «Проверено» означает наблюдалось на одном брокере Apache Kafka 4.3.1 (KRaft) с `confluent-kafka` 2.16.2.

## Справочник

### Модель

| Понятие | Смысл | Проверено |
|---|---|---|
| запись (record) | ключ, значение, заголовки, метка времени | ключ и значение — да |
| тема (topic) | именованный поток записей | да |
| партиция | упорядоченный журнал внутри темы | да |
| смещение (offset) | номер записи внутри партиции | да |
| low / high watermark | первое доступное смещение / смещение следующей записи | да |
| группа потребителей | набор читателей с общей сохранённой позицией | да |
| брокер, контроллер | хранение партиций / метаданные кластера (KRaft) | да |

### Клиентский API (`confluent-kafka` 2.16.2)

| Элемент | Поведение | Проверено |
|---|---|---|
| `Producer.produce(topic, key=, value=, on_delivery=)` | асинхронная постановка записи в буфер | да |
| `Producer.flush()` | дожидается отправки и вызывает обратные вызовы | да |
| `msg.partition()`, `msg.offset()` в обратном вызове | где запись легла | да |
| `Consumer.subscribe([topic])`, `poll(timeout)` | чтение с выбором партиций брокером | да |
| `Consumer.get_watermark_offsets(TopicPartition, timeout)` | `(low, high)` | да |
| `Consumer.commit(asynchronous=False)` | фиксация позиции группы | да |
| `AdminClient.create_topics([NewTopic(...)])` | словарь «тема → future»; `None` при успехе | да |
| `AdminClient.list_topics(timeout)` | метаданные, партиции темы | да |

### Конфигурация и значения по умолчанию (образ `apache/kafka:4.3.1`)

| Параметр | Значение | Источник |
|---|---|---|
| `process.roles` | `broker,controller` | `server.properties` |
| `num.partitions` | 1 | `server.properties` |
| `log.retention.hours` | 168 | `server.properties` |
| `log.segment.bytes` | 1073741824 | `server.properties` |
| `offsets.topic.replication.factor` | 1 | `server.properties` |
| автосоздание тем | включено (запись в несуществующую тему создала её с 1 партицией) | проверено |
| `auto.offset.reset` клиента | в примерах задавался явно; значения `earliest` и `latest` проверены, значение по умолчанию не проверялось | частично |

### Ошибки (проверено)

| Ситуация | Результат |
|---|---|
| уменьшить число партиций | `InvalidPartitionsException: The topic orders currently has 3 partition(s); 2 would not be an increase.` |
| увеличить число партиций (3 → 4) | выполнено |
| `produce` в несуществующую тему | тема создана автоматически, партиция 0 |

## Внутреннее устройство

- **Партиция — каталог из сегментов.** Имя файла сегмента — смещение его первой записи; `.log` хранит записи, `.index` — разрежённый индекс смещений, `.timeindex` — индекс времени (проверено наличием файлов).
- **Порядок гарантируется внутри партиции.** Смещения возрастают на 1; между партициями порядка нет (проверено: смещения 0, 1, 2 в каждой партиции независимо).
- **Позиция читателя хранится в Kafka** во внутренней теме `__consumer_offsets` (проверено наличием каталогов; содержимое темы здесь не разбиралось).
- **Ключ определяет партицию.** Один ключ — одна партиция (проверено на двух ключах); сама функция (хеш murmur2 по умолчанию в Java-клиенте) в `confluent-kafka` реализована в librdkafka.
- **Запись асинхронна:** `produce` лишь ставит её в очередь клиента; подтверждение — в обратном вызове.

> ⚠️ Проверить: точная формула выбора партиции по ключу в librdkafka (какой хеш используется по умолчанию в 2.16.0), структура индексов и формат записи на диске здесь не проверялись; в частности, привязка ключей `user0` и `user1` к партициям 2 и 1 наблюдалась, но не выведена.

## Подвохи

### 1. Партиции нельзя уменьшить

Только увеличить; уменьшение — `InvalidPartitionsException` (проверено).

### 2. Увеличение партиций меняет отображение ключей

Новая партиция меняет число, по которому берётся остаток от хеша, поэтому ключи могут сменить партицию; порядок записей одного ключа относительно старых записей не сохраняется (по документации; здесь не проверялось).

### 3. Автосоздание тем

Опечатка в имени темы создаст новую тему с 1 партицией (проверено), а не ошибку. В рабочей системе автосоздание обычно отключают.

### 4. `auto.offset.reset` не действует при сохранённой позиции

Повторный запуск группы не вернулся к началу (проверено).

### 5. `produce` — не отправка

Без `flush()`/`poll()` обратные вызовы не сработают, а запись может не уйти.

### 6. Пустая партиция

Партиция 0 осталась пустой при двух ключах (проверено): распределение по ключам может быть неравномерным.

### 7. Данные в `/tmp`

В образе данные лежат в `/tmp/kraft-combined-logs`: удаление контейнера удаляет всё.

## Компромиссы и альтернативы

| Выбор | Плюсы | Минусы |
|---|---|---|
| Журнал Kafka | повторное чтение, много читателей, масштабирование | нет маршрутизации по обменникам, порядок только в партиции |
| Очередь ([RabbitMQ](../../../rabbitmq/overview.ru.md)) | гибкая маршрутизация, удаление после обработки | нет повторного чтения (кроме streams) |
| Больше партиций | параллелизм | нельзя уменьшить, порядок только внутри |
| Меньше партиций | проще порядок | меньше параллелизма |

## Вопросы с собеседований

<details><summary>1. Чем журнал Kafka отличается от очереди?</summary>

Записи не удаляются при чтении, а хранятся по сроку хранения; читатели независимы и сами хранят позицию.

→ [Основы](basics.ru.md#журнал-вместо-очереди)

</details>

<details><summary>2. Что такое смещение?</summary>

Порядковый номер записи внутри партиции.

→ [Основы](basics.ru.md#журнал-вместо-очереди)

</details>

<details><summary>3. Подвох: порядок записей гарантирован по всей теме?</summary>

Нет: только внутри партиции.

→ [Подвох 6](#6-пустая-партиция)

</details>

<details><summary>4. Зачем темы делят на партиции?</summary>

Для параллельной записи и чтения и масштабирования; партиции обрабатываются независимо.

→ [Основы](basics.ru.md#тема-и-партиции)

</details>

<details><summary>5. Как ключ влияет на партицию?</summary>

Записи с одним ключом попадают в одну партицию (проверено), что сохраняет их порядок.

→ [Основы](basics.ru.md#запись)

</details>

<details><summary>6. Подвох: `produce` вернулся без ошибки. Запись на брокере?</summary>

Не обязательно: `produce` лишь ставит запись в буфер; результат — в обратном вызове после `flush()`/`poll()`.

→ [Подвох 5](#5-produce--не-отправка)

</details>

<details><summary>7. Что делает `auto.offset.reset`?</summary>

Определяет начальную позицию группы без сохранённой позиции: `earliest` или `latest`.

→ [Основы](basics.ru.md#откуда-читать-если-у-группы-нет-сохранённой-позиции)

</details>

<details><summary>8. Подвох: группа с `auto.offset.reset=earliest` повторно запущена после чтения всей темы. С начала ли она читает?</summary>

Нет: у неё есть сохранённая позиция, `auto.offset.reset` не действует.

→ [Продвинутая теория](advanced.ru.md#позиции-групп-потребителей)

</details>

<details><summary>9. Где Kafka хранит позиции групп?</summary>

Во внутренней теме `__consumer_offsets`.

→ [Продвинутая теория](advanced.ru.md#внутренние-темы)

</details>

<details><summary>10. Можно ли уменьшить число партиций?</summary>

Нет: `InvalidPartitionsException`; только увеличить, что может изменить отображение ключей.

→ [Подвох 1](#1-партиции-нельзя-уменьшить)

</details>

<details><summary>11. Подвох: что произойдёт при записи в несуществующую тему?</summary>

На этом брокере тема создалась автоматически с 1 партицией.

→ [Подвох 3](#3-автосоздание-тем)

</details>

<details><summary>12. Что такое KRaft?</summary>

Встроенный кворум контроллеров на основе Raft, хранящий метаданные кластера без ZooKeeper.

→ [Продвинутая теория](advanced.ru.md#что-такое-брокер-и-режим-kraft)

</details>

## Шпаргалка

```text
produce(topic, key, value, on_delivery) ; flush()           # async; result in the callback
subscribe([topic]) ; poll(t) ; commit()                      # group position stored in __consumer_offsets
get_watermark_offsets(tp) -> (low, high)
auto.offset.reset applies only if the group has no committed position
partitions: can grow, cannot shrink ; order only within a partition ; same key -> same partition
```

- Журнал, а не очередь: читать можно повторно.
- Порядок — только внутри партиции.
- `flush()` перед выходом.
