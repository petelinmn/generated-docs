# Потребители и группы: экспертный уровень

🌐 **Русский** · [English](expert.en.md)

**Уровни:** [overview](overview.ru.md) · [1. Основы](basics.ru.md) · [2. Продвинутый](advanced.ru.md) · **3. Эксперт** · [4. Квиз](quiz.ru.md)

Опирается на [базовую](basics.ru.md) и [продвинутую](advanced.ru.md) теорию. «Проверено» означает наблюдалось на одном брокере Apache Kafka 4.3.1 с `confluent-kafka` 2.16.2.

## Справочник

### Параметры потребителя

| Параметр | Назначение | Проверено |
|---|---|---|
| `group.id` | имя группы | да |
| `auto.offset.reset` (`earliest`, `latest`) | начальная позиция без сохранённой | да |
| `enable.auto.commit` | автофиксация | выключался явно |
| `partition.assignment.strategy` (`cooperative-sticky`) | стратегия назначения | да (кооперативная) |
| `group.protocol` (`consumer`) | новый протокол группы | да (работает) |
| `max.poll.interval.ms` | предел паузы между `poll` | да (`_MAX_POLL_EXCEEDED`) |
| `session.timeout.ms`, `heartbeat.interval.ms`, `max.partition.fetch.bytes`, `fetch.min.bytes`, `group.instance.id` | живость, выборка, статическое членство | не проверялись |

### API

| Элемент | Поведение | Проверено |
|---|---|---|
| `subscribe(topics, on_assign=, on_revoke=)` | вступление в группу, обработчики ребалансировки | да |
| `poll(timeout)` | сообщение, `None` или сообщение с `error()` | да |
| `assignment()` | список назначенных `TopicPartition` | да |
| `commit(asynchronous=False)` | фиксирует прочитанное | да |
| `commit(message=m)` | фиксирует `offset + 1` | да |
| `committed([TopicPartition…], timeout)` | сохранённые смещения; `-1001` — нет | да |
| `assign([TopicPartition(t, p, off)])`, `seek(tp)` | чтение с заданной позиции без группы | да |
| `close()` | выход из группы | да |

### Значения и коды (проверено)

| Что | Значение |
|---|---|
| нет сохранённого смещения | `-1001` (`OFFSET_INVALID`) |
| пауза между `poll` длиннее лимита | `_MAX_POLL_EXCEEDED` при следующем `poll` |
| зафиксировано после чтения смещения 0 | 1 |
| члены 1 / 2 / 4 при 3 партициях | `[0,1,2]` / `[0,1],[2]` / у четвёртого пусто |

## Внутреннее устройство

- **Партиция принадлежит одному члену группы** — основа параллелизма и порядка.
- **Координатор группы** — брокер, который хранит состав группы и её смещения (внутренняя тема `__consumer_offsets`, [модуль 01](../01-kafka-basics/advanced.ru.md#внутренние-темы)).
- **Eager-ребалансировка отзывает все партиции** у всех членов, затем назначает заново (проверено событиями `revoke`/`assign`).
- **Кооперативная и новая серверная ребалансировка отзывают только переезжающие партиции** (проверено).
- **Зафиксированное смещение — «следующее к чтению»**; отсюда `offset + 1`.

> ⚠️ Проверить: роль координатора и лидера группы, формат записи в `__consumer_offsets`, статическое членство (`group.instance.id`) и работа `session.timeout.ms` здесь не проверялись.

## Подвохи

### 1. Лишние потребители простаивают

Четвёртый член на трёх партициях не получил ни одной (проверено).

### 2. Eager-ребалансировка останавливает всех

Все теряют все партиции, даже неизменившиеся (проверено).

### 3. Фиксация `offset`, а не `offset + 1`

Приведёт к повторной обработке последней записи после перезапуска.

### 4. Нет фиксации — повтор

Прочитанное и необработанное без фиксации придёт снова (проверено).

### 5. Долгая обработка → `_MAX_POLL_EXCEEDED`

Потребитель выбывает из группы, партиции переходят к другим (проверено ошибкой).

### 6. `assignment()` после ошибки

После `_MAX_POLL_EXCEEDED` список назначенных партиций остался прежним (проверено), пока не пройдёт перераспределение; не считайте его актуальным.

### 7. Один `group.id` у разных приложений

Приложения делят партиции и каждое видит лишь часть данных.

## Компромиссы и альтернативы

| Выбор | Плюсы | Минусы |
|---|---|---|
| автофиксация | проще | возможна потеря необработанных записей |
| ручная фиксация после обработки | минимум один раз | дубликаты, нужна идемпотентность |
| eager-ребалансировка | простая | пауза для всех |
| `cooperative-sticky` / новый протокол | мягкие ребалансировки | сложнее, нужна совместимость |
| `assign` без группы | полный контроль позиции | нет балансировки между экземплярами |

## Вопросы с собеседований

<details><summary>1. Что такое группа потребителей?</summary>

Набор потребителей с одним `group.id`; партиции темы делятся между ними, каждая — одному члену.

→ [Основы](basics.ru.md#группа-потребителей)

</details>

<details><summary>2. Подвох: в теме 3 партиции, в группе 4 потребителя. Что будет?</summary>

Один останется без партиций.

→ [Подвох 1](#1-лишние-потребители-простаивают)

</details>

<details><summary>3. Что такое ребалансировка и когда она случается?</summary>

Перераспределение партиций при смене состава группы или числа партиций.

→ [Продвинутая теория](advanced.ru.md#ребалансировка)

</details>

<details><summary>4. Чем кооперативная ребалансировка лучше eager?</summary>

Отзываются только переезжающие партиции; остальные читаются без паузы.

→ [Продвинутая теория](advanced.ru.md#кооперативная-ребалансировка)

</details>

<details><summary>5. Что зафиксировано после чтения записи со смещением 0?</summary>

Смещение 1: фиксируется следующее к чтению.

→ [Основы](basics.ru.md#зафиксированное-смещение--следующее-к-чтению)

</details>

<details><summary>6. Подвох: что будет, если обработать записи и закрыть потребителя без `commit` при выключенной автофиксации?</summary>

После перезапуска те же записи придут снова.

→ [Подвох 4](#4-нет-фиксации--повтор)

</details>

<details><summary>7. Что значит `-1001` в `committed`?</summary>

Сохранённой позиции нет (`OFFSET_INVALID`).

→ [Основы](basics.ru.md#фиксация-смещений-commit)

</details>

<details><summary>8. Для чего `max.poll.interval.ms`?</summary>

Для обнаружения зависшего потребителя: при слишком долгой паузе между `poll` он выбывает (`_MAX_POLL_EXCEEDED`).

→ [Продвинутая теория](advanced.ru.md#живость-члена-группы-maxpollintervalms)

</details>

<details><summary>9. Подвох: можно ли читать без группы?</summary>

Да: `assign` с партицией и смещением и `seek`; балансировки между экземплярами нет.

→ [Основы](basics.ru.md#чтение-с-заданной-позиции)

</details>

<details><summary>10. Автофиксация или ручная?</summary>

Для критичных данных — ручная после обработки (минимум один раз и идемпотентность); автофиксация проще, но может потерять необработанное.

→ [Продвинутая теория](advanced.ru.md#стратегии-фиксации)

</details>

<details><summary>11. Что делает `close()` у потребителя?</summary>

Сообщает брокеру о выходе, ускоряя ребалансировку.

→ [Продвинутая теория](advanced.ru.md#лучшие-практики)

</details>

<details><summary>12. Подвох: два разных приложения используют один `group.id`. Что произойдёт?</summary>

Они разделят партиции, и каждое получит лишь часть записей.

→ [Подвох 7](#7-один-groupid-у-разных-приложений)

</details>

## Шпаргалка

```text
Consumer({"group.id":g, "auto.offset.reset":"earliest", "enable.auto.commit":False, "partition.assignment.strategy":"cooperative-sticky"})
subscribe([t], on_assign=, on_revoke=) ; poll(1.0) ; commit(message=m) | commit() ; committed([...]) ; close()
committed offset = next to read (offset+1) ; -1001 = none ; _MAX_POLL_EXCEEDED = poll pause too long
assign([TopicPartition(t,p,off)]) ; seek(tp)  # no group balancing
```

- Партиция — одному члену группы; потребителей не больше партиций.
- Фиксируйте после обработки, `offset + 1`.
- Не блокируйте `poll`.
