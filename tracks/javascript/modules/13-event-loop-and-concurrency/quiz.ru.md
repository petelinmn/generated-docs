# Квиз: цикл событий и параллелизм

## 1. 🟢 В каком порядке выведется текст?

```js
console.log('1');
setTimeout(() => console.log('2'), 0);
Promise.resolve().then(() => console.log('3'));
console.log('4');
```

- A) `1 2 3 4`
- B) `1 4 3 2`
- C) `1 3 4 2`
- D) `1 4 2 3`

<details><summary>Ответ</summary>

**B.** Сначала синхронный код (`1`, `4`), затем микрозадача (`3`), потом таймер (`2`).
→ [Базовая теория](basics.ru.md#макрозадачи-и-микрозадачи)

</details>

## 2. 🟢 Что означает `setTimeout(fn, 100)`?

- A) Вызов ровно через 100 мс
- B) Вызов не раньше чем через 100 мс
- C) Вызов не позже чем через 100 мс
- D) Вызов раньше, чем придут микрозадачи

<details><summary>Ответ</summary>

**B.** Задержка минимальная: блокирующий код или загрузка цикла сдвинут вызов.
→ [Базовая теория](basics.ru.md#таймеры)

</details>

## 3. 🟢 Что произойдёт с таймером на 10 мс, если сразу после его создания код 80 мс крутится в синхронном цикле?

- A) Сработает через 10 мс, прервав цикл
- B) Сработает после завершения цикла
- C) Не сработает никогда
- D) Сработает дважды

<details><summary>Ответ</summary>

**B.** Один поток: пока стек не освободился, ничего другого не выполняется.
→ [Базовая теория](basics.ru.md#блокировка-цикла)

</details>

<details><summary>Ответ</summary>

## 5. 🟡 Что выведется первым внутри колбэка `fs.readFile`?

```js
setTimeout(() => console.log('timeout'), 0);
setImmediate(() => console.log('immediate'));
```

- A) `timeout`
- B) `immediate`
- C) Порядок случайный
- D) Ничего

<details><summary>Ответ</summary>

**B.** Внутри колбэка ввода-вывода после poll идёт фаза check (`setImmediate`), а таймеры — на следующей итерации. В основном модуле порядок не гарантирован.
→ [Продвинутая теория](advanced.ru.md#фазы-цикла-событий-nodejs)

</details>

## 9. 🟡 Выберите все верные утверждения

- [ ] A) Рабочий поток имеет собственный цикл событий
- [ ] B) Объекты между потоками разделяются по ссылке
- [ ] C) `SharedArrayBuffer` — общая память потоков
- [ ] D) Рабочий поток ускоряет сетевой ввод-вывод

<details><summary>Ответ</summary>

**A, C.** B неверно: объекты копируются или передаются; D неверно: ввод-вывод и так асинхронен, потоки помогают при нагрузке на CPU.

</details>

## 10. 🔴 Найдите ошибку

> «`try { setTimeout(() => { throw new Error('x') }, 0) } catch (e) { … }` перехватит ошибку».

<details><summary>Ответ</summary>

Колбэк выполняется позже и в другом стеке, поэтому `try/catch` его не видит; исключение станет `uncaughtException` и завершит процесс (без обработчика).
→ [Подвох 4](expert.ru.md#4-исключение-в-таймере-или-микрозадаче)

</details>

## 11. 🔴 В каком порядке выведется текст в CommonJS-файле?

```js
console.log('A');
process.nextTick(() => console.log('B'));
Promise.resolve().then(() => console.log('C'));
queueMicrotask(() => console.log('D'));
setTimeout(() => console.log('E'), 0);
console.log('F');
```

- A) `A F C D B E`
- B) `A F B C D E`
- C) `A B C D E F`
- D) `A F E B C D`

<details><summary>Ответ</summary>

**B.** Синхронный код (`A`, `F`), затем `nextTick` (`B`), микрозадачи по порядку постановки (`C`, `D`), таймер (`E`).
→ [Подвох 3](expert.ru.md#3-nexttick-и-промисы)

</details>

## 12. 🔴 Что произойдёт, если микрозадача бесконечно ставит новую микрозадачу?

- A) Таймеры сработают в своё время
- B) Таймеры и ввод-вывод не получат управления («голодание»)
- C) Произойдёт `RangeError`
- D) Микрозадачи выполнятся по одной за итерацию

<details><summary>Ответ</summary>

**B.** Очередь микрозадач выполняется до опустошения; в опыте таймер `0` сработал только после 200001 микрозадачи.
→ [Внутреннее устройство](expert.ru.md#внутреннее-устройство)

</details>

## 13. 🔴 Открытый вопрос

Объясните, как Node.js обрабатывает тысячи одновременных соединений одним потоком JavaScript и когда нужны рабочие потоки.

<details><summary>Ключевые мысли хорошего ответа</summary>

- Ввод-вывод асинхронен: ОС и libuv выполняют операции в фоне; готовые результаты возвращаются колбэками в очереди цикла событий.
- JavaScript-колбэки выполняются по одному, поэтому быстрые обработчики обслуживают много соединений; микрозадачи идут после каждой макрозадачи.
- Блокирующий синхронный код задерживает всех; тяжёлые вычисления выносят в рабочие потоки (обмен сообщениями, transfer, `SharedArrayBuffer` + `Atomics`) или дробят.
- Рабочие потоки нужны для CPU, не для ввода-вывода; создавать их лучше пулом.

</details>

→ [Экспертная теория](expert.ru.md#внутреннее-устройство)
