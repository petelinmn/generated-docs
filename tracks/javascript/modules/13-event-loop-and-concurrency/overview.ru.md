# Цикл событий и параллелизм

🌐 **Русский** · [English](overview.en.md)

## Коротко

JavaScript выполняет код в одном потоке. Параллельность создаёт среда выполнения: цикл событий (event loop) берёт готовые задачи из очередей и по одной выполняет их до конца. Долгие операции (ввод-вывод, таймеры) уходят «в фон» и возвращаются колбэками. Если нужно настоящее параллельное вычисление, используют рабочие потоки (worker threads) с обменом сообщениями и общей памятью.

## Ключевые идеи

- **Один поток, одна задача за раз:** пока выполняется синхронный код, ничего другого не происходит.
- **Макрозадачи** (таймеры, ввод-вывод, `setImmediate`) и **микрозадачи** (`then`, `queueMicrotask`) — разные очереди; микрозадачи выполняются полностью после каждой макрозадачи.
- **`process.nextTick`** — отдельная очередь Node.js, которая обслуживается раньше микрозадач промисов.
- **`setTimeout(fn, 0)` — не «сразу»:** это минимум одна итерация цикла.
- **Блокирующий код задерживает всё:** таймеры, ответы, обработку запросов.
- **Внутри колбэка ввода-вывода `setImmediate` всегда раньше `setTimeout(…, 0)`.**
- **Рабочие потоки** выполняют код параллельно; данные копируются (structured clone), передаются (transfer) или разделяются (`SharedArrayBuffer`).
- **`Atomics`** делают операции над общей памятью безопасными.
- **Для ввода-вывода рабочие потоки не нужны:** он и так асинхронный; они нужны для нагрузки на процессор.

## Минимальный пример

```js
console.log('1 sync');
setTimeout(() => console.log('4 timeout'), 0);
Promise.resolve().then(() => console.log('3 microtask'));
console.log('2 sync');
```

```text
1 sync
2 sync
3 microtask
4 timeout
```

Сначала весь синхронный код, затем микрозадачи, затем таймер.

## Когда применять и когда нет

| Задача | Выбор |
|---|---|
| Ввод-вывод, сеть, таймеры | обычная асинхронность, потоки не нужны |
| Тяжёлое вычисление (хэш, сжатие, разбор) | рабочий поток |
| Разбить долгую работу, не блокируя цикл | порции с `setImmediate` |
| Общий счётчик между потоками | `SharedArrayBuffer` + `Atomics` |
| Изоляция сбоя | отдельный процесс (`child_process`, [модуль 16](../../overview.ru.md)) |

- ❌ Не выполняйте долгие синхронные циклы в обработчике запроса.
- ❌ Не полагайтесь на точное время срабатывания таймера.
