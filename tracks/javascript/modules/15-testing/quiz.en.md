# Quiz: testing

🌐 [Русский](quiz.ru.md) · **English**

> Answer on your own first, then open the answer. The label shows the question level: 🟢 [basic](basics.en.md) · 🟡 [advanced](advanced.en.md) · 🔴 [expert](expert.en.md).

## 1. 🟢 How do you run the built-in Node.js runner?

- A) `node test`
- B) `node --test`
- C) `npm run jest`
- D) `node --assert`

<details><summary>Answer</summary>

**B.** `node --test` finds test files and runs them.
→ [Basic theory](basics.en.md#the-first-test)

</details>

## 2. 🟢 When is a test considered failed?

- A) When the function returned `false`
- B) When the function threw an error or the promise is rejected
- C) When it ran for more than a second
- D) When it printed something to the console

<details><summary>Answer</summary>

**B.** A test passes if the function finished without an exception.
→ [Basic theory](basics.en.md#the-first-test)

</details>

## 3. 🟢 In what order do hooks and tests run?

```js
before(…); beforeEach(…); afterEach(…); after(…);
it('first', …); it('second', …);
```

- A) `before, beforeEach, first, afterEach, beforeEach, second, afterEach, after`
- B) `before, first, second, after`
- C) `beforeEach, first, afterEach, before, second, after`
- D) `before, beforeEach, afterEach, first, second, after`

<details><summary>Answer</summary>

**A.** `before` and `after` once per suite, `beforeEach`/`afterEach` around every test.
→ [Basic theory](basics.en.md#hooks)

</details>

## 4. 🟢 What is the exit code of `node --test` if one test failed?

- A) `0`
- B) `1`
- C) `2`
- D) Depends on the number of failures

<details><summary>Answer</summary>

**B.** `0` on success, `1` on failure (in the experiment); CI relies on the exit code.
→ [Basic theory](basics.en.md#the-exit-code)

</details>

## 5. 🟡 What does `mock.fn(() => 'default')` return after `mockImplementationOnce(() => 'once')` for two calls in a row?

- A) `['default', 'default']`
- B) `['once', 'default']`
- C) `['once', 'once']`
- D) `['default', 'once']`

<details><summary>Answer</summary>

**B.** The replacement applies to one call, then the default implementation returns.
→ [Advanced theory](advanced.en.md#mocks)

</details>

## 6. 🟡 What happens with `{ only: true }` if you just run `node --test`?

- A) Only that test runs
- B) The marker is ignored, all tests run (the runner prints a notice)
- C) The runner fails
- D) The test is skipped

<details><summary>Answer</summary>

**B.** `only` needs the `--test-only` flag to work.
→ [Advanced theory](advanced.en.md#selecting-and-filtering-tests)

</details>

## 7. 🟡 What does `t.mock.timers.tick(1000)` do after `enable({ apis: ['setTimeout'] })`?

- A) Waits a real second
- B) "Fast-forwards" the fake time at once and calls the timers that came due
- C) Disables timers
- D) Calls `Date.now()`

<details><summary>Answer</summary>

**B.** The test does not wait: time is advanced programmatically.
→ [Advanced theory](advanced.en.md#fake-timers)

</details>

## 8. 🟡 What happens on the first run of a test with `t.assert.snapshot(...)`?

- A) The test creates a snapshot and passes
- B) The test fails until a snapshot file is created (`--test-update-snapshots`)
- C) The snapshot is skipped
- D) The runner asks for confirmation

<details><summary>Answer</summary>

**B.** The error `Missing snapshots can be generated by rerunning the command with the --test-update-snapshots flag`.
→ [Advanced theory](advanced.en.md#snapshots)

</details>

## 9. 🟡 Choose all true statements

- [ ] A) Every test file runs in a separate process
- [ ] B) In the loose `node:assert`, `'1'` equals `1` in `equal`
- [ ] C) `assert.rejects` can be called without `await`
- [ ] D) `mock.timers` can replace `Date`

<details><summary>Answer</summary>

**A, B, D.** C is wrong: without `await` the test ends before the check and the file fails later.
→ [Expert theory](expert.en.md#internals)

</details>

## 10. 🔴 Find the mistake

> "100% line coverage means all functions of the module are checked by tests."

<details><summary>Answer</summary>

No. A one-line uncovered function gives `100%` of lines with `75%` of functions; coverage shows only that code ran, not the quality of the checks.
→ [Gotcha 7](expert.en.md#7-line-coverage-is-deceptive)

</details>

## 11. 🔴 A helper file `test/helper.js` prints text when loaded. What happens with `node --test` without arguments?

- A) Nothing, it is not a test
- B) The runner runs it as a test file
- C) The runner reports an error
- D) The file is skipped because there are no `test` calls

<details><summary>Answer</summary>

**B.** All files in the `test` folder run (in the experiment `helper executed as test file`). Do not keep helper code there.
→ [Test file discovery](expert.en.md#test-file-discovery)

</details>

## 12. 🔴 Why does `assert.throws(() => assert.strictEqual(1, 2, 'custom message'), { message: 'custom message' })` fail on Node.js 24.15?

- A) `strictEqual` does not throw
- B) The difference of the values is appended to your own message, so the message does not match
- C) You cannot pass a message to `strictEqual`
- D) `throws` does not accept an object

<details><summary>Answer</summary>

**B.** The message is `'custom message\n\n1 !== 2\n'`.
→ [Gotcha 2](expert.en.md#2-your-own-message-appends-the-difference)

</details>

## 13. 🔴 Open question

How would you organize tests for a module that uses the network, timers and the current time so they are fast and deterministic?

<details><summary>Key points of a good answer</summary>

- Dependencies (a network client, time) are passed as parameters or replaced: `mock.fn`, `t.mock.method`.
- Timers and `Date` are replaced through `t.mock.timers`; waiting is replaced by `tick`.
- Success, errors (`assert.rejects`, `assert.throws`), and the number and arguments of calls are checked.
- Files are isolated by processes; inside a file state is reset with `beforeEach`; in CI — `node --test` and coverage control.

</details>

→ [Advanced theory](advanced.en.md)
