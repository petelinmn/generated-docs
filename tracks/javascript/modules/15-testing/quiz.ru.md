# Квиз: тестирование

🌐 **Русский** · [English](quiz.en.md)

> Сначала ответьте сами, потом откройте ответ. Метка показывает уровень вопроса: 🟢 [базовая](basics.ru.md) · 🟡 [продвинутая](advanced.ru.md) · 🔴 [экспертная](expert.ru.md).

## 1. 🟢 Как запустить встроенный раннер Node.js?

- A) `node test`
- B) `node --test`
- C) `npm run jest`
- D) `node --assert`

<details><summary>Ответ</summary>

**B.** `node --test` находит тестовые файлы и запускает их.
→ [Базовая теория](basics.ru.md#первый-тест)

</details>

## 2. 🟢 Когда тест считается упавшим?

- A) Когда функция вернула `false`
- B) Когда функция бросила ошибку или промис отклонён
- C) Когда он выполнялся дольше секунды
- D) Когда он вывел что-то в консоль

<details><summary>Ответ</summary>

**B.** Тест проходит, если функция завершилась без исключения.
→ [Базовая теория](basics.ru.md#первый-тест)

</details>

## 3. 🟢 В каком порядке выполнятся хуки и тесты?

```js
before(…); beforeEach(…); afterEach(…); after(…);
it('first', …); it('second', …);
```

- A) `before, beforeEach, first, afterEach, beforeEach, second, afterEach, after`
- B) `before, first, second, after`
- C) `beforeEach, first, afterEach, before, second, after`
- D) `before, beforeEach, afterEach, first, second, after`

<details><summary>Ответ</summary>

**A.** `before` и `after` — один раз на набор, `beforeEach`/`afterEach` — вокруг каждого теста.
→ [Базовая теория](basics.ru.md#хуки)

</details>

## 4. 🟢 Какой код выхода у `node --test`, если один тест упал?

- A) `0`
- B) `1`
- C) `2`
- D) Зависит от числа упавших

<details><summary>Ответ</summary>

**B.** `0` при успехе, `1` при падении (в опыте); CI опирается на код выхода.
→ [Базовая теория](basics.ru.md#код-возврата)

</details>

## 5. 🟡 Что вернёт `mock.fn(() => 'default')` после `mockImplementationOnce(() => 'once')` при двух вызовах подряд?

- A) `['default', 'default']`
- B) `['once', 'default']`
- C) `['once', 'once']`
- D) `['default', 'once']`

<details><summary>Ответ</summary>

**B.** Подмена действует на один вызов, затем возвращается реализация по умолчанию.
→ [Продвинутая теория](advanced.ru.md#моки)

</details>

## 6. 🟡 Что произойдёт с `{ only: true }`, если запустить просто `node --test`?

- A) Выполнится только этот тест
- B) Метка игнорируется, выполнятся все тесты (раннер выводит уведомление)
- C) Раннер завершится с ошибкой
- D) Тест будет пропущен

<details><summary>Ответ</summary>

**B.** Для работы `only` нужен флаг `--test-only`.
→ [Продвинутая теория](advanced.ru.md#выбор-и-фильтрация-тестов)

## 7. 🟡 Что делает `t.mock.timers.tick(1000)` после `enable({ apis: ['setTimeout'] })`?

- A) Ждёт реальную секунду
- B) Мгновенно «перематывает» фальшивое время и вызывает сработавшие таймеры
- C) Отключает таймеры
- D) Вызывает `Date.now()`

<details><summary>Ответ</summary>

**B.** Тест не ждёт: время продвигается программно.
→ [Продвинутая теория](advanced.ru.md#фальшивые-таймеры)

## 8. 🟡 Что произойдёт при первом запуске теста со `t.assert.snapshot(...)`?

- A) Тест создаст снимок и пройдёт
- B) Тест упадёт, пока не создан файл снимка (`--test-update-snapshots`)
- C) Снимок пропустится
- D) Раннер спросит подтверждение

## 9. 🟡 Выберите все верные утверждения

- [ ] A) Каждый тестовый файл выполняется в отдельном процессе
- [ ] B) В нестрогом `node:assert` значение `'1'` равно `1` в `equal`
- [ ] C) `assert.rejects` можно вызывать без `await`
- [ ] D) `mock.timers` позволяет подменить `Date`

<details><summary>Ответ</summary>

**A, B, D.** C неверно: без `await` тест завершится раньше проверки, и файл упадёт позже.
→ [Экспертная теория](expert.ru.md#внутреннее-устройство)

</details>

## 10. 🔴 Найдите ошибку

> «Покрытие строк 100% означает, что все функции модуля проверены тестами».

<details><summary>Ответ</summary>

Нет. Однострочная непокрытая функция даёт `100%` строк при `75%` функций; покрытие показывает только выполнение кода, а не качество проверок.
→ [Подвох 7](expert.ru.md#7-покрытие-строк-обманчиво)

</details>

## 11. 🔴 Вспомогательный файл `test/helper.js` печатает текст при загрузке. Что произойдёт при `node --test` без аргументов?

- A) Ничего, это не тест
- B) Раннер выполнит его как тестовый файл
- C) Раннер выдаст ошибку
- D) Файл будет пропущен, так как нет вызовов `test`

<details><summary>Ответ</summary>

**B.** Все файлы в папке `test` выполняются (в опыте `helper executed as test file`). Не держите там вспомогательный код.
→ [Обнаружение тестовых файлов](expert.ru.md#обнаружение-тестовых-файлов)

</details>

## 12. 🔴 Почему `assert.throws(() => assert.strictEqual(1, 2, 'custom message'), { message: 'custom message' })` падает в Node.js 24.15?

- A) `strictEqual` не бросает ошибку
- B) К собственному тексту дописывается разница значений, поэтому сообщение не совпадает
- C) Нельзя передавать текст в `strictEqual`
- D) `throws` не принимает объект

<details><summary>Ответ</summary>

**B.** Сообщение — `'custom message\n\n1 !== 2\n'`.
→ [Подвох 2](expert.ru.md#2-свой-текст-ошибки-дописывает-разницу)

</details>

## 13. 🔴 Открытый вопрос

Как организовать тесты для модуля, который ходит в сеть, использует таймеры и текущее время, чтобы они были быстрыми и детерминированными?

<details><summary>Ключевые мысли хорошего ответа</summary>

- Зависимости (клиент сети, время) принимаются параметрами или подменяются: `mock.fn`, `t.mock.method`.
- Таймеры и `Date` подменяются через `t.mock.timers`; ожидание заменяется `tick`.
- Проверяются успех, ошибки (`assert.rejects`, `assert.throws`), число и аргументы вызовов.
- Файлы изолированы процессами; внутри файла состояние сбрасывается `beforeEach`; в CI — `node --test` и контроль покрытия.

</details>

→ [Продвинутая теория](advanced.ru.md)
