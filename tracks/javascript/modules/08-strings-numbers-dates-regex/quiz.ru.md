## 1. 🟢 Что вернёт `'a-b-c'.replace('-', '+')`?

- A) `'a+b+c'`
- B) `'a+b-c'`
- C) `'a-b-c'`
- D) `['a', 'b', 'c']`

<details><summary>Ответ</summary>

**B.** `replace` со строкой заменяет только первое вхождение; для всех — `replaceAll`.
→ [Базовая теория](basics.ru.md#строки)

</details>

## 2. 🟢 Чему равна `'😀'.length`?

- A) `1`
- B) `2`
- C) `4`
- D) `8`

<details><summary>Ответ</summary>

**B.** Две 16-битные кодовые единицы (суррогатная пара); `[...'😀'].length` — `1`.
→ [Базовая теория](basics.ru.md#юникод-первое-знакомство)

</details>

## 3. 🟢 Что вернёт `(1.005).toFixed(2)`?

- A) `'1.01'`
- B) `'1.00'`
- C) `1.01`
- D) `1`

<details><summary>Ответ</summary>

**B.** `toFixed` возвращает **строку**, а `1.005` хранится как `1.00499…`.
→ [Базовая теория](basics.ru.md#форматирование)

</details>

## 4. 🟢 Что вернёт `Math.round(-2.5)`?

- A) `-3`
- B) `-2`
- C) `-2.5`
- D) `2`

<details><summary>Ответ</summary>

**B.** Половина округляется в сторону `+∞`: `2.5` → `3`, `-2.5` → `-2`.
→ [Базовая теория](basics.ru.md#math)

</details>

- A) `1`
- B) `0`
- C) `12`
- D) Любой

<details><summary>Ответ</summary>

**B.** Месяцы нумеруются с нуля.
→ [Базовая теория](basics.ru.md#date-основы)

## 6. 🟡 Что делает `new Date(2024, 0, 31, 25).getDate()`?

- A) `31`
- B) `25`
- C) `1`
- D) `NaN`

<details><summary>Ответ</summary>

**C.** Час `25` «переливается» на следующие сутки (1 февраля).
→ [Продвинутая теория](advanced.ru.md#date-ловушки)

## 7. 🟡 Как разбирается `new Date('2024-01-15')` по сравнению с `new Date(2024, 0, 15)`?

- A) Одинаково
- B) Первое — полночь UTC, второе — полночь по местному времени
- C) Первое — местное, второе — UTC
- D) Первое — `Invalid Date`

<details><summary>Ответ</summary>

**B.** Значения совпадают только в поясе UTC; в UTC+4 в опыте они различались.
→ [Продвинутая теория](advanced.ru.md#date-ловушки)

</details>

## 8. 🟡 Что выведет код?

```js
const g = /a/g;
console.log(g.test('aa'), g.test('aa'), g.test('aa'));
```

- A) `true true true`
- B) `true true false`
- C) `true false false`
- D) `false false false`

<details><summary>Ответ</summary>

**B.** У `g`-регулярки есть состояние `lastIndex`: третий вызов начинается за концом строки и сбрасывает его.
→ [Продвинутая теория](advanced.ru.md#флаги-и-состояние)

</details>

## 9. 🟡 Что вернёт `/\d+(?!px)/.exec('12px 34em')[0]`?

- A) `'34'`
- B) `'1'`
- C) `'12'`
- D) `null`

<details><summary>Ответ</summary>

**B.** Движок откатился на одну цифру, после которой нет `px`. Корректно: `\d+(?!\d|px)` — `'34'`.
→ [Продвинутая теория](advanced.ru.md#группы-и-lookaround)

</details>

## 11. 🔴 Найдите ошибку

> «`'ä' > 'z'` — ложно, значит, при сортировке слов `ä` пойдёт перед `z`».

<details><summary>Ответ</summary>

Операторы сравнивают коды символов: `'ä'` (U+00E4) больше `'z'` (U+007A), поэтому `'ä' > 'z'` — `true`, и `sort()` ставит `ä` после `z`. Для порядка по языку нужен `localeCompare` / `Intl.Collator`.
→ [Базовая теория](basics.ru.md#сравнение-строк)

</details>

## 12. 🔴 Почему `/^(a+)+$/.test('aaaaaaaaaaaaaaaaaaaaaaaab')` может выполняться очень долго?

- A) Строка слишком длинная для JavaScript
- B) Вложенные повторы приводят к экспоненциальному откату (ReDoS)
- C) `test` всегда работает долго
- D) Из-за флага `g`

<details><summary>Ответ</summary>

**B.** Движок перебирает экспоненциальное число способов разбить `a`-ы между группами. В опыте на 24 символах — более 50 мс.
→ [Продвинутая теория](advanced.ru.md#ошибки-и-redos)

</details>

## 13. 🔴 Открытый вопрос

Как надёжно хранить и показывать момент времени в приложении?

<details><summary>Ключевые мысли хорошего ответа</summary>

- Хранить и передавать в UTC: миллисекунды или ISO-строка с `Z`.
- Пояс и язык применять только на выводе: `Intl.DateTimeFormat` с `timeZone`.
- Не использовать строки без пояса; помнить про переходы на летнее время и «переливание» полей.
- Для сложной календарной арифметики — библиотека (Temporal в Node.js 24.15 нет).

</details>

→ [Продвинутая теория](advanced.ru.md#date-ловушки)
