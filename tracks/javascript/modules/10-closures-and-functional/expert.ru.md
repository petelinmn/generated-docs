# Замыкания и функциональный стиль: экспертный уровень

**Уровни:** [overview](overview.ru.md) · [1. Основы](basics.ru.md) · [2. Продвинутый](advanced.ru.md) · **3. Эксперт** · [4. Квиз](quiz.ru.md)

Опирается на [базовую](basics.ru.md) и [продвинутую](advanced.ru.md) теорию. Все результаты получены запуском на Node.js 24.15.

## Справочник

### Уровни защиты объекта

| Операция | Добавить свойство | Удалить | Изменить значение | Проверка |
|---|---|---|---|---|
| `Object.preventExtensions(o)` | нет | да (в опыте) | да | `Object.isExtensible` |
| `Object.seal(o)` | нет | нет (в опыте `delete` → `false`) | да (в опыте `x` стал `2`) | `Object.isSealed` |
| `Object.freeze(o)` | нет | нет (в опыте `delete` → `false`) | нет | `Object.isFrozen` |

В строгом режиме неудачный `delete` — `TypeError: Cannot delete property 'x' of #<Object>` (в опыте в ES-модуле).

Дескриптор свойства замороженного объекта: `{ value: 1, writable: false, enumerable: true, configurable: false }` (в опыте). Заморозка неглубокая; глубокая делается рекурсивно:

```js
const deepFreeze = v => { Object.values(v).forEach(x => typeof x === 'object' && x !== null && deepFreeze(x)); return Object.freeze(v); };
const d = deepFreeze({ a: { b: { c: 1 } }, arr: [1, 2] });
try { d.a.b.c = 2 } catch (e) { console.log(e.message) }
try { d.arr.push(3) } catch (e) { console.log(e.message) }
```

```text
Cannot assign to read only property 'c' of object '#<Object>'
Cannot add property 2, object is not extensible
```

В нестрогом режиме запись в замороженный объект молча игнорируется (в опыте `Object.freeze({ a: 1 })` после `o.a = 2; o.z = 1` даёт `1 undefined`).

### Способы копирования

| Способ | Глубина | Что теряет |
|---|---|---|
| `{ ...o }`, `Object.assign({}, o)` | поверхностная | геттеры превращаются в значения (в опыте `{ value: 7, … }`) |
| `structuredClone(o)` | глубокая | функции (`DataCloneError`), прототип (класс превращается в обычный объект), флаг заморозки |
| `JSON.parse(JSON.stringify(o))` | глубокая | `undefined` и функции исчезают, `Date` → строка, `Map`/`Set` → `{}` (в опыте `{"d":"1970-01-01T00:00:00.000Z","m":{},"s":{}}`) |

`structuredClone` в опыте: копирует `Date`, `Set`, `Map`, `RegExp` и **циклические ссылки**; экземпляр класса становится обычным объектом (`k.constructor === Object`, `k instanceof K` — `false`); `Symbol` — `DataCloneError`; копия замороженного объекта не заморожена (`Object.isFrozen` — `false`).

### Копирующие методы массива

| Изменяет | Возвращает копию |
|---|---|
| `sort()` | `toSorted()` |
| `reverse()` | `toReversed()` |
| `splice()` | `toSpliced()` |
| `arr[i] = x` | `with(i, x)` |

### Что учитывает `fn.length`

Число параметров **до первого значения по умолчанию или rest**: `((a, b = 2, ...r) => 0).length` — `1`, `((...a) => 0).length` — `0`. Функция после `bind` получает `name` вида `bound foo` и `length` меньше на число связанных аргументов (в опыте `bound mul`, `1`).

## Внутреннее устройство

- **Окружение.** Каждый вызов функции создаёт запись окружения (environment record) с локальными переменными и ссылкой на внешнее. При создании функции она запоминает окружение, в котором определена (внутренний слот `[[Environment]]`). Поиск имени идёт по цепочке окружений: это и есть замыкание.
- **Переменная, а не значение.** Замыкание ссылается на привязку (binding) в окружении, поэтому `getX` видит `x = 2`, а две функции из одного вызова делят одну переменную (в опыте `pair()` → `2`).
- **Окружение на каждый вызов.** Два вызова `makeCounter` создают два окружения: отсюда независимость счётчиков.
- **`let` в заголовке цикла.** На каждой итерации создаётся копия привязки: значение переносится в новое окружение перед инкрементом. Поэтому замыкание, изменяющее `i` в теле, меняет только свою копию: в опыте цикл с `i++` в теле и в заголовке дал `[ 1, 3 ]`.
- **`eval` и замыкания.** Прямой `eval` видит переменные замыкания (в опыте `eval('secret')` вернул `5`), даже если имя `secret` в коде функции не встречается.
- **Память.** Окружение живёт, пока достижима хотя бы одна функция, которая на него ссылается; сборщик мусора освобождает его после этого. Что именно движок оставляет в окружении (только используемые переменные или все), — деталь реализации.

> ⚠️ Проверить: оптимизации V8, при которых замыкание сохраняет не все переменные внешней функции, и точные случаи утечек памяти из-за общего контекста не проверялись запуском.

- **Рекурсия и стек.** Размер стека вызовов ограничен: `sum(1e6)` с обычной рекурсией дало `RangeError: Maximum call stack size exceeded`, а trampoline-версия на цикле — `500000500000`.
- **Оптимизация хвостовых вызовов.** Стандарт описывает её, но Node.js (V8) её не выполняет: настоящая хвостовая рекурсия `tail(n - 1, acc + n)` при `n = 1e6` тоже даёт `RangeError: Maximum call stack size exceeded` (в опыте). На неё нельзя полагаться.

> ⚠️ Проверить: наличие хвостовой оптимизации в других движках (например, Safari/JavaScriptCore) по документации не сверялось.

## Подвохи

### 1. `map(parseInt)`

`['1', '2', '3'].map(parseInt)` даёт `[ 1, NaN, NaN ]`: индекс попадает в параметр `radix`.

### 2. `Object.freeze` не глубокий

`o.n.b = 3` изменило вложенный объект замороженного `o`; `Object.isFrozen(o.n)` — `false`.

### 3. Заморозка и режимы

В нестрогом коде запись молча игнорируется (`1 undefined`), в строгом и в модулях — `TypeError`. Один и тот же код ведёт себя по-разному.

### 4. `structuredClone` теряет прототип

Экземпляр класса превращается в простой объект: методы и геттеры пропадают.

### 5. Каррирование и значения по умолчанию

`curry((a, b = 2) => a + b)(1)` сразу вызывает функцию и возвращает `3`: `length` равен `1`.

### 6. Повторный `bind` не меняет `this`

`b1 = h.bind({ v: 1 })`, `b2 = b1.bind({ v: 2 })`: `b2()` вернёт `1`.

### 7. `this` внутри обычной функции в замыкании

Обычная функция, вернувшаяся из метода, теряет `this`: в нестрогом режиме `this` — глобальный объект (в опыте `typeof this` — `object`), в строгом — `undefined`. Стрелка берёт `this` из внешней функции (в опыте `obj.regular()()` → `1`).

### 8. Общий кэш растёт

Мемоизация с объектами-ключами в `Map` не освобождает память; ключи-объекты лучше хранить в `WeakMap` (`wm.get(key)` → `1`, `wm.has({})` → `false`).

### 9. Замыкание и `let` с изменением внутри тела

Копия привязки создаётся на каждой итерации: функции, созданные до `i++` в теле, видят значения `1` и `3`, а не `0` и `2`.

## Компромиссы и альтернативы

| Подход | Плюсы | Минусы |
|---|---|---|
| Замыкания для состояния | проще класса, настоящая приватность | нет прототипа: каждый экземпляр хранит свои копии функций |
| Классы с `#`-полями | методы в прототипе, `instanceof` | больше церемоний |
| `WeakMap` для приватных данных | данные вне объекта, не удерживают его | медленнее, косвенность |
| Неизменяемость по соглашению | быстро, без обёрток | ничего не защищает |
| `Object.freeze`/`deepFreeze` | защита во время выполнения | неглубокий, затраты на обход |
| Библиотеки неизменяемых структур | структурное разделение | зависимость; не запускались |
| Трамплин | рекурсия без роста стека | менее читаемо |

## Вопросы с собеседований

<details><summary>1. Что такое замыкание?</summary>

Функция вместе с ссылкой на окружение, где она создана: она видит его переменные даже после выхода из внешней функции.

→ [Базовая теория](basics.ru.md#что-такое-замыкание)

</details>

<details><summary>2. Замыкание хранит значение или переменную?</summary>

Переменную: `x = 2` после создания `getX` видно при вызове.

→ [Базовая теория](basics.ru.md#замыкание-хранит-переменную-а-не-значение)

</details>

<details><summary>3. Что выведет цикл с <code>var</code> и замыканиями и как исправить?</summary>

`[ 3, 3, 3 ]`; заменить `var` на `let`.

→ [Базовая теория](basics.ru.md#замыкания-в-цикле)

</details>

<details><summary>4. Как сделать приватное состояние без классов?</summary>

Фабрика с локальной переменной и функциями, которые на неё ссылаются.

→ [Базовая теория](basics.ru.md#фабрики-и-приватное-состояние)

</details>

<details><summary>5. Подвох: что вернёт <code>['1','2','3'].map(parseInt)</code>?</summary>

`[ 1, NaN, NaN ]`: вторым аргументом приходит индекс как основание.

→ [Подвох 1](#1-mapparseint)

</details>

<details><summary>6. Чем каррирование отличается от частичного применения?</summary>

Каррирование превращает функцию от n аргументов в цепочку функций по одному аргументу (в нашей реализации допускаются и группы); частичное применение фиксирует часть аргументов и возвращает функцию от оставшихся (`bind`).

→ [Продвинутая теория](advanced.ru.md#каррирование-и-частичное-применение)

</details>

<details><summary>7. В чём разница <code>pipe</code> и <code>compose</code>?</summary>

Порядок: `pipe` — слева направо, `compose` — справа налево. `pipe(inc, sq)(3)` = 16, `compose(inc, sq)(3)` = 10.

→ [Продвинутая теория](advanced.ru.md#композиция)

</details>

<details><summary>8. Когда нельзя мемоизировать?</summary>

Для функций с побочными эффектами и зависимостью от времени или внешнего состояния; а также с объектами-ключами без нормализации.

→ [Продвинутая теория](advanced.ru.md#мемоизация)

</details>

<details><summary>9. Подвох: заморозили объект. Можно ли изменить вложенное свойство?</summary>

Да: `Object.freeze` неглубокий (`o.n.b = 3` сработало).

→ [Подвох 2](#2-objectfreeze-не-глубокий)

</details>

<details><summary>10. Чем <code>structuredClone</code> лучше <code>JSON.parse(JSON.stringify())</code> и чем хуже?</summary>

Лучше: копирует `Date`, `Map`, `Set`, `RegExp`, циклические ссылки. Хуже: не копирует функции и прототип.

→ [Способы копирования](#способы-копирования)

</details>

<details><summary>11. Почему в нестрогом режиме запись в замороженный объект не падает?</summary>

В нестрогом режиме неудачная запись молча игнорируется, ошибку даёт только строгий режим и модули.

→ [Подвох 3](#3-заморозка-и-режимы)

</details>

<details><summary>12. Почему рекурсия на миллион уровней падает и что делать?</summary>

Стек вызовов ограничен (`RangeError`), оптимизации хвостовых вызовов в V8 нет. Нужен цикл или trampoline.

→ [Внутреннее устройство](#внутреннее-устройство)

</details>

## Шпаргалка

```text
function mk() { let n = 0; return () => ++n }      // замыкание: переменная в окружении
const dbl = f.bind(null, 2)                          // частичное применение
const pipe = (...f) => x => f.reduce((v, g) => g(v), x)
Object.freeze(o) — неглубокий; structuredClone(o) — глубокая копия без функций
arr.toSorted() / toReversed() / with(i, x) / toSpliced()  — без мутации
reduce(f, init) — всегда с начальным значением
```

- Замыкание видит изменения переменной.
- `fn.length` останавливается на первом значении по умолчанию.
- Хвостовой оптимизации в V8 нет.
