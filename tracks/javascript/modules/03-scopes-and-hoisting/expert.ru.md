# Переменные и области видимости: экспертная теория

🌐 **Русский** · [English](expert.en.md)

**Уровни:** [обзор](overview.ru.md) · [1. Базовая](basics.ru.md) · [2. Продвинутая](advanced.ru.md) · **3. Экспертная** · [4. Квиз](quiz.ru.md)

Опирается на [базовую](basics.ru.md) и [продвинутую](advanced.ru.md) теорию. Все результаты получены запуском на Node.js 24.15 (ES-модуль, строгий режим), если не указано иное.

## Справочник

### Формы объявления

| Форма | Область | Всплытие | Повторное объявление | Переприсваивание |
|---|---|---|---|---|
| `var x` | функция (или модуль) | да, значение `undefined` | допустимо (в той же функции) | да |
| `let x` | блок | да, но TDZ | `SyntaxError` | да |
| `const x` | блок | да, но TDZ | `SyntaxError` | `TypeError: Assignment to constant variable.` |
| `function f() {}` | функция (блок — в строгом режиме) | целиком, вместе с телом | допустимо среди `var` в функции | да |
| `var f = function () {}` | как `var` | имя всплывает, значение `undefined` | допустимо | да |
| `class C {}` | блок | да, но TDZ | `SyntaxError` | да (имя), содержимое остаётся |
| параметр функции | область параметров | — | `var a` в теле не создаёт новую (`params(7)` вернул `7`) | да |
| параметр `catch (e)` | блок `catch` | — | — | да |

> ⚠️ Проверить: поведение `import` как всплывающей привязки и `using`-объявлений (явное управление ресурсами) в этом материале не запускалось.

### Сообщения об ошибках

| Ситуация | Ошибка |
|---|---|
| Чтение `let`/`const`/`class` до объявления | `ReferenceError: Cannot access 'x' before initialization` |
| Обращение к необъявленному имени | `ReferenceError: x is not defined` |
| Присваивание `const` | `TypeError: Assignment to constant variable.` |
| Повторное `let`/`const` в одной области | `SyntaxError: Identifier 'x' has already been declared` |
| Вызов `var`, равной `undefined` | `TypeError: expr is not a function` |
| `let x = x + 1` | `ReferenceError: Cannot access 'x' before initialization` (имя уже скрыто) |
| `for (const i = 0; i < 2; i++)` | `TypeError: Assignment to constant variable.` |

## Внутреннее устройство

- **Окружения (Environment Records).** Спецификация описывает область как *окружение*: таблицу «имя → значение» со ссылкой на внешнее окружение. Поиск идёт по цепочке ссылок — это и есть цепочка областей.
- **Создание привязок до выполнения.** Перед выполнением тела функции, блока или модуля движок создаёт все объявленные в нём привязки (создание/инстанцирование). Для `var` и функций привязка сразу получает значение (`undefined` или тело функции); для `let`/`const`/`class` она остаётся **неинициализированной** до выполнения объявления — это и есть TDZ. Всплытие — следствие этого шага, а не физического «переноса кода».
- **Функция и `var` с одним именем.** Внутри функции объявление функции побеждает: `typeof f1` до `var f1 = 1` равен `'function'`, а после присваивания — `'number'`; `var f2` без значения не перетирает функцию (`'function'`). На верхнем уровне **модуля** функция — лексическая привязка, поэтому `var q = 1; function q(){}` — `SyntaxError: Identifier 'q' has already been declared`.
- **Привязка на каждую итерацию.** В `for (let i = …; …; i++)` на каждой итерации создаётся новое окружение, в которое копируется значение `i`. Поэтому замыкания видят свои значения (`[0, 1, 2]`), а `i++` внутри замыкания меняет только «свою» копию: два прохода `fns2.map(f => f())` дали `[0, 1, 2]` и затем `[1, 2, 3]`.
- **Область параметров.** Параметры со значениями по умолчанию получают отдельное окружение; `var a` в теле создаёт другую переменную, и замыкание из параметра видит параметр, а не телесную `a` (в опыте `((a, b = () => a) => { var a = 2; return b(); })(1)` вернуло `1`).
- **Глобальная область.** Глобальное окружение состоит из окружения объекта (`var` и функции становятся свойствами `globalThis`) и декларативной части (`let`, `const`, `class` — без свойств). В файле Node.js верхний уровень принадлежит модулю: у `var topVar` нет дескриптора на `globalThis` (в опыте `undefined`).
- **`this`.** В ES-модуле `this` на верхнем уровне и внутри обычной функции, вызванной без объекта, равен `undefined` (в опыте `typeof this` — `'undefined'` для обычной и стрелочной функций).
- **Замыкание.** Функция хранит ссылку на окружение, где создана. Окружение живёт, пока на него есть ссылки: так счётчик `count` из `mk()` продолжает существовать после выхода из `mk`.

> ⚠️ Проверить: как V8 размещает переменные (регистры, контексты в куче) и анализ того, какие переменные захвачены замыканиями, взяты из общих знаний о движке и не проверялись; спецификация такого поведения не требует.

## Подвохи

### 1. `typeof` внутри TDZ падает

`typeof c1` до `const c1` — `ReferenceError`. Безопасность `typeof` для необъявленных имён не распространяется на TDZ.

### 2. Всплытие функционального выражения

`var expr = function () {}` всплывает как `undefined`: вызов до присваивания — `TypeError: expr is not a function`, а не `ReferenceError`.

### 3. `const` в цикле `for`

`for (const i = 0; i < 2; i++)` падает на втором шаге (`TypeError`), а `for (const x of [1, 2])` работает: на каждой итерации создаётся новая привязка.

### 4. Затенение скрывает внешнее имя целиком

`let x = 1; { let x = x + 1; }` — `ReferenceError`: внутри блока `x` уже означает внутреннюю, ещё не инициализированную переменную.

### 5. Статические поля классов и TDZ

`class A { static s = B.v }` до объявления `class B` — `ReferenceError` (`B` в TDZ).

### 6. `var` из `catch`, `if`, цикла «протекает»

Область у `var` — функция, а не блок (в опыте `leaked`, `fromCatch` и `i` видны после блока).

### 7. Функции в блоках зависят от режима

В строгом режиме функция из блока видна только в блоке; в нестрогом — «всплывает» в функцию после выполнения блока (в опыте в `.cjs`).

### 8. Параметры по умолчанию и тело функции

Значение по умолчанию не видит `let`/`var` из тела (в опыте `[ 'outer', 'outer', 'body' ]`).

### 9. `eval` в строгом режиме

`eval('var ev = 1')` в модуле не создаёт переменную снаружи: `typeof ev` равен `'undefined'` (в опыте).

## Компромиссы и альтернативы

| Подход | Плюсы | Минусы |
|---|---|---|
| `const` по умолчанию | меньше случайных переприсваиваний, ясный код | не защищает содержимое |
| `let` | гибкость | можно случайно изменить |
| `var` | совместимость со старым кодом | функциональная область, всплытие, повторные объявления |
| `Object.freeze` | защищает от записи верхнего уровня | поверхностная |
| Модули и блоки вместо IIFE | изоляция без лишних функций | требуют ESM |
| Линтеры (`no-var`, `prefer-const`, `no-use-before-define`) | находят проблемы заранее | не запускались |

## Вопросы с собеседований

<details><summary>1. Чем <code>var</code>, <code>let</code> и <code>const</code> различаются?</summary>

Область (функция против блока), всплытие (`undefined` против TDZ), повторные объявления (допустимы только у `var`), переприсваивание (не разрешено у `const`).

→ [Справочник](#формы-объявления)

</details>

<details><summary>2. Что такое всплытие?</summary>

Привязки создаются до выполнения кода области: `var` получает `undefined`, функция — своё тело, `let`/`const`/`class` остаются неинициализированными (TDZ).

→ [Базовая теория](basics.ru.md#всплытие-hoisting)

</details>

<details><summary>3. Что такое TDZ и почему <code>typeof</code> в ней падает?</summary>

Период от начала блока до объявления, когда привязка существует, но не инициализирована. Любое обращение, включая `typeof`, — `ReferenceError`.

→ [Подвох 1](#1-typeof-внутри-tdz-падает)

</details>

<details><summary>4. Ловушка: что выведет цикл с <code>var</code> и <code>setTimeout</code>?</summary>

`3, 3, 3`: одна переменная на весь цикл; к моменту вызова она равна `3`. С `let` — `0, 1, 2`.

→ [Базовая теория](basics.ru.md#замыкание-в-цикле-var-и-let)

</details>

<details><summary>5. Позволяет ли <code>const</code> менять объект?</summary>

Да, запрещено лишь переприсваивание. Для защиты — `Object.freeze` (поверхностная).

→ [Базовая теория](basics.ru.md#let-const-и-var)

</details>

<details><summary>6. Ловушка: <code>var expr = function () {}</code> вызвана до объявления. Что произойдёт?</summary>

`TypeError: expr is not a function`: `expr` всплыла со значением `undefined`.

→ [Подвох 2](#2-всплытие-функционального-выражения)

</details>

<details><summary>7. Что такое замыкание?</summary>

Функция вместе со ссылкой на окружение, где она создана; окружение живёт, пока на него ссылаются.

→ [Внутреннее устройство](#внутреннее-устройство)

</details>

<details><summary>8. Почему <code>let</code> в заголовке цикла решает проблему замыканий?</summary>

На каждой итерации создаётся новое окружение с копией переменной.

→ [Внутреннее устройство](#внутреннее-устройство)

</details>

<details><summary>9. Станет ли <code>var</code> на верхнем уровне файла свойством <code>globalThis</code>?</summary>

В файле Node.js — нет, это переменная модуля. В классическом браузерном скрипте или `node -e` — да.

→ [Продвинутая теория](advanced.ru.md#область-модуля-и-глобальная-область)

</details>

<details><summary>10. Ловушка: что вернёт <code>let x = 1; { let x = x + 1; }</code>?</summary>

`ReferenceError`: внутренняя `x` затеняет внешнюю и находится в TDZ.

→ [Подвох 4](#4-затенение-скрывает-внешнее-имя-целиком)

</details>

<details><summary>11. Как работают функции в блоках в строгом и нестрогом режиме?</summary>

Строгий — видны только в блоке; нестрогий — после выполнения блока доступны во внешней функции.

→ [Продвинутая теория](advanced.ru.md#функции-в-блоках)

</details>

<details><summary>12. Зачем нужны фигурные скобки в <code>case</code> с <code>let</code>?</summary>

Все ветки <code>switch</code> делят одну область, и одинаковые <code>let</code> дают <code>SyntaxError</code>.

→ [Продвинутая теория](advanced.ru.md#switch-и-catch)

</details>

## Шпаргалка

```text
const по умолчанию ; let при переприсваивании ; var — не использовать
TDZ: let/const/class до объявления → ReferenceError
var и function всплывают; function expression — как var (undefined)
for (let …) — новая привязка на итерацию; for (var …) — одна на цикл
блок { } — область для let/const/class; var — область функции
верхний уровень ES-модуля — переменные модуля, не globalThis
```
