# Классы: экспертная теория

🌐 **Русский** · [English](expert.en.md)

**Уровни:** [обзор](overview.ru.md) · [1. Базовая](basics.ru.md) · [2. Продвинутая](advanced.ru.md) · **3. Экспертная** · [4. Квиз](quiz.ru.md)

Опирается на [базовую](basics.ru.md) и [продвинутую](advanced.ru.md) теорию. Все результаты получены запуском на Node.js 24.15 (ES-модуль; где указано, нестрогий файл `.cjs`).

## Справочник

### Элементы тела класса

| Элемент | Запись | Где живёт | Перечисляемо |
|---|---|---|---|
| конструктор | `constructor(...) {}` | сам класс (функция) | — |
| метод | `m() {}` | `Class.prototype` | нет |
| геттер/сеттер | `get x() {}` / `set x(v) {}` | `Class.prototype` | нет |
| поле экземпляра | `x = 1;` | каждый экземпляр | да |
| приватное поле/метод | `#x = 1;` / `#m() {}` | экземпляр (скрыто) | не видно в ключах |
| статический метод/поле | `static m() {}` / `static s = 1;` | сам класс | поле — да, метод — нет |
| статический блок | `static { ... }` | выполняется при создании класса | — |
| приватное статическое | `static #x` | сам класс (скрыто) | не видно |
| вычисляемое имя | `[expr]() {}` | как у обычного члена | — |

> ⚠️ Проверить: ключевое слово `accessor` (автоаксессоры, декораторы) и вычисляемые имена с генераторами/`async` в опытах не запускались.

### Правила конструктора

| Случай | Результат |
|---|---|
| Вызов класса без `new` | `TypeError: Class constructor Point cannot be invoked without 'new'` |
| `this` в конструкторе наследника до `super()` | `ReferenceError: Must call super constructor in derived class before accessing 'this' or returning from derived constructor` |
| Пустой конструктор наследника | та же `ReferenceError` при `new` |
| `class Y extends null` | `TypeError: Super constructor null of Y is not a constructor` при `new Y()` |
| Конструктор возвращает объект | `new` вернёт этот объект (`{ custom: true }`); поля наследника добавляются к нему |
| Конструктор возвращает примитив | игнорируется (стандартное правило `new`, [модуль 04](../04-functions/expert.ru.md#внутреннее-устройство)) |

> ⚠️ Проверить: возврат примитива из конструктора класса (в опыте проверен только возврат объекта).

## Внутреннее устройство

- **Класс — функция.** `typeof Point` — `'function'`; у неё есть `[[Construct]]`, а свойство `prototype` **не перезаписываемо** (в опыте `writable: false`, у обычной функции — `true`). `Object.getPrototypeOf(X) === Function.prototype` (в опыте), а у наследника — родительский класс: `Object.getPrototypeOf(Z) === X`, поэтому статические члены наследуются.
- **Состав.** `Object.getOwnPropertyNames(class { static a = 1; static m() {} })` вернул `[ 'length', 'name', 'prototype', 'm', 'a' ]`: статический метод создаётся при определении, статическое поле — при инициализации (позже).
- **Тело класса всегда строгое.** Даже в нестрогом `.cjs` метод, вызванный как `m()`, получает `this === undefined`, а `m.call(5)` — примитив `5` (в опыте).
- **Методы неперечисляемы.** Дескриптор метода на прототипе имеет `enumerable: false` (в опыте `toString`), поэтому `for...in` и `Object.keys` их не видят.
- **Порядок создания экземпляра (`new Derived()`).** Конструктор базового класса создаёт объект и инициализирует **свои** поля; затем управление возвращается в конструктор наследника после `super()`, и только тогда инициализируются поля наследника. Поэтому из конструктора `Base` поле `b` наследника не видно (в опыте `seenB: undefined`). Для базового класса поля инициализируются перед телом конструктора (`ctor sees 1`).
- **`super`.** `super.method()` ищет метод в прототипе того объекта, где определён текущий метод («home object»), но вызывает его с текущим `this`. Поэтому `super.kind` у геттера наследника читает геттер родителя на том же экземпляре.
- **Приватные имена.** `#x` — не строковое свойство, а запись в отдельной «приватной» таблице экземпляра; доступ вне тела класса запрещён на этапе компиляции (`SyntaxError`). `#x in o` проверяет наличие такой записи (бренд-проверка, в опыте `true`/`false`).
- **Выражение класса.** Имя `Named` у `const E = class Named {}` связано только внутри класса; `E.name` — `'Named'`, снаружи `typeof Named` — `'undefined'` (в опыте).

> ⚠️ Проверить: точная структура внутренних слотов (`[[HomeObject]]`, `[[Fields]]`, приватные окружения) и оптимизации V8 для приватных полей взяты из спецификации и в опытах не проверялись.

## Подвохи

### 1. Конструктор родителя вызывает переопределяемый метод

Поля наследника ещё не созданы: `this.b` равно `undefined` (в опыте).

### 2. Метод теряет `this`

`const { method } = f; method()` — `TypeError: Cannot read properties of undefined (reading 'v')` (в опыте). Даже в нестрогом коде тело класса строгое, поэтому `this` не подменяется глобальным объектом.

### 3. Поле со стрелкой создаётся на каждом экземпляре

`Object.hasOwn(f, 'arrow')` — `true`, у метода — `false`; при миллионах экземпляров это расход памяти.

### 4. Статические члены наследуются по ссылке

`B.s` читает `A.s` (`Object.hasOwn(B, 's')` — `false`); запись `B.s = 1` создаст собственное свойство у `B` и скроет родительское.

### 5. `class` не всплывает

До объявления — `ReferenceError: Cannot access 'Later' before initialization` (в опыте).

### 6. Нельзя обратиться к приватному имени снаружи

Не `undefined`, а `SyntaxError` на этапе разбора файла: программа не запустится.

### 7. `Array` и `map`

У `Stack extends Array` метод `map` возвращает `Stack` (в опыте `true`): наследуются и «видовые» конструкторы; при нестандартном конструкторе подкласса это может ломать код.

### 8. Ошибка без `name`

Подкласс `Error` без собственного `name` печатается как `Error: ...`. Задавайте `this.name` (в опыте `MyErr: boom`).

### 9. Возврат объекта из конструктора

Подменяет результат `new` (`{ custom: true }`); `instanceof` для него не работает.

## Компромиссы и альтернативы

| Подход | Плюсы | Минусы |
|---|---|---|
| `class` | ясный синтаксис, приватные члены, `extends`/`super` | `this` и порядок полей требуют внимания |
| Фабричные функции и замыкания | настоящая приватность, нет `this` | нет `instanceof`, копия методов на объект |
| Литералы и `Object.create` | минимум синтаксиса | нет приватности и `super` |
| Примеси (mixins) | повторное использование без глубокой иерархии | сложнее отладка цепочки |
| Композиция | гибкость | больше связующего кода |
| TypeScript | модификаторы, `abstract`, `implements` | типы стираются; другой уровень проверки |

## Вопросы с собеседований

<details><summary>1. Чем класс отличается от функции-конструктора?</summary>

Класс нельзя вызвать без `new`, его тело строгое, методы неперечисляемы, есть `extends`/`super`, приватные члены, `prototype` не перезаписывается; по сути это та же прототипная модель.

→ [Внутреннее устройство](#внутреннее-устройство)

</details>

<details><summary>2. Где живут методы класса и поля экземпляра?</summary>

Методы — на `Class.prototype`; поля — в самих экземплярах.

→ [Справочник](#элементы-тела-класса)

</details>

<details><summary>3. Что такое приватные поля и чем они отличаются от соглашения <code>_name</code>?</summary>

`#x` недоступны снаружи на уровне языка (ошибка разбора), не попадают в ключи и `JSON`; `_name` — лишь договорённость.

→ [Базовая теория](basics.ru.md#приватные-члены)

</details>

<details><summary>4. Ловушка: что произойдёт, если в конструкторе наследника обратиться к <code>this</code> до <code>super()</code>?</summary>

`ReferenceError: Must call super constructor ...`.

→ [Справочник](#правила-конструктора)

</details>

<details><summary>5. В каком порядке инициализируются поля при наследовании?</summary>

Поля базового класса — перед телом его конструктора; поля наследника — после возврата из `super()`.

→ [Внутреннее устройство](#внутреннее-устройство)

</details>

<details><summary>6. Ловушка: почему метод, переданный как обратный вызов, ломается?</summary>

Он отрывается от экземпляра, `this` становится `undefined` (тело класса строгое). Решение: поле-стрелка или `bind`.

→ [Подвох 2](#2-метод-теряет-this)

</details>

<details><summary>7. Как сделать абстрактный класс?</summary>

В конструкторе проверять `new.target === Abs` и бросать ошибку.

→ [Продвинутая теория](advanced.ru.md#newtarget-и-абстрактные-классы)

</details>

<details><summary>8. Как работает <code>super</code> в методе и в конструкторе?</summary>

В конструкторе `super(...)` вызывает родительский конструктор и создаёт `this`; в методе `super.m()` вызывает метод прототипа родителя с текущим `this`.

→ [Базовая теория](basics.ru.md#наследование-extends-и-super)

</details>

<details><summary>9. Наследуются ли статические члены?</summary>

Да, через цепочку прототипов конструкторов; `this` в статическом методе — класс, у которого его вызвали.

→ [Продвинутая теория](advanced.ru.md#статическое-наследование-и-выражения-классов)

</details>

<details><summary>10. Как добавить поведение без наследования?</summary>

Примесь — функция, возвращающая класс (`class extends B`), или композиция.

→ [Продвинутая теория](advanced.ru.md#примеси-mixins)

</details>

<details><summary>11. Что делает <code>#x in obj</code>?</summary>

Проверяет, что у объекта есть приватное поле `#x` (создан этим классом), не падая на чужих объектах.

→ [Продвинутая теория](advanced.ru.md#приватные-методы-статические-приватные-члены-и-блоки)

</details>

<details><summary>12. Как написать пользовательскую ошибку?</summary>

`class MyErr extends Error { constructor(m, code) { super(m); this.name = 'MyErr'; this.code = code; } }`.

→ [Продвинутая теория](advanced.ru.md#расширение-встроенных-классов)

</details>

## Шпаргалка

```text
class A { #p = 1; x = 0; static s = 0; static { … }
  constructor() {} get g() {} set g(v) {} m() {} static sm() {} #pm() {} }
class B extends A { constructor() { super(); } m() { return super.m(); } }
new A() обязателен ; this после super() ; #p in o ; new.target
```

- Методы на прототипе (неперечисляемы), поля — в экземпляре.
- Поля наследника — после `super()`.
- Метод как callback → стрелка-поле или `bind`.
- Классы строгие; не всплывают.
