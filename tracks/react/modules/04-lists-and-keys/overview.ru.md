# Списки, ключи и идентичность

🌐 **Русский** · [English](overview.en.md)

## Коротко

Список в React — это массив элементов. Каждому нужен `key` — имя, по которому React узнаёт тот же элемент при следующем рендере. Ключи решают, какой компонент какое состояние сохранит, какой узел DOM переиспользуется, а какой создаётся заново. Те же правила идентичности объясняют, когда состояние переживает изменение интерфейса, а когда пропадает.

## Ключевые идеи

- Ключ различает элементы среди соседей.
- Берите ключи из данных: идентификатор из базы или созданный при создании записи.
- Индекс в роли ключа следует за позицией, а не за элементом.
- Случайный ключ создаёт все элементы заново при каждом рендере.
- Без ключей React предупреждает и опирается на позицию.
- Состояние живёт, пока тот же тип компонента стоит в той же позиции.
- Смена `key` — способ намеренно сбросить компонент.

## Минимальный пример

```tsx
const users = [{ id: 'u1', name: 'Ann' }, { id: 'u2', name: 'Bob' }];

<ul>
  {users.map(u => <li key={u.id}>{u.name}</li>)}
</ul>
```

## Когда применять, а когда нет

- ✅ Любой массив элементов: устойчивые ключи.
- ✅ Сброс формы или вида для другой записи: смените `key`.
- ❌ Индекс в роли ключа для списка, который переставляют, фильтруют или редактируют.
- ❌ Создание ключей во время рендера.
