# Квиз: жизненный цикл индексов

🌐 **Русский** · [English](quiz.en.md)

> Сначала ответьте сами, затем раскройте ответ. 🟢 [базовый](basics.ru.md) · 🟡 [продвинутый](advanced.ru.md) · 🔴 [экспертный](expert.ru.md).

## 1. 🟢 Какое поле обязательно в документах data stream?

- A) `date`
- B) `created_at`
- C) `@timestamp`
- D) `_id`

<details><summary>Ответ</summary>

**C.** Поток упорядочивает данные по времени и требует поле `@timestamp`. Другие имена его не заменяют без явной настройки шаблона, а `_id` задавать не обязательно.
→ [Базовая теория](basics.ru.md)

</details>

## 2. 🟢 Куда пишется новый документ потока?

- A) в текущий индекс записи
- B) в индекс, соответствующий его дате
- C) во все backing-индексы
- D) в первый индекс

<details><summary>Ответ</summary>

**A.** Всё новое пишется в последний backing-индекс — индекс записи. Дата документа на выбор не влияет, и копий во все индексы нет.
→ [Базовая теория](basics.ru.md)

</details>

## 3. 🟢 Что разрешено по имени потока?

- A) перезапись по `_id`
- B) удаление по `_id`
- C) частичный `update` по `_id`
- D) добавление через `create`

<details><summary>Ответ</summary>

**D.** По имени потока можно только добавлять (`create`). Перезапись, удаление и обновление по `_id` требуют обращения к конкретному backing-индексу.
→ [Базовая теория](basics.ru.md)

</details>

## 4. 🟢 Можно ли удалить текущий индекс записи потока?

- A) да, но данные останутся
- B) нет, запрос отклоняется
- C) да
- D) да, поток переключится на старый

<details><summary>Ответ</summary>

**B.** Индекс записи нужен потоку, поэтому удалить его нельзя: сначала делают rollover. Поток не переключается на старый индекс сам.
→ [Базовая теория](basics.ru.md)

</details>

## 5. 🟡 `job_interval` по умолчанию?

- A) непрерывно
- B) 5 минут
- C) 1 минута
- D) 1 час

<details><summary>Ответ</summary>

**B.** ISM проверяет индексы периодически, по умолчанию раз в 5 минут, поэтому действия происходят не мгновенно.
→ [Продвинутая теория](advanced.ru.md)

</details>

## 6. 🟡 Что нужно обычному индексу для ISM-rollover?

- [ ] A) настройка `rollover_alias`
- [ ] B) поле `@timestamp` в mapping
- [ ] C) две реплики
- [ ] D) псевдоним записи

<details><summary>Ответ</summary>

**A, D.** Для обычного индекса ISM должен знать псевдоним, который переключать: настройку `rollover_alias` и сам псевдоним записи. `@timestamp` и две реплики не требуются.
→ [Продвинутая теория](advanced.ru.md)

</details>

## 7. 🟡 Политику изменили. Уже привязанный индекс:

- A) работает по прежней версии до `change_policy`
- B) переходит на новую сразу
- C) удаляется
- D) получает состояние failed

<details><summary>Ответ</summary>

**A.** Привязанный индекс хранит копию версии политики и продолжает по ней, пока его явно не переведут. Сам он не обновляется, не удаляется и не переходит в failed.
→ [Продвинутая теория](advanced.ru.md)

</details>

## 8. 🟡 `min_index_age: 7d` в переходе отсчитывается от:

- A) последней записи
- B) значения `@timestamp`
- C) создания индекса
- D) входа в состояние

<details><summary>Ответ</summary>

**C.** Возраст — это возраст индекса с момента создания. Время последней записи, значения полей и вход в состояние к нему не относятся.
→ [Продвинутая теория](advanced.ru.md)

</details>

## 9. 🔴 Куда ISM добавляет повторы по умолчанию?

- A) без повторов
- B) бесконечные повторы
- C) одна попытка через час
- D) 3 попытки с экспоненциальной задержкой

<details><summary>Ответ</summary>

**D.** Действию по умолчанию дают несколько повторов с растущей паузой: три попытки и экспоненциальная задержка. Бесконечными они не бывают.
→ [Экспертная теория](expert.ru.md)

</details>

## 10. 🔴 Повторный `PUT` существующей политики без номеров последовательности:

- A) удалит старую
- B) 409
- C) обновит
- D) создаст вторую

<details><summary>Ответ</summary>

**B.** Без `if_seq_no` и `if_primary_term` запрос считается созданием, а политика уже есть — это конфликт. Старая не удаляется и вторая не появляется.
→ [Экспертная теория](expert.ru.md)

</details>

## 11. 🔴 Как исправить один документ в потоке?

- A) удалить поток
- B) `_rollover`
- C) записать в backing-индекс с `if_seq_no` и `if_primary_term`
- D) `PUT stream/_doc/id`

<details><summary>Ответ</summary>

**C.** Исправление идёт в конкретный backing-индекс с проверкой версии, чтобы не затереть чужое изменение. `PUT` по имени потока запрещён, а rollover и удаление потока не исправляют документ.
→ [Экспертная теория](expert.ru.md)

</details>

## 12. 🔴 Открытый вопрос: логи 100 ГиБ в день, хранить 30 дней. Что настроите?

<details><summary>Ответ</summary>

Data stream с шаблоном; rollover по размеру первичного шарда и по возрасту; число шардов, чтобы шард был 30–50 ГиБ; после остывания `read_only` и `force_merge`; удаление по возрасту; снимки, если нужна копия; оценка диска с репликами и запасом.
→ [Продвинутая теория](advanced.ru.md)

</details>
