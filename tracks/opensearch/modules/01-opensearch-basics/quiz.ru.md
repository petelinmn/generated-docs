# Квиз: основы OpenSearch

🌐 **Русский** · [English](quiz.en.md)

> Сначала ответьте сами, затем раскройте ответ. 🟢 [базовый](basics.ru.md) · 🟡 [продвинутый](advanced.ru.md) · 🔴 [экспертный](expert.ru.md).

## 1. 🟢 Что такое индекс?

- A) Процесс на сервере
- B) Копия шарда
- C) Набор документов с общими настройками
- D) Один JSON-объект

<details><summary>Ответ</summary>

**C.** D — документ, A — узел, B — реплика.
→ [Базовая теория](basics.ru.md)

</details>

## 2. 🟢 Документ записан без параметра `refresh`. Что верно сразу после ответа?

- A) `get` по `_id` находит его, поиск может ещё не находить
- B) Не находит ни `get`, ни поиск
- C) Находят оба
- D) Поиск находит, `get` — нет

<details><summary>Ответ</summary>

**A.** Поиск ждёт refresh.
→ [Базовая теория](basics.ru.md)

</details>

## 3. 🟢 `index` с уже занятым `_id`:

- A) объединяет поля
- B) возвращает 409
- C) создаёт второй документ
- D) заменяет документ целиком

<details><summary>Ответ</summary>

**D.** Объединяет `update`, отказывает `create`.
→ [Базовая теория](basics.ru.md)

</details>

## 4. 🟢 Один узел, индекс с одной репликой. Статус?

- A) индекс не создастся
- B) `yellow`
- C) `green`
- D) `red`

<details><summary>Ответ</summary>

**B.** Реплику не размещают на том же узле, что и основной шард.
→ [Базовая теория](basics.ru.md)

</details>

## 5. 🟡 Что выведет второй вызов `update` с тем же значением?

- A) `created`
- B) `noop`, версия не изменилась
- C) `updated`, версия выросла
- D) 409

<details><summary>Ответ</summary>

**B.** Частичное обновление тем же значением ничего не меняет, поэтому OpenSearch отвечает `noop` и не увеличивает версию. Это не создание и не конфликт 409.
→ [Базовая теория](basics.ru.md)

</details>

## 6. 🟡 Какие утверждения о `_bulk` верны?

- [ ] A) У каждой операции свой статус
- [ ] B) Одна ошибка откатывает всё
- [ ] C) Эффективнее множества одиночных запросов
- [ ] D) Не атомарен

<details><summary>Ответ</summary>

**A, C, D.** `_bulk` — это пакет независимых операций в одном запросе: у каждой свой статус, и сетевых обходов меньше. Транзакции нет, поэтому ошибка одной не откатывает остальные.
→ [Базовая теория](basics.ru.md)

</details>

## 7. 🟡 Документ записан с `routing=alice`, читается без него в индексе из трёх шардов. Что произошло в эксперименте?

- A) 404
- B) документ найден
- C) 400
- D) 409

<details><summary>Ответ</summary>

**A.** Запрос ушёл в другой шард. Если хеш `_id` случайно укажет на тот же шард, документ найдётся — на это нельзя полагаться.
→ [Продвинутая теория](advanced.ru.md)

</details>

## 8. 🟡 Как не потерять чужое изменение при «прочитать → изменить → записать»?

- A) увеличить число реплик
- B) `_bulk`
- C) `if_seq_no` и `if_primary_term`
- D) `refresh=true`

<details><summary>Ответ</summary>

**C.** При конфликте — 409.
→ [Продвинутая теория](advanced.ru.md)

</details>

## 9. 🟡 Что можно менять на открытом индексе?

- A) `number_of_shards`
- B) тип существующего поля
- C) имя индекса
- D) `number_of_replicas`

<details><summary>Ответ</summary>

**D.** Число реплик — динамическая настройка. Число первичных шардов, тип поля и имя индекса на месте изменить нельзя.
→ [Продвинутая теория](advanced.ru.md)

</details>

## 10. 🔴 `from=9995, size=10` при настройках по умолчанию:

- A) вернёт пустой список без ошибки
- B) ошибка 400
- C) вернёт 5 документов
- D) вернёт 10 документов

<details><summary>Ответ</summary>

**B.** `from + size` больше `max_result_window` = 10000.
→ [Экспертная теория](expert.ru.md)

</details>

## 12. 🔴 Открытый вопрос: события об изменении товаров приходят из очереди и могут прийти повторно и не по порядку. Как писать их в индекс?

<details><summary>Ответ</summary>

`_id` — идентификатор товара (повтор не создаёт дубликат); `version_type=external` с версией из источника (старое событие получает 409, его пропускают); пакетами `_bulk` с разбором ошибок; удаление требует учесть `gc_deletes`, в течение которого помнится версия удалённого документа.
→ [Продвинутая теория](advanced.ru.md)

</details>
