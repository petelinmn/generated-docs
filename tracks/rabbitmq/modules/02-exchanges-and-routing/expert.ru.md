# Обменники и маршрутизация: экспертный уровень

🌐 **Русский** · [English](expert.en.md)

**Уровни:** [overview](overview.ru.md) · [1. Основы](basics.ru.md) · [2. Продвинутый](advanced.ru.md) · **3. Эксперт** · [4. Квиз](quiz.ru.md)

Опирается на [базовую](basics.ru.md) и [продвинутую](advanced.ru.md) теорию. Поведение с пометкой «проверено» наблюдалось на брокере RabbitMQ 4.4.1.

## Справочник

### Типы обменников

| Тип | Правило сопоставления | Ключ маршрутизации | Проверено |
|---|---|---|---|
| по умолчанию (`""`) | имя очереди равно ключу | используется | да |
| `direct` | ключ равен ключу привязки | используется | да |
| `fanout` | все привязанные очереди | игнорируется | да |
| `topic` | слова через точку; `*` одно слово, `#` ноль или больше | используется | да |
| `headers` | таблица заголовков и `x-match` | игнорируется | да (`all`, `any`) |

> ⚠️ Проверить: документация также описывает значения `x-match` — `all-with-x` и `any-with-x` (учитываются заголовки, начинающиеся с `x-`), и значение `all` по умолчанию, если `x-match` не указан; здесь это не проверялось.

### Параметры объявления (`exchange_declare`)

| Параметр | Смысл | Проверено |
|---|---|---|
| `exchange_type` | `direct`, `fanout`, `topic`, `headers` (иначе 406 `unknown exchange type`) | да |
| `durable` | переживает перезапуск брокера | нет |
| `auto_delete` | удаляется после снятия последней привязки | да |
| `internal` | клиенты не могут публиковать | да |
| `passive` | только проверить существование (404 и закрытый канал, если нет) | да |
| `arguments` | `alternate-exchange` и аргументы плагинов | да |

### Правила и коды ошибок

| Ситуация | Результат |
|---|---|
| Повторное объявление с другим типом или аргументами | `406 PRECONDITION_FAILED`, канал закрыт |
| Неизвестный тип обменника | `406 PRECONDITION_FAILED` |
| Имя с префиксом `amq.` | `403 ACCESS_REFUSED` |
| Удалить обменник по умолчанию или привязать к нему | `403 ACCESS_REFUSED` |
| Публикация в `internal` обменник | канал закрыт |
| `mandatory=True` и нет маршрута | `basic.return` с `312 NO_ROUTE` |

## Внутреннее устройство

- **Маршрутизация — поиск по привязкам.** Для `direct` и `topic` брокер сопоставляет ключ с таблицей привязок обменника; очередь входит в результат не более одного раза, поэтому несколько подходящих привязок всё равно дают одну копию.
- **Сообщение не копируется по значению для каждой очереди по сети.** Производитель отправляет его один раз; брокер помещает ссылку в каждую целевую очередь (видимый эффект — одна доставка на очередь).
- **Обменник по умолчанию неявный:** брокер считает каждую очередь привязанной по имени, поэтому его нельзя удалить или перепривязать.
- **Цепочки alternate exchange** (у альтернативного обменника свой альтернативный) возможны; немаршрутизируемое сообщение заканчивает путь в последнем обменнике, который не может его маршрутизировать.

> ⚠️ Проверить: утверждение, что сообщения хранятся один раз и очереди ссылаются на них, описывает устройство классического хранилища и здесь не исследовалось; считайте его фоном.

## Подвохи

### 1. Тихое отбрасывание

Публикация в обменник без подходящей привязки не даёт видимого эффекта.

### 2. `*` — одно слово

`*.orange.*` совпал с `quick.orange.rabbit` и `lazy.orange.elephant`, но не с `lazy` и не с `quick.brown.fox`.

### 3. `#` совпадает с нулём слов

`lazy.#` совпал с самим `lazy`.

### 4. Две привязки, одна копия

Очередь с привязками `a.b` и `a.#` и публикация `a.b` дали ровно одно сообщение.

### 5. Fanout игнорирует ключ

Ключ, заданный fanout-обменнику, ничего не делает.

### 6. Несовпадающее повторное объявление

Потребитель, объявивший `topic`, когда производитель создал `direct`, закрывает свой канал с 406.

### 7. Публикация в internal обменник

Закрывает канал, так что неверную цель замечают только через обработчик закрытия.

## Компромиссы и альтернативы

| Выбор | Плюсы | Минусы |
|---|---|---|
| `topic` со схемой ключей | гибко, развивается | нужна дисциплина ключей |
| Много `direct` обменников | просто для каждого | разрастание топологии |
| `headers` | сопоставление по нескольким атрибутам | медленнее, сложнее инспектировать |
| Alternate exchange | собирает мёртвый трафик | ещё одна очередь под наблюдением |
| `mandatory` + обработчик возврата | обратная связь на каждую публикацию | асинхронная обработка у издателя |

## Вопросы с собеседований

<details><summary>1. Какие бывают типы обменников?</summary>

`direct`, `fanout`, `topic`, `headers`, плюс обменник по умолчанию (безымянный).

→ [Базовая теория](basics.ru.md#что-делает-обменник)

</details>

<details><summary>2. Как работает обменник по умолчанию?</summary>

Это direct-обменник, неявно привязанный к каждой очереди по имени очереди.

→ [Базовая теория](basics.ru.md#обменник-по-умолчанию)

</details>

<details><summary>3. Подвох: подходит ли `lazy.#` под ключ `lazy`?</summary>

Да, `#` совпадает с нулём или несколькими словами.

→ [Подвох 3](#3--совпадает-с-нулём-слов)

</details>

<details><summary>4. Подвох: очередь привязана с `a.b` и `a.#`. Вы публикуете `a.b`. Сколько копий?</summary>

Одна.

→ [Подвох 4](#4-две-привязки-одна-копия)

</details>

<details><summary>5. Что происходит с немаршрутизируемым сообщением?</summary>

Оно отбрасывается, если `mandatory` не вернёт его (`312 NO_ROUTE`) или alternate exchange не заберёт.

→ [Продвинутая теория](advanced.ru.md#немаршрутизируемые-сообщения-и-mandatory)

</details>

<details><summary>6. Для чего нужен alternate exchange?</summary>

Чтобы собирать сообщения, которые обменник не смог маршрутизировать.

→ [Продвинутая теория](advanced.ru.md#alternate-exchange)

</details>

<details><summary>7. Использует ли fanout-обменник ключ маршрутизации?</summary>

Нет, он игнорируется.

→ [Подвох 5](#5-fanout-игнорирует-ключ)

</details>

<details><summary>8. Что значат `x-match: all` и `any`?</summary>

Должны совпасть все заголовки привязки или хотя бы один.

→ [Базовая теория](basics.ru.md#headers)

</details>

<details><summary>9. Подвох: что будет при повторном объявлении обменника с другим типом?</summary>

`406 PRECONDITION_FAILED`, и канал закрывается.

→ [Подвох 6](#6-несовпадающее-повторное-объявление)

</details>

<details><summary>10. Что такое internal обменник?</summary>

Такой, в который клиенты публиковать не могут; в него маршрутизируют только другие обменники.

→ [Продвинутая теория](advanced.ru.md#internal-и-auto-delete-обменники)

</details>

<details><summary>11. Можно ли привязывать обменники к обменникам?</summary>

Да (`exchange_bind`), получается граф маршрутизации.

→ [Продвинутая теория](advanced.ru.md#привязки-обменник-обменник)

</details>

<details><summary>12. Почему `topic` лучше множества direct-обменников?</summary>

Один обменник со схемой ключей покрывает много случаев, включая поведение direct и fanout.

→ [Базовая теория](basics.ru.md#выбор-типа)

</details>

## Шпаргалка

```text
default "" : routes by queue name; cannot declare/delete/bind
direct     : key == binding key
fanout     : key ignored
topic      : * = one word, # = zero or more, words split by "."
headers    : arguments + x-match=all|any
exchange_declare(ex, exchange_type, durable, auto_delete, internal, passive, arguments)
alternate-exchange : arguments on the exchange; mandatory=True -> basic.return 312 NO_ROUTE
```

- Привязывайте до публикации.
- Одна копия на очередь.
- Объявляйте повторно с теми же аргументами.
