## 1. 🟢 Какой обменник игнорирует ключ маршрутизации?

- A) `direct`
- B) `fanout`
- C) `topic`
- D) обменник по умолчанию

<details><summary>Ответ</summary>

**B.** (`headers` тоже его игнорирует и использует заголовки.)
→ [Базовая теория](basics.ru.md#fanout)

</details>

## 2. 🟢 Что делает `basic_publish("", "work", …)`?

- A) Падает: имя обменника пусто
- B) Публикует через обменник по умолчанию в очередь `work`
- C) Публикует в fanout
- D) Создаёт очередь `work`

<details><summary>Ответ</summary>

**B.** Обменник по умолчанию маршрутизирует по имени очереди; очередей он не создаёт.
→ [Базовая теория](basics.ru.md#обменник-по-умолчанию)

</details>

## 3. 🟢 Какие ключи подходят под привязку `lazy.#`?

- A) Только `lazy`
- B) Только `lazy.pink.rabbit`
- C) `lazy`, `lazy.orange.elephant`, `lazy.pink.rabbit`
- D) Любой ключ

<details><summary>Ответ</summary>

**C.** `#` совпадает с нулём или несколькими словами.
→ [Базовая теория](basics.ru.md#topic)

</details>

## 10. 🔴 Найдите ошибку

```python
ch.exchange_declare("events", exchange_type="topic")
ch.basic_publish("events", "order.created", b"...")   # no queues bound yet
```

<details><summary>Ответ</summary>

Ни одна очередь не привязана, поэтому сообщение молча отбрасывается. Привяжите очереди потребителей до публикации, либо пусть alternate exchange ловит немаршрутизированное, либо публикуйте с `mandatory=True`.
→ [Продвинутая теория](advanced.ru.md#alternate-exchange)

</details>

## 11. 🔴 Что будет при публикации в `internal` обменник?

- A) Маршрутизация как обычно
- B) Брокер закроет канал
- C) Сообщение вернётся
- D) Оно встанет в очередь на потом

<details><summary>Ответ</summary>

**B.** Internal-обменники принимают сообщения только по привязкам других обменников.
→ [Продвинутая теория](advanced.ru.md#internal-и-auto-delete-обменники)

</details>

## 12. 🔴 Открытый вопрос

Спроектируйте обменники для системы заказов: биллинг хочет все события заказов, доставка — только `order.paid`, а сервису аудита нужно всё, включая события, которые никто не маршрутизирует.

<details><summary>Ключевые мысли хорошего ответа</summary>

- Один `topic`-обменник (`orders`) с ключами `order.<событие>`.
- Очередь биллинга привязана с `order.#`; доставка — с `order.paid`; аудит — с `#`.
- Alternate exchange (fanout) с очередью для немаршрутизированных; `mandatory` для критичных публикаций.
- Топология объявляется в одной общей процедуре запуска; durable-обменники и очереди.

</details>

→ [Продвинутая теория](advanced.ru.md)
