# Обмен сообщениями и модель AMQP

🌐 **Русский** · [English](overview.en.md)

## Коротко

Брокер сообщений принимает сообщения от производителей и отдаёт их потребителям, так что сервисам не нужно быть живыми одновременно и знать друг друга. В RabbitMQ (AMQP 0-9-1) производитель публикует в **обменник** (exchange), обменник маршрутизирует сообщение через **привязки** (bindings) в **очереди** (queues), а **потребители** берут сообщения из очередей и **подтверждают** их. Работа идёт в дешёвых **каналах** (channels) внутри одного долгоживущего **соединения** (connection).

## Ключевые идеи

- **Производитель → обменник → привязка → очередь → потребитель.** Производитель никогда не пишет в очередь напрямую; безымянный обменник по умолчанию лишь выглядит так (он маршрутизирует по имени очереди).
- **Соединение дорогое, канал дешёвый.** Одно соединение на процесс, каналы на задачу.
- **`basic_get` опрашивает, `basic_consume` получает push.** Предпочитайте consume.
- **Подтверждайте после обработки.** Неподтверждённое сообщение возвращается в очередь, когда потребитель умирает, с пометкой `redelivered`.
- **Ошибка на канале закрывает этот канал**, а не соединение: пассивное объявление отсутствующей очереди дало `404 NOT_FOUND` и мёртвый канал.
- **RabbitMQ 4.4 отказывается создавать очереди, которые не durable и не exclusive**, и закрывает соединение (`541`).
- **Публикация асинхронна:** счётчик сообщений сразу после публикации может отставать.
- **pika 1.5.0** объявляет `BlockingConnection` устаревшим; используйте `pika.Connection`.

## Минимальный пример

```python
import pika
conn = pika.Connection(pika.ConnectionParameters("localhost"))
ch = conn.channel()
ch.queue_declare("hello", durable=True)
ch.basic_publish(exchange="", routing_key="hello", body=b"Hello, RabbitMQ!")
method, props, body = ch.basic_get("hello")      # (GetOk, properties, b'Hello, RabbitMQ!')
ch.basic_ack(method.delivery_tag)
conn.close()
```

Весь код запускался на настоящем брокере RabbitMQ 4.4.1 в Docker (см. «Как проверялся код» в [базовой теории](basics.ru.md)).

## Когда применять и когда нет

| Задача | Выбор |
|---|---|
| Развязать сервисы по времени, сгладить пики, распределить работу между воркерами | очередь RabbitMQ |
| Одно событие для многих независимых подписчиков | обменники (fanout / topic), [модуль 02](../02-exchanges-and-routing/overview.ru.md) |
| Ответ нужен прямо сейчас, один на один | прямой вызов; RPC через брокер — исключение (модуль 04 ([дорожная карта](../../overview.ru.md))) |
| Журнал с повторным чтением многими потребителями | stream или система-журнал вроде Kafka (см. типы очередей, модуль 07 в [дорожной карте](../../overview.ru.md)) |
| Данные, которые нужно хранить и запрашивать | база данных |

- ❌ Не используйте брокер как базу данных.
- ❌ Не рассчитывайте на доставку «ровно один раз»: проектируйте с учётом дубликатов.
