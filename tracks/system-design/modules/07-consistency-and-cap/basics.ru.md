# Согласованность и CAP: базовая теория

🌐 **Русский** · [English](basics.en.md)

**Уровни:** [обзор](overview.ru.md) · **1. Базовая** · [2. Продвинутая](advanced.ru.md) · [3. Экспертная](expert.ru.md) · [4. Квиз](quiz.ru.md)

**Пререквизиты:** транзакции, репликация · **Время:** ~2 ч

## Зачем это нужно

Двое покупают последний билет. Реплика ещё не знает о покупке. Чтобы решить, что должно произойти, нужны точные слова для гарантий.

## Две разные «согласованности»

| Термин | О чём |
|---|---|
| C в ACID | транзакция сохраняет правила данных |
| C в CAP | линеаризуемость: система ведёт себя как одна копия |
| Изоляция | что параллельные транзакции видят друг о друге |

## Модели согласованности

| Модель | Обещание |
|---|---|
| Линеаризуемость | после завершения записи все читают новое значение |
| Причинная | причинно связанные записи видны в правильном порядке |
| Сессионные гарантии | один клиент не видит противоречий |
| Eventual | без новых записей копии когда-нибудь сойдутся |

## CAP

Если сеть разделила узлы (P), система не может одновременно отвечать на каждый запрос (A) и вести себя как одна копия (C). CAP не про выбор «двух из трёх» в обычном режиме: разделения случаются сами, выбирается поведение во время них.

```csharp
public bool TryWrite(int node, string value)
{
    if (mode == Mode.Cp && !HasMajority(node)) return false;

    foreach (int i in Reachable(node)) _values[i] = value;
    return true;
}
```

В режиме CP узел в меньшинстве отказывает, в режиме AP обе стороны принимают записи и расходятся: после восстановления связи на одной `left`, на другой `right`. Файл: [Ex02_Partition.cs](code/Examples/Ex02_Partition.cs). Это упрощённая модель, а не протокол репликации.

## Аномалии транзакций

| Аномалия | Что происходит |
|---|---|
| Dirty read | видно незафиксированное |
| Nonrepeatable read | повторное чтение строки дало другое |
| Phantom read | повторный запрос дал другой набор строк |
| Lost update | одно изменение затёрло другое |
| Write skew | каждый проверил правило, вместе его нарушили |

## Ошибки новичка

- ❌ «У нас транзакции, значит гонок нет» → ✅ зависит от уровня изоляции.
- ❌ «Мы выбрали CA» → ✅ разделения всё равно случаются.
- ❌ Прочитать, посчитать и записать без защиты → ✅ атомарная операция или проверка версии.
- ❌ Считать eventual consistency «почти мгновенной» → ✅ срока она не обещает.
