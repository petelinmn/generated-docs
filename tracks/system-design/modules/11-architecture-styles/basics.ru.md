# Архитектурные стили: базовая теория

🌐 **Русский** · [English](basics.en.md)

**Уровни:** [обзор](overview.ru.md) · **1. Базовая** · [2. Продвинутая](advanced.ru.md) · [3. Экспертная](expert.ru.md) · [4. Квиз](quiz.ru.md)

**Пререквизиты:** опыт разработки веб-приложения · **Время:** ~2 ч

## Зачем это нужно

Границы, проведённые неудачно, дорого менять. Стиль определяет, сколько будет стоить каждое следующее изменение и что может сломаться независимо.

## Стили

| Стиль | Суть |
|---|---|
| N-tier | слои, каждый обращается только к нижним |
| Web-Queue-Worker | веб-часть, очередь и фоновый обработчик |
| Микросервисы | небольшие автономные сервисы со своими данными |
| Событийная | издатели и потребители через брокер |
| Модульный монолит | один процесс, строгие модули |
| Serverless | функции, которыми управляет платформа |

Центр архитектуры Azure отдельно описывает также big data и big compute.

## Монолит и микросервисы

| | Монолит | Микросервисы |
|---|---|---|
| Развёртывание | одно | по сервисам |
| Вызовы | в памяти | по сети |
| Транзакции | локальные | saga |
| Эксплуатация | проще | требует автоматизации и наблюдаемости |
| Независимость команд | низкая | высокая |

## Модульный монолит

Модули общаются через контракты: интерфейсы и события, а не через внутренние классы друг друга.

```csharp
public int Place(decimal total)
{
    int id = ++_lastId;
    bus.Publish(new OrderPlaced(id, total));
    return id;
}
```

`OrderService` ничего не знает о биллинге; `InvoiceService` подписывается на событие. Файл: [Ex01_ModularMonolith.cs](code/Examples/Ex01_ModularMonolith.cs). Шина в примере синхронная: сбой обработчика роняет публикующего.

## Ошибки новичка

- ❌ Распределённый монолит: сервисы выпускаются только вместе → ✅ независимые контракты и данные.
- ❌ Общая база у всех сервисов → ✅ у каждого свои данные.
- ❌ Модули, знающие внутренности друг друга → ✅ контракты.
- ❌ Выбирать стиль по моде → ✅ по требованиям.
