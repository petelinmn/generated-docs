# Архитектурные стили

🌐 **Русский** · [English](overview.en.md)

## Коротко

Стиль определяет, как система разделена на части и как части общаются. Выбор зависит от команды, нагрузки и скорости изменений, а не от моды.

## Ключевые идеи

- Монолит — одна единица развёртывания, а не обязательно беспорядок.
- Модульный монолит держит границы внутри одного процесса.
- Микросервисы дают независимость ценой распределённости.
- Сетевой вызов медленнее и менее надёжен, чем вызов метода.
- Границы проводят по бизнес-возможностям.
- Правила архитектуры стоит проверять тестами.
- Решения записывают в ADR.

## Минимальный пример

```csharp
bus.Subscribe<OrderPlaced>(e => Invoices[e.OrderId] = e.Total);
```

## Когда применять, а когда нет

- ✅ Новый продукт: начните с модульного монолита.
- ✅ Несколько команд мешают друг другу выпускать изменения.
- ❌ Микросервисы для команды из трёх человек без причины.
- ❌ Разделение по техническим слоям на отдельные сервисы.
