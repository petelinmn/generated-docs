# Консенсус и координация: продвинутая теория

🌐 **Русский** · [English](advanced.en.md)

**Уровни:** [обзор](overview.ru.md) · [1. Базовая](basics.ru.md) · **2. Продвинутая** · [3. Экспертная](expert.ru.md) · [4. Квиз](quiz.ru.md)

## Правила голосования

Узел отдаёт не более одного голоса за терм и не голосует за кандидата, чей журнал менее актуален. Из двух журналов актуальнее тот, где больше терм последней записи; при равных термах — более длинный.

```csharp
bool upToDate = candidateLogTerm > LastLogTerm
    || (candidateLogTerm == LastLogTerm && candidateLogIndex >= LastLogIndex);
if (!upToDate || (_votedFor is not null && _votedFor != candidate)) return false;
```

Так лидером не станет узел, у которого нет зафиксированных записей.

## Случайный таймаут

Чтобы голоса не делились бесконечно, таймаут выборов берут случайным из интервала; в статье приведён пример 150–300 мс.

## Фиксация записей

Запись зафиксирована, когда лидер, создавший её, разместил её на большинстве. Записи прежних термов не считаются зафиксированными простым подсчётом копий: они фиксируются вместе с записью текущего терма.

## Термы

Каждый узел хранит текущий терм. Увидев больший, лидер или кандидат становится follower. Запрос с устаревшим термом отклоняется.

## Лучшие практики

- Нечётное число узлов, обычно 3 или 5.
- Разносите узлы по зонам отказа.
- Измеряйте длительности монотонными часами.
- Делайте задачу под блокировкой идемпотентной.

## Частые ошибки

- ❌ Растянуть кластер на два дата-центра поровну → ✅ потеря любого может лишить большинства; нужна третья зона.
- ❌ Много узлов «для скорости» → ✅ каждая запись ждёт большинство.
- ❌ Короткий lease без продления → ✅ продлевать заранее и всё равно использовать fencing.
- ❌ Считать, что освобождение блокировки всегда выполнится → ✅ срок обязателен.
