# Квиз: Делегаты, события, лямбды

## 1. 🟢 Какой стандартный тип делегата подходит для метода, который принимает `int` и возвращает `string`?

- A) `Action<int>`
- B) `Func<int, string>`
- C) `Predicate<int>`
- D) `Func<string, int>`

<details><summary>Ответ</summary>

**B.** У `Func` **последний** параметр типа — результат, остальные — аргументы. `Action` ничего не возвращает, `Predicate<T>` возвращает `bool`.
→ [Базовая теория](basics.ru.md#готовые-типы-func-action-predicate)

</details>

## 2. 🟢 Что выведет код?

```csharp
static Func<int, int> Compose(Func<int, int> f, Func<int, int> g) => x => g(f(x));
var inc = (int x) => x + 1;
var dbl = (int x) => x * 2;
Console.WriteLine($"{Compose(inc, dbl)(5)} {Compose(dbl, inc)(5)}");
```

<details><summary>Ответ</summary>

```text
12 11
```

`Compose(inc, dbl)(5)` = `dbl(inc(5))` = `12`; `Compose(dbl, inc)(5)` = `inc(dbl(5))` = `11`. Лямбда `x => g(f(x))` захватывает `f` и `g` (проверено).
→ [Базовая теория](basics.ru.md#лямбда-выражения)

</details>

## 3. 🟢 Что разрешено делать с событием `event` снаружи объявляющего класса?

- A) вызывать и подписываться
- B) только подписываться и отписываться (`+=`, `-=`)
- C) только вызывать
- D) присваивать `null`

<details><summary>Ответ</summary>

**B.** Событие защищает делегат: `c.Evt();` и `c.Evt = null;` вне класса — ошибка `CS0070` (проверено). Для публичного поля-делегата обе операции были бы допустимы, поэтому поле для уведомлений не используют.
→ [Базовая теория](basics.ru.md#события)

</details>

## 4. 🟢 Что вернёт многоадресный `Func<int>`, составленный из методов, возвращающих `1`, `2`, `3`?

- A) `1`
- B) `6`
- C) `3`
- D) массив `[1, 2, 3]`

<details><summary>Ответ</summary>

**C.** Вызываются все обработчики по порядку, но результат — последнего; значения первых двух теряются (проверено). Для сбора всех результатов используйте `GetInvocationList()`.
→ [Продвинутая теория](advanced.ru.md#многоадресные-делегаты)

</details>

## 5. 🟡 Что выведет код?

```csharp
Action many = () => Console.WriteLine("first");
many += () => throw new InvalidOperationException("boom");
many += () => Console.WriteLine("third");
many();
```

- A) `first`, `third`, затем исключение
- B) `first`, затем `InvalidOperationException`; `third` не выполнится
- C) `first`, `third` без исключения
- D) ничего: исключение возникает до первого вывода

<details><summary>Ответ</summary>

**B.** Исключение прерывает многоадресный вызов (проверено: `1 → throw → 3`, третий не выполнился). Для независимого вызова обходите `GetInvocationList()` и оборачивайте каждый вызов в `try`.
→ [Экспертная теория](expert.ru.md#исключение-прерывает-многоадресный-вызов)

</details>

## 6. 🟡 Сработает ли отписка?

```csharp
Action a = () => Console.WriteLine("lam");
Action combined = a;
combined -= () => Console.WriteLine("lam");   // the same text
combined();
```

- A) выведет `lam` — обработчик остался
- B) ничего не выведет
- C) исключение
- D) ошибка компиляции

<details><summary>Ответ</summary>

**A.** Делегаты сравниваются по методу и цели, а два лямбда-выражения с одинаковым текстом — разные методы (`(Func<int>)(() => 1) == (Func<int>)(() => 1)` → `False`). Для отписки сохраняйте ссылку на исходный делегат или возвращайте `IDisposable`.
→ [Экспертная теория](expert.ru.md#отписка-другой-копией-лямбды-не-работает)

</details>

## 7. 🟡 Что выведет код?

```csharp
var bad = new List<Func<int>>();
for (int i = 0; i < 3; i++) bad.Add(() => i);

var good = new List<Func<int>>();
for (int i = 0; i < 3; i++) { int copy = i; good.Add(() => copy); }

Console.WriteLine(string.Join(",", bad.Select(f => f())) + " | " + string.Join(",", good.Select(f => f())));
```

<details><summary>Ответ</summary>

```text
3,3,3 | 0,1,2
```

Замыкание захватывает **переменную**, а не значение. В `for` она одна на весь цикл и к моменту вызова равна `3`; копия внутри тела создаётся заново на каждой итерации (проверено).
→ [Продвинутая теория](advanced.ru.md#замыкания-и-их-стоимость)

</details>

## 8. 🟡 Выберите все верные утверждения

- [ ] A) `Action copy = orig; orig += handler;` — `copy` тоже получит `handler`
- [ ] B) `+=` у делегата создаёт новый делегат
- [ ] C) `n?.Invoke()` безопасен для `null`-делегата
- [ ] D) вызов `n()` для `null`-делегата бросает `NullReferenceException`

<details><summary>Ответ</summary>

**B, C, D.** A неверно: делегаты неизменяемы, `+=` создаёт новый объект, а `copy` продолжает указывать на старый (проверено).
→ [Продвинутая теория](advanced.ru.md#многоадресные-делегаты)

</details>

## 9. 🟡 Открытый вопрос: как событие может привести к утечке памяти и как этого избежать?

<details><summary>Ключевые пункты хорошего ответа</summary>

- издатель хранит ссылки на подписчиков (в списке вызова делегата): долгоживущий издатель удерживает короткоживущих подписчиков и всё, что они захватили;
- всегда отписывайтесь (`-=`) вместе с завершением жизни подписчика — например, в `Dispose`;
- удобный приём — метод `Subscribe`, возвращающий `IDisposable` (отписка в `Dispose`);
- альтернативы: слабые события (`WeakReference`), короткоживущий издатель;
- лямбды-обработчики нельзя отписать «такой же» лямбдой — храните ссылку на делегат ([12 · Память и GC](../12-memory-and-gc/overview.ru.md)).

</details>

## 10. 🔴 Что даст `static`-лямбда и когда она не скомпилируется?

```csharp
int x = 5;
Func<int> f = static () => x;
```

<details><summary>Ответ</summary>

Ошибка `CS8820`: `static`-лямбда не может захватывать локальные переменные и `this` (проверено). Зато компилятор гарантирует, что захвата нет: такая лямбда не выделяет память (делегат кешируется), тогда как лямбда с захватом создаёт объект замыкания (в замере — 80 байт), а группа методов экземпляра — делегат при каждом преобразовании (56 байт; для статического метода 0).
→ [Экспертная теория](expert.ru.md#static-лямбда-и-захват)

</details>

## 11. 🔴 Что произойдёт, если обработчик отпишет сам себя во время вызова события?

```csharp
// a one-shot handler: removes itself on the first call
```

- A) `InvalidOperationException`
- B) безопасно: вызывается копия списка вызова на момент начала; обработчик сработает один раз
- C) все остальные обработчики будут пропущены
- D) бесконечный цикл

<details><summary>Ответ</summary>

**B.** Делегат неизменяем: отписка создаёт новый делегат, а текущий вызов продолжает обходить старый список (проверено: первая рассылка вызвала обоих, вторая — только оставшийся).
→ [Экспертная теория](expert.ru.md#отписка-во-время-вызова-безопасна)

</details>
