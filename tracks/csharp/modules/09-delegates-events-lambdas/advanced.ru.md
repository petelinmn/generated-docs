# Делегаты, события, лямбды: продвинутая теория

🌐 **Русский** · [English](advanced.en.md)

**Уровни:** [обзор](overview.ru.md) · [1. Базовая](basics.ru.md) · **2. Продвинутая** · [3. Экспертная](expert.ru.md)

## Многоадресные делегаты

```csharp
Action bad = () => log.Add("1");
bad += () => throw new InvalidOperationException("x");
bad += () => log.Add("3");
try { bad(); } catch (Exception e) { log.Add("caught " + e.Message); }
// 1 caught x — the third handler never ran
```

Правила, проверенные запуском:

- **Порядок** вызова — порядок добавления.
- **Результат** — значение последнего метода: для `Func<int>` с тремя обработчиками `1`, `2`, `3` вызов вернул `3`. Результаты остальных теряются.
- **Исключение прерывает цепочку**: после броска оставшиеся обработчики не выполняются. Чтобы вызвать все независимо, переберите `GetInvocationList()` и вызывайте каждый в своём `try`.
- **`+=` для `null`** создаёт делегат: `Action? none = null; none += …;` сработало. Вызов `none()` у пустого делегата даёт `NullReferenceException`, поэтому `?.Invoke()`.
- **Делегаты неизменяемы**: `+=` и `-=` создают **новый** делегат. Копия `Action copy = orig;`, сделанная до `orig += …`, осталась прежней (проверено).
- **`-=`** убирает **последнее вхождение** такого же делегата: для `all = r1; all += r1; all -= r1;` остался один `r1`. Сравнение — по методу и объекту: `(Action)Hello == (Action)Hello` — `True`, а два одинаковых по тексту лямбда-выражения — `False`, поэтому отписаться «такой же» лямбдой нельзя (проверено: она не удалилась).
- `Delegate.Combine(a, b)` и `Delegate.Remove(...)` — то же, что `+` и `-` (`Combine(act, act)` для делегата из трёх методов дал список из шести).

## Лямбды в деталях

### Естественный тип и параметры

```csharp
var natural = (int x) => x + 1;                  // Func<int, int>
var withDefault = (int x, int y = 10) => x + y;  // withDefault(1) == 11
var typed = int (int x) => x;                    // explicit return type
Func<int, int> sq = static x => x * x;           // static lambda
```

Группа методов тоже получает естественный тип: `var f = Hello;` — `Action` (если подходящий единственный метод).

### static-лямбды

Модификатор `static` запрещает лямбде захватывать переменные (и `this`): ошибка CS8820 «Статическая анонимная функция не может содержать ссылку на "x"» (проверено). Это защищает от случайного замыкания и от лишних выделений.

### Замыкания и их стоимость

Когда лямбда использует локальную переменную, компилятор переносит её в поле скрытого класса (`<>c__DisplayClass…`), а лямбду делает методом этого класса. Проверено рефлексией: у делегата `inc` свойство `Target` — объект класса `<>c__DisplayClass0_0`, а его поля — **все** захваченные переменные области (`log`, `counter`, …): они живут в одном объекте.

Выделения памяти (измерено через `GC.GetAllocatedBytesForCurrentThread`):

| Выражение | Выделено |
|---|---|
| лямбда без захвата (`x => x + 1`) | 0 байт: компилятор кеширует делегат |
| группа методов статического метода | 0 байт: тоже кешируется (проверено на .NET 11) |
| группа методов метода экземпляра (`o.Inst`) | 56 байт: каждый раз создаётся новый делегат |
| лямбда с захватом (`() => y`) | 80 байт: объект замыкания (24) + делегат (56) |
| вызов уже созданного делегата ×1000 | 0 байт |

Следствие для «горячего» кода: не создавайте делегат с захватом в каждой итерации; используйте `static`-лямбды и передавайте состояние параметром; создайте делегат один раз и переиспользуйте.

```csharp
static Func<int, int> Make() => x => x + 1;            // ReferenceEquals(Make(), Make()) == true: cached
static Func<int> MakeCap(int y) => () => y;            // a new delegate and closure every call
```

### Локальные функции и лямбды

Локальная функция — тоже метод внутри метода, но её не нужно присваивать делегату, у неё могут быть имя, рекурсия и атрибуты, а компилятор не создаёт делегат, пока вы его не потребуете. Если передать её как делегат (`Func<int,int> f = Local;`), она ведёт себя как лямбда. Рекурсивная лямбда требует предварительного объявления переменной: `Func<int,int> fact = null!; fact = n => n <= 1 ? 1 : n * fact(n - 1);` (`fact(5)` — `120`).

### Возврат функций

```csharp
Func<int, Func<int, int>> adder = a => b => a + b;   // currying
Console.WriteLine(adder(2)(3));                       // 5
```

Каждая вложенная лямбда создаёт своё замыкание.

## События в деталях

### Событие и публичное поле

```csharp
public class C { public event Action? Evt; }

var c = new C();
c.Evt();          // error CS0070: an event can be only on the left of += and -=
c.Evt = null;     // error CS0070
```

Событие позволяет подписчику только `+=`/`-=`. Публичное поле-делегат позволяет **кому угодно** вызвать его, заменить цепочку или обнулить: чужой код сломает подписки.

### Шаблон EventArgs

- Издатель объявляет `event EventHandler<TEventArgs>? Name`.
- Вызов оформляют защищённым виртуальным методом `OnName`, чтобы наследники могли его переопределить:

```csharp
protected virtual void OnChanged(ValueEventArgs e) => Changed?.Invoke(this, e);
```

- Данные события — класс-наследник `EventArgs` (в современном .NET для `EventHandler<T>` ограничение `T : EventArgs` не требуется, но шаблон по-прежнему принят).
- Имена: событие — глагол или причастие (`Clicked`, `Changed`, `Closing`); метод-вызыватель — `On` + имя.

### Потокобезопасность вызова

Проверка `if (Changed != null) Changed(...)` небезопасна: между проверкой и вызовом другой поток может отписать последний обработчик. Выражение `Changed?.Invoke(...)` читает поле **один раз** и вызывает копию, поэтому `NullReferenceException` не возникает. Из-за неизменяемости делегатов безопасна и отписка во время вызова: в проверке первый обработчик отписал сам себя во время `Set(1)`, и при втором `Set(2)` вызвался только второй (журнал `once other other`). Но сами обработчики выполняются в потоке вызывающего и должны быть готовы к многопоточности.

### Собственные аксессоры add/remove

По умолчанию событие — делегат-поле плюс методы `add`/`remove` (проверено рефлексией: у `Publisher` есть `add_Changed`, `remove_Changed`, событие `Changed` и закрытое поле `Changed` типа `EventHandler`1`). Аксессоры можно написать вручную, например, чтобы хранить подписчиков в словаре или проверять подписку:

```csharp
private Action? _h;
public event Action Evt
{
    add { _h += value; }
    remove { _h -= value; }
}
```

### Утечки и отписка

Подписка `+=` сохраняет ссылку на объект-подписчик в делегате издателя. Если издатель живёт дольше, подписчик не будет собран: подробно с примером — [12 · Память и GC](../12-memory-and-gc/advanced.ru.md#утечки-памяти-в-управляемом-коде). Решения: `-=` в `Dispose`, возврат токена-`IDisposable` из метода подписки, слабые события.

### async void и события

Обработчик события может быть `async void` (единственное оправданное применение `async void`): исключение из него нельзя поймать вокруг вызова события, оно уйдёт в контекст синхронизации и может завершить процесс (10 · Async/await). Оборачивайте тело обработчика в `try/catch`.

## Вариантность делегатов

Делегаты вариантны по типам параметров и результата:

```csharp
Func<string> fs = () => "s";
Func<object> fo = fs;                        // covariance by result

Action<object> ao = o => Console.Write("ao");
Action<string> asx = ao;                     // contravariance by parameter
asx("x");
```

Проверено: оба присваивания работают. Работает только для ссылочных типов. Подробнее о правилах — в [06 · Коллекции и обобщения](../06-collections-and-generics/advanced.ru.md#вариантность).

## Вызов без компиляторных проверок

`Delegate.DynamicInvoke(params object[])` вызывает делегат с неизвестной сигнатурой: `d3.DynamicInvoke(1, 2)` дал `3`, а неверные аргументы (`"x"`, `2`) — `ArgumentException` во время выполнения. Он заметно медленнее обычного вызова; применяйте только когда тип неизвестен на этапе компиляции.

## Лучшие практики

- Используйте `Func`/`Action`/`Predicate` вместо собственных делегатов; собственный — когда нужны `ref`/`out`/`in`-параметры или говорящее имя.
- Событие — `EventHandler<T>` и защищённый `OnXxx`; вызывайте через `?.Invoke`.
- Отписывайтесь от событий долгоживущих объектов.
- В горячем коде — `static`-лямбды и делегаты, созданные один раз.
- Не полагайтесь на порядок выполнения подписчиков и не бросайте исключения из обработчиков: первое прерывает цепочку.
- Для публичного API вместо многоадресных делегатов с результатом — события или интерфейсы.

## Частые ошибки

- ❌ Исключение в одном обработчике, и остальные не вызваны → ✅ перебирать `GetInvocationList()` с `try` на каждый.
- ❌ Отписка «такой же» лямбдой → ✅ сохранить делегат в переменную или использовать метод.
- ❌ Лямбда с захватом в цикле, который выполняется миллионы раз → ✅ `static` и параметр состояния.
- ❌ `async void` вне обработчиков событий → ✅ `async Task`.
- ❌ Публичное поле-делегат → ✅ `event`.
- ❌ Проверка `!= null` и вызов отдельно → ✅ `?.Invoke`.
