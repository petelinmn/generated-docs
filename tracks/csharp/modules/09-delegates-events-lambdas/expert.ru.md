# Делегаты, события, лямбды: экспертная теория

🌐 **Русский** · [English](expert.en.md)

**Уровни:** [обзор](overview.ru.md) · [1. Базовая](basics.ru.md) · [2. Продвинутая](advanced.ru.md) · **3. Экспертная**

## Под капотом

### Что такое делегат

Каждый тип делегата, объявленный через `delegate` (и `Func`, `Action` и другие), — **запечатанный класс**, который наследует от `System.MulticastDelegate` (проверено: у `Action` базовый тип — `MulticastDelegate`, `IsSealed == True`). Объект делегата хранит два значения:

- **цель** (`Target`) — объект, у которого вызывается метод; для статического метода и для лямбды без захвата её нет или это экземпляр служебного класса;
- **метод** (`Method`) — ссылку на реализацию.

Проверено: у делегата на статический метод `Multiply` — `Method.Name == "Multiply"` и `Target == null`. Метод `Invoke` объявляется компилятором и реализуется самим runtime: вызов `d(x)` превращается в `d.Invoke(x)`, то есть в косвенный вызов по ссылке на метод, а не в обычный вызов.

### Многоадресность

`MulticastDelegate` держит **список вызова** (invocation list). `+=` вызывает `Delegate.Combine`, `-=` — `Delegate.Remove`: оба **создают новый делегат** (старые не меняются, поэтому делегаты безопасны для многопоточного чтения). `GetInvocationList()` возвращает массив делегатов из одного метода; проверено: `Combine(act, act)` для делегата из трёх методов дал шесть. `Remove` ищет **последнее вхождение**. Сравнение `==` — по методу и цели: два вызова `(Action)Hello` равны, а две одинаковые по тексту лямбды — нет (разные объекты-цели или разные методы).

### Лямбда без захвата и кеш

Для лямбды без захвата компилятор создаёт статический метод в служебном классе `<>c` (проверено: `Target` — экземпляр `<>c`, `Method.DeclaringType` — `<>c`) и **кеширует делегат** в статическом поле. Поэтому `ReferenceEquals(Make(), Make())` — `True`, а выделений при повторном вычислении лямбды нет (0 байт). Начиная с C# 11, так же кешируются группы методов статических методов (0 байт — проверено). У метода **экземпляра** делегат привязан к объекту, поэтому каждое преобразование группы методов создаёт новый делегат (56 байт).

### Замыкание и скрытый класс

Для лямбды с захватом компилятор создаёт **класс замыкания** `<>c__DisplayClass…` вложенный в тип, в котором объявлен метод (проверено: `Target.GetType().Name`, а `DeclaringType` — `Program`). Захваченные локальные переменные и параметры становятся **полями** этого класса; сама лямбда — его метод. Важные следствия:

- Все лямбды одной области видимости используют **один** объект замыкания. Проверено: в методе, где одна лямбда использовала малую переменную `small`, а другая — большой массив `big`, живая первая лямбда удерживала и `big` — массив не был собран (`IsAlive == True`), хотя использующая его лямбда уже недоступна. Поэтому долгоживущие обработчики лучше создавать в отдельном методе с минимумом захватываемого.
- Каждый вход в область создаёт новый объект замыкания (для переменных внутри цикла — на каждую итерацию, для переменной `for` — один на весь цикл: отсюда `3,3,3`, см. [07 · LINQ](../07-linq/advanced.ru.md#замыкания-переменная-читается-при-выполнении)).
- В файле с операторами верхнего уровня все локальные переменные находятся в одной области, и замыкание поэтому несёт их все (проверено: поля `log, counter, rp, h, d3, fact`).
- `this` захватывается как поле, если лямбда использует члены экземпляра: тогда объект живёт, пока жив делегат.

### События — это поле и два метода

Для объявления `public event EventHandler<ValueEventArgs>? Changed;` компилятор генерирует (проверено рефлексией у `Publisher`):

| Член | Что это |
|---|---|
| закрытое поле `Changed` типа `EventHandler`1` | хранит делегат |
| метод `add_Changed` | подписка: `+=` |
| метод `remove_Changed` | отписка: `-=` |
| событие `Changed` | метаданные, связывающие `add`/`remove` |

Снаружи видны только `add` и `remove`, поэтому присвоить или вызвать событие нельзя (CS0070). Внутри класса имя `Changed` указывает на поле, поэтому `Changed?.Invoke(...)` работает. Аксессоры событий-полей генерируются потокобезопасными (по спецификации: обновление поля — циклом сравнения и обмена). Если написать `add`/`remove` вручную, потокобезопасность — на вас.

### Указатели на функции

В небезопасном коде есть тип `delegate*<…>`: «голый» указатель на метод без объекта делегата. Проверено: `delegate*<int, int> p = &Sq; p(4)` вернул `16`, размер указателя — 8 байт (как `IntPtr` на этой платформе).

| | делегат | указатель на функцию |
|---|---|---|
| объект в куче | да (56 байт) | нет |
| цель и замыкание | да | нет, только статические методы |
| многоадресность | да | нет |
| безопасность | управляемый | `unsafe`, нужен `AllowUnsafeBlocks` |
| применение | обычный код | взаимодействие с нативным кодом, высокопроизводительные пути |

### Стандартные типы делегатов

| Тип | Сигнатура |
|---|---|
| `Action`, `Action<T1…T16>` | `void (…)` |
| `Func<TResult>`, `Func<T1…T16, TResult>` | `TResult (…)` |
| `Predicate<T>` | `bool (T)` |
| `Comparison<T>` | `int (T, T)` |
| `Converter<TIn, TOut>` | `TOut (TIn)` |
| `EventHandler`, `EventHandler<T>` | `void (object? sender, T e)` |
| `AsyncCallback`, `ThreadStart`, `ParameterizedThreadStart` | наследие потоковых и асинхронных API |

### Формы лямбд и групп методов

| Форма | Пример | С версии |
|---|---|---|
| лямбда-выражение | `x => x * 2` | C# 3 |
| лямбда с блоком | `x => { return x * 2; }` | C# 3 |
| асинхронная | `async x => await Foo(x)` | C# 5 |
| без параметров | `() => 1` | C# 3 |
| отброшенные параметры | `(_, _) => 0` | C# 9 |
| `static` | `static x => x` | C# 9 |
| естественный тип, `var` | `var f = (int x) => x;` | C# 10 |
| явный возвращаемый тип | `int (int x) => x` | C# 10 |
| атрибуты на лямбде | `[Obsolete] (int x) => x` | C# 10 |
| параметры по умолчанию и `params` | `(int x, int y = 10) => x + y` | C# 12 |
| группа методов | `Func<int,int> f = Twice;` | C# 1 |

### Что захватывает замыкание

| Захватывается | Как |
|---|---|
| локальная переменная, параметр | поле класса замыкания; изменения видны обеим сторонам |
| `this` | поле-ссылка на объект |
| `ref`-параметры, `ref struct`, `Span<T>` | **нельзя** |

### Члены Delegate

| Член | Назначение |
|---|---|
| `Target`, `Method` | цель и метод |
| `Invoke(…)` | вызов (то же, что `d(…)`) |
| `GetInvocationList()` | массив делегатов из одного метода |
| `DynamicInvoke(object[])` | вызов без проверки сигнатуры на этапе компиляции (медленный; неверные аргументы дают `ArgumentException`) |
| `Delegate.Combine`, `Delegate.Remove` | то же, что `+`, `-` |
| `Delegate.CreateDelegate(type, method)` | создание делегата рефлексией (`Twice` → вызов `d(4)` дал `8`) |

## Подвохи

Каждый подвох проверен запуском.

### Исключение прерывает многоадресный вызов

`1 → throw → 3`: третий обработчик не выполнился. Для независимого вызова используйте `GetInvocationList()` и `try` на каждый.

### Результат — последнего обработчика

`Func<int>` с `1, 2, 3` вернул `3`; значения первых двух потеряны.

### Отписка другой копией лямбды не работает

`combined -= l2` (лямбда с тем же текстом) оставила обработчик: вывод всё равно `lam`.

### Копия делегата не видит изменений

`Action copy = orig; orig += …; copy();` вызвал только исходный метод: `+=` создаёт новый делегат.

### Замыкание удерживает лишнее

Живая лямбда, использующая только `small`, не дала собрать `big`, захваченный другой лямбдой: они делят объект замыкания.

### Группа методов экземпляра создаёт делегат каждый раз

`Func<int> g = o.Inst;` в цикле — 56 байт на итерацию; для статического метода — 0 (кеш).

### Вызов null-делегата

`n!()` для `null` — `NullReferenceException`; `n?.Invoke()` безопасно.

### События нельзя вызвать снаружи

`c.Evt();` и `c.Evt = null;` вне класса — CS0070; для публичного поля-делегата обе операции были бы допустимы.

### static-лямбда и захват

`static () => x` при использовании локальной `x` — CS8820.

### Отписка во время вызова безопасна

Первый обработчик отписал себя в `Set(1)`; вторая рассылка вызвала только второй (`once other other`): вызывается копия списка на момент начала вызова.

### Два одинаковых лямбда-выражения не равны

`(Func<int>)(() => 1) == (Func<int>)(() => 1)` — `False`: разные методы.

## Компромиссы и альтернативы

| Задача | Вариант | Цена |
|---|---|---|
| Передать поведение | делегат (`Func`/`Action`) | выделение при захвате, косвенный вызов |
| | интерфейс с одним методом | больше кода, зато явный контракт и без замыканий |
| Уведомления | `event` | подписчики удерживаются издателем; нужна отписка |
| | интерфейс-наблюдатель, `IObservable<T>` | больше шаблонного кода |
| | `Channel<T>` | другая модель: очередь сообщений |
| Горячий путь | `static`-лямбда, делегат один раз | передавать состояние параметрами |
| | указатель `delegate*` | `unsafe`, только статические методы |
| Динамический вызов | `DynamicInvoke` | медленный, ошибки во время выполнения |

## Вопросы с собеседований

**1. Что такое делегат? Как он устроен?**

<details><summary>Ответ</summary>

Типобезопасная ссылка на метод. Это запечатанный класс, наследник `MulticastDelegate`, который хранит цель (`Target`) и метод (`Method`) и список вызова. Вызов `d(x)` — это `d.Invoke(x)`.

</details>

**2. Чем отличаются `Func`, `Action` и `Predicate`?**

<details><summary>Ответ</summary>

`Action` — возвращает `void`; `Func<…, TResult>` — возвращает значение (последний параметр типа — результат); `Predicate<T>` — `bool (T)`, то есть частный случай `Func<T,bool>`, исторически используется в `List<T>.RemoveAll`, `FindAll`.

</details>

**3. Что такое многоадресный делегат? Что вернёт вызов и что будет при исключении?**

<details><summary>Ответ</summary>

Делегат со списком вызова: `+=` добавляет, `-=` убирает; при вызове методы выполняются по порядку. Возвращаемое значение — результат **последнего** (проверено: `3` для `1, 2, 3`). Исключение прерывает цепочку: следующие обработчики не вызываются (`1 caught x`).

</details>

**4. Чем событие отличается от публичного поля-делегата?**

<details><summary>Ответ</summary>

Событие — поле-делегат плюс методы `add`/`remove`: снаружи можно только подписаться и отписаться, а вызвать и перезаписать его может лишь сам класс (CS0070). Публичное поле позволяет кому угодно вызвать делегат, заменить цепочку или обнулить её.

</details>

**5. Как правильно вызывать событие? Почему `?.Invoke`?**

<details><summary>Ответ</summary>

`Changed?.Invoke(this, e)`: если подписчиков нет, событие `null`; `?.` читает поле один раз и вызывает копию, поэтому между проверкой и вызовом другой поток не обнулит его. Прямой вызов `null`-делегата — `NullReferenceException` (проверено).

</details>

**6. Что такое замыкание? Что захватывается — значение или переменная?**

<details><summary>Ответ</summary>

Лямбда, использующая локальные переменные внешнего метода. Захватывается **переменная**, а не значение: компилятор переносит её в поле скрытого класса (`<>c__DisplayClass`), и лямбда с внешним кодом видят одно и то же поле (`counter == 2` после двух вызовов `inc`).

</details>

**7. Подвох: что выведет код?**

```csharp
var fs = new List<Func<int>>();
for (int i = 0; i < 3; i++) fs.Add(() => i);
foreach (var f in fs) Console.Write(f() + " ");
```

<details><summary>Ответ</summary>

`3 3 3`: у цикла `for` одна переменная `i`, лямбды читают её итоговое значение. С `foreach (var i in …)` было бы `0 1 2`. Исправление — копия в локальную переменную внутри тела цикла.

</details>

**8. Когда лямбда выделяет память?**

<details><summary>Ответ</summary>

Лямбда без захвата — нет (делегат кешируется в статическом поле, 0 байт), лямбда с захватом — да: объект замыкания (24 байта) и делегат (56) = 80 байт на создание (проверено). Группа методов статического метода — 0, экземпляра — 56 на каждое преобразование. Вызов созданного делегата не выделяет память.

</details>

**9. Что делает модификатор `static` у лямбды?**

<details><summary>Ответ</summary>

Запрещает захват локальных переменных и `this` (CS8820), поэтому лямбда гарантированно без замыкания и кешируется. Используют для защиты от случайных выделений в горячем коде.

</details>

**10. Как отписаться от события, на которое подписались лямбдой?**

<details><summary>Ответ</summary>

Сохранить делегат в переменную и использовать её и в `+=`, и в `-=`. Другая лямбда с тем же текстом — другой делегат (равенство по методу и цели), и `-=` её не удалит (проверено). Либо подписываться методом, либо возвращать из метода подписки токен `IDisposable`.

</details>

**11. Какую утечку памяти дают события?**

<details><summary>Ответ</summary>

Делегат в событии издателя ссылается на объект-подписчик. Если издатель живёт дольше, подписчик не собирается. Решения: `-=` в `Dispose`, токен-подписка, слабые события. Подробнее — [12 · Память и GC](../12-memory-and-gc/advanced.ru.md#утечки-памяти-в-управляемом-коде).

</details>

**12. Подвох: почему живая лямбда не даёт собрать большой объект, который она не использует?**

<details><summary>Ответ</summary>

Все лямбды одной области делят один объект замыкания с полями для **всех** захваченных переменных. Если одна лямбда использует `big`, а другая — `small`, и живёт вторая, она удерживает объект замыкания, а значит и `big` (проверено: массив не был собран).

</details>

**13. Как делегаты вариантны?**

<details><summary>Ответ</summary>

Ковариантны по результату (`Func<string>` → `Func<object>`) и контравариантны по параметрам (`Action<object>` → `Action<string>`); работает для ссылочных типов. Проверено присваиваниями.

</details>

**14. Чем делегат отличается от указателя на функцию `delegate*`?**

<details><summary>Ответ</summary>

Делегат — объект в куче (56 байт) с целью и списком вызова, управляемый и безопасный. `delegate*<…>` — «голый» указатель (8 байт на 64-битной платформе) на статический метод: без объекта, цели и многоадресности, только в `unsafe`-коде; применяется для нативных вызовов и горячих путей.

</details>

**15. Что такое `async void` в обработчиках событий и чем он опасен?**

<details><summary>Ответ</summary>

Событие ожидает `void`-обработчик, поэтому `async void` — единственное допустимое применение. Исключение из него нельзя поймать вокруг вызова события: оно уходит в контекст синхронизации и может завершить процесс. Поэтому тело оборачивают в `try/catch`. Подробнее — 10 · Async/await.

</details>

**16. Как вызвать все обработчики многоадресного делегата независимо друг от друга?**

<details><summary>Ответ</summary>

Перебрать `GetInvocationList()` и вызвать каждый в своём `try/catch`; тогда исключение одного не прерывает остальных. Результаты и ошибки собираются отдельно.

</details>

## Шпаргалка

| Нужно | Решение |
|---|---|
| Передать поведение | `Func`/`Action`/`Predicate` |

| Отписаться от лямбды | сохранить делегат в переменную |

| Нативные пути | `delegate*` в `unsafe` |
