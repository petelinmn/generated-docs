# Интерфейсы, структуры, записи: базовая теория

**Пререквизиты:** [04 · ООП: классы и объекты](../04-oop-basics/overview.ru.md), [02 · Типы и переменные](../02-types-and-variables/overview.ru.md).

## Зачем это нужно

Класс — не единственный способ описать тип. Три других инструмента решают конкретные задачи:

- **интерфейс** описывает **контракт** — что тип умеет, не говоря, как; один класс может реализовать много интерфейсов;
- **структура** (`struct`) — **значимый тип**: данные копируются при присваивании, хорошо подходит для небольших значений (точка, цвет, деньги);
- **запись** (`record`) — тип для **данных**: компилятор сам создаёт равенство по значению, `ToString()`, копирование `with` и деконструкцию.

## Интерфейсы

Интерфейс — набор членов без реализации. Класс, который его реализует, обязан предоставить все члены:

```csharp
public interface IShape
{
    string Name { get; }
    double Area();
}

public class Circle(double radius) : IShape
{
    public string Name => "circle";
    public double Area() => Math.PI * radius * radius;
}
```

Код, которому нужен контракт, работает с интерфейсом и не знает о конкретном классе:

```csharp
static double TotalArea(IEnumerable<IShape> shapes) => shapes.Sum(s => s.Area());
```

- Имена интерфейсов по соглашению начинаются с `I`.
- Класс реализует **несколько интерфейсов** (`class Foo : IA, IB`), но наследует только от одного класса.
- Переменной интерфейсного типа можно присвоить любой объект, реализующий интерфейс; проверить — `is`, `as` (`ia is IB`).
- С C# 8 интерфейс может содержать **реализацию по умолчанию** — подробнее в [продвинутой теории](advanced.ru.md#реализация-по-умолчанию-и-явная-реализация).

### Интерфейс или абстрактный класс

| | Интерфейс | Абстрактный класс |
|---|---|---|
| Состояние (поля) | нет | есть |
| Конструкторы | нет | есть |
| Сколько можно реализовать или унаследовать | сколько угодно | один |
| Для чего | контракт, возможность («умеет») | общая основа, «является» |

Правило: начинай с интерфейса; абстрактный класс нужен, когда хочется передать наследникам готовое состояние и реализацию.

## Структуры

Структура — значимый тип. Переменная хранит **сами данные**, а не ссылку, поэтому присваивание копирует значение:

```csharp
public struct Pt
{
    public int X;
    public int Y;
    public Pt(int x, int y) { X = x; Y = y; }
}

var p1 = new Pt(1, 2);
var p2 = p1;            // a copy
p2.X = 99;
Console.WriteLine($"{p1.X} {p2.X}");   // 1 99
```

Структура не создаётся «отдельным объектом» в куче: локальная переменная живёт в стеке, а поле структуры — внутри владеющего объекта (подробнее — [02 · Типы и переменные](../02-types-and-variables/expert.ru.md)). Это снимает нагрузку со сборщика мусора, но копирование больших структур стоит дорого.

Свойства структур:

- нельзя унаследовать от другой структуры или класса (интерфейсы реализовать можно);
- у структуры всегда есть значение по умолчанию — все поля нулевые: `default(Pt)` — `(0, 0)`;
- с C# 10 можно объявить конструктор без параметров и инициализаторы полей: `struct Wd { public int V = 7; public Wd() { } }` — тогда `new Wd().V` равно `7`, а `default(Wd).V` — `0`;
- `==` для структур автоматически **не определён**: `a == b` не компилируется (ошибка CS0019), но `a.Equals(b)` сравнивает поля.

**`readonly struct`** гарантирует, что структура неизменяема: все поля только для чтения. Это защищает от скрытых копий (см. [продвинутую теорию](advanced.ru.md#изменяемые-структуры)).

### Когда использовать структуру

- ✅ маленькое (до 16 байт ориентировочно), неизменяемое значение, логически «одно число»: координаты, цвет, дата;
- ✅ тип, который создаётся в больших количествах;
- ❌ большие объекты, объекты с идентичностью, типы, которые нужно наследовать;
- ❌ изменяемые структуры — источник ошибок.

## Записи

Запись (`record`) — тип, который описывает данные, и для них компилятор генерирует типичный код:

```csharp
public record Person(string Name, int Age);

var a = new Person("Ann", 30);
var b = new Person("Ann", 30);

Console.WriteLine(a == b);              // True — equality by value
Console.WriteLine(ReferenceEquals(a, b)); // False — different objects
Console.WriteLine(a);                   // Person { Name = Ann, Age = 30 }
```

Что даёт запись:

- **равенство по значению**: `==` и `Equals` сравнивают все свойства, а `GetHashCode` согласован с ними;
- **`ToString()`** в виде `Person { Name = Ann, Age = 30 }`;
- **неизменяемость** по умолчанию: свойства позиционной записи — `init`;
- **выражение `with`** — копия с изменением:

```csharp
var older = a with { Age = 31 };        // a is unchanged
Console.WriteLine(older);               // Person { Name = Ann, Age = 31 }
```

- **деконструкция**: `var (name, age) = a;`.

`record` по умолчанию — класс (`record class`), то есть ссылочный тип. Для значимого типа есть `record struct`, а `readonly record struct` — неизменяемый вариант:

```csharp
public readonly record struct Point(int X, int Y);
```

Запись можно объявить и без позиционных параметров, с обычными свойствами: `public record Order { public required int Id { get; init; } }`.

## Равенство: ссылки и значения

Три способа сравнить объекты:

| Способ | Что делает по умолчанию |
|---|---|
| `ReferenceEquals(a, b)` | сравнивает ссылки (для значимых типов всегда `false`) |
| `a.Equals(b)` | класс — ссылки; структура — поля; запись — значения свойств |
| `a == b` | класс — ссылки (если не перегружен); структура — не определён; запись — значения; `string` — по содержимому |

Поэтому для обычных классов два объекта с одинаковыми данными не равны, а для записей — равны. Если нужно равенство по значению для класса, переопределите `Equals` и `GetHashCode` (см. [продвинутую теорию](advanced.ru.md#равенство-и-gethashcode)).

## Что выбрать

| Нужно | Выбор |
|---|---|
| Контракт, сменные реализации, тесты с подменой | интерфейс |
| Объект с идентичностью и изменяемым состоянием | `class` |
| Данные, которые сравниваются по значению и не меняются | `record` |
| Маленькое значение без идентичности | `struct` / `readonly record struct` |

## Ошибки новичка

- ❌ Использовать класс-«контейнер данных» и удивляться, что `==` даёт `false` → ✅ `record`.
- ❌ Делать структуру большой или изменяемой → ✅ маленькая неизменяемая или обычный класс.
- ❌ Ожидать, что `with` копирует вложенные объекты → ✅ копия поверхностная.
- ❌ Создавать интерфейс «на всякий случай» с одной реализацией → ✅ интерфейс нужен, когда есть вторая реализация или подмена в тестах.
- ❌ Пытаться изменить элемент `List<структура>` на месте (`list[0].X = 5`) → ✅ ошибка CS1612; заменить элемент целиком.
