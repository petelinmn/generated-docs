# Квиз: Интерфейсы, структуры, записи

🌐 **Русский** · [English](quiz.en.md)

> Сначала ответь сам, потом раскрывай ответ. Отметка показывает, из какого уровня вопрос: 🟢 [базовая теория](basics.ru.md) · 🟡 [продвинутая](advanced.ru.md) · 🔴 [экспертная](expert.ru.md).

## 1. 🟢 Что из этого возможно в C#?

- A) класс наследуется от двух классов
- B) класс реализует несколько интерфейсов
- C) интерфейс создаётся через `new`
- D) структура наследуется от класса

<details><summary>Ответ</summary>

**B.** Базовый класс один, а интерфейсов можно реализовать сколько угодно. Интерфейс создать нельзя — только объект, который его реализует. Структуры не наследуют классы (кроме неявного `ValueType`).
→ [Базовая теория](basics.ru.md#интерфейсы)

</details>

## 2. 🟢 Что выведет код?

```csharp
record Point(int X, int Y);

var p1 = new Point(1, 2); var p2 = new Point(1, 2);
var p3 = p1 with { X = 10 };
Console.WriteLine($"{p1 == p2} {ReferenceEquals(p1, p2)} {p3}");
```

<details><summary>Ответ</summary>

```text
True False Point { X = 10, Y = 2 }
```

У записи равенство по значению (`==` сравнивает свойства), но это два разных объекта в памяти. `with` создаёт копию с изменённым свойством, исходный `p1` не меняется.
→ [Базовая теория](basics.ru.md#записи)

</details>

## 3. 🟢 Выберите все верные утверждения

- [ ] A) `record` по умолчанию — ссылочный тип
- [ ] B) `record struct` — значимый тип
- [ ] C) свойства позиционной записи можно присвоить после создания
- [ ] D) структура при присваивании копируется

<details><summary>Ответ</summary>

**A, B, D.** C неверно: свойства позиционной записи — `init`, присваивание после создания даёт ошибку `CS8852` (проверено). Для изменения используйте `with`.
→ [Базовая теория](basics.ru.md#структуры)

</details>

## 4. 🟢 Чем интерфейс отличается от абстрактного класса?

- A) интерфейс описывает контракт без состояния (полей), класс может реализовать несколько интерфейсов
- B) интерфейс может иметь поля экземпляра
- C) абстрактный класс можно реализовать несколькими классами одновременно
- D) разницы нет

<details><summary>Ответ</summary>

**A.** Интерфейс — контракт без состояния (с C# 8 допускает методы по умолчанию). Абстрактный класс может хранить поля и общую логику, но наследовать можно только один.
→ [Базовая теория](basics.ru.md#интерфейс-или-абстрактный-класс)

</details>

## 5. 🟡 Что произойдёт?

```csharp
struct Vec { public int X; }
var list = new List<Vec> { new() { X = 1 } };
list[0].X = 5;
```

- A) `list[0].X` станет 5
- B) ошибка компиляции CS1612
- C) исключение во время выполнения
- D) ничего, значение останется 1

<details><summary>Ответ</summary>

**B.** Индексатор списка возвращает **копию** структуры, поэтому изменение копии бессмысленно, и компилятор не пускает (`CS1612`). Исправление: записать новое значение целиком — `list[0] = list[0] with { X = 5 }` (для `record struct`) или `var v = list[0]; v.X = 5; list[0] = v;`. Для массива `arr[0].X = 7` работает: элемент массива доступен по ссылке.
→ [Продвинутая теория](advanced.ru.md#изменяемые-структуры)

</details>

## 6. 🟡 Что выведет код?

```csharp
class BadKey { public int Id; public override bool Equals(object? o) => o is BadKey b && b.Id == Id; public override int GetHashCode() => Id; }

var set = new HashSet<BadKey>();
var k = new BadKey { Id = 1 };
set.Add(k);
k.Id = 2;
Console.WriteLine($"{set.Count} {set.Contains(k)}");
```

- A) `1 True`
- B) `1 False`
- C) `0 False`
- D) `2 True`

<details><summary>Ответ</summary>

**B.** Элемент остался в множестве (`Count == 1`), но лежит в «корзине» по старому хеш-коду, поэтому поиск по новому хешу его не находит. Ключи коллекций должны быть неизменяемыми — например, запись `GoodKey(int Id)`.
→ [Продвинутая теория](advanced.ru.md#подвох-изменяемый-ключ)

</details>

## 7. 🟡 Выберите все верные утверждения

- [ ] A) `Equals` без `GetHashCode` даёт предупреждение компилятора `CS0659`
- [ ] B) две записи с одинаковым по содержимому `List<int>` равны
- [ ] C) `with` копирует `List<T>` поверхностно
- [ ] D) явная реализация интерфейса видна только через переменную типа интерфейса

<details><summary>Ответ</summary>

**A, C, D.** B неверно: `List<T>` сравнивается по ссылке, поэтому такие записи не равны, а `with` не клонирует список — изменение копии видно в оригинале. A: без `GetHashCode` типы не находятся в `HashSet`/`Dictionary` (проверено).
→ [Продвинутая теория](advanced.ru.md#записи-глубже)

</details>

## 8. 🟡 Метод интерфейса с реализацией по умолчанию не виден через класс. Почему этот код не компилируется?

```csharp
interface IShape { string Describe() => "shape"; }
class Sq : IShape { }

new Sq().Describe();
```

<details><summary>Ответ</summary>

Ошибка `CS1061`: методы по умолчанию доступны только через переменную типа интерфейса — `IShape s = new Sq(); s.Describe();`. Класс «наследует» контракт, но не сами члены. Если нужен вызов через класс, реализуйте метод в классе.
→ [Продвинутая теория](advanced.ru.md#реализация-по-умолчанию-и-явная-реализация)

</details>

## 9. 🟡 Открытый вопрос: когда выбирать `struct`, когда `class`, когда `record`?

<details><summary>Ключевые пункты хорошего ответа</summary>

- структура — небольшие неизменяемые значения (около 16 байт), без частого боксинга, когда нужна семантика копирования;
- класс — когда есть идентичность, изменяемое состояние, большой размер или наследование;
- `record` (класс) — данные с равенством по значению, `with`, деконструкцией: DTO, события, значения предметной области;
- `readonly record struct` — маленькие значения с равенством по значению;
- структуры, упакованные в `object`/интерфейс, теряют преимущество — копируются в кучу.

</details>

## 10. 🔴 Что выведет код?

```csharp
Console.WriteLine(double.NaN == double.NaN);
Console.WriteLine(double.NaN.Equals(double.NaN));
```

- A) `True` / `True`
- B) `False` / `True`
- C) `False` / `False`
- D) `True` / `False`

<details><summary>Ответ</summary>

**B.** Оператор `==` следует IEEE 754 (`NaN` не равно ничему, даже себе), а `Equals` обязан быть рефлексивным, чтобы `NaN` можно было найти в словаре. То же расхождение возникает у записей и структур с полем `double` (проверено).
→ [Экспертная теория](expert.ru.md#nan)

</details>

## 11. 🔴 Найдите ошибку

```csharp
struct Inner { public int N; public void Inc() => N++; }
class Holder { public readonly Inner I = new(); }

var h = new Holder();
h.I.Inc(); h.I.Inc();
Console.WriteLine(h.I.N);
```

<details><summary>Ответ</summary>

Выведется `0`: для `readonly`-поля со структурой компилятор вызывает метод у **защитной копии**, поэтому изменения теряются (проверено: `N == 0`). Исправление: сделать структуру `readonly struct` с неизменяемым состоянием (и метод возвращает новое значение), либо убрать `readonly` у поля.
→ [Экспертная теория](expert.ru.md#вызов-метода-структуры-через-readonly-поле)

</details>
