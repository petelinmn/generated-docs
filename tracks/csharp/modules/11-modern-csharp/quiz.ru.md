# Квиз: Современный C#

## 1. 🟢 Что вернёт `Classify(7)`?

```csharp
static string Classify(int n) => n switch
{
    < 0 => "negative",
    0 => "zero",
    >= 1 and < 10 => "digit",
    _ => "big",
};
```

- A) `"negative"`
- B) `"digit"`
- C) `"big"`
- D) исключение `SwitchExpressionException`

<details><summary>Ответ</summary>

**B.** Ветви проверяются сверху вниз; `7` не меньше нуля, не равно нулю и подходит под `>= 1 and < 10`. Ветвь `_` — запасная и срабатывает, только если ничего выше не подошло, поэтому C неверно. D было бы без `_` для значения, не попавшего ни в одну ветвь.
→ [Базовая теория](basics.ru.md#выражение-switch)

</details>

## 2. 🟢 Какое выражение корректно проверяет «`o` — положительное целое» и даёт переменную `n`?

- A) `if (o is int n && n > 0)`
- B) `if (o is int n || n > 0)`
- C) `if (o as int n)`
- D) `if (o == int n)`

<details><summary>Ответ</summary>

**A.** Образец типа `is int n` объявляет переменную, которая определённо присвоена только в ветви, где совпадение произошло, поэтому условие `n > 0` дописывается через `&&`. В B переменная `n` не определена, если первая часть ложна — ошибка компиляции. C и D — не существующий синтаксис.
→ [Базовая теория](basics.ru.md#сопоставление-с-образцом)

</details>

## 3. 🟢 Чем параметр первичного конструктора отличается от свойства?

- A) ничем: компилятор всегда делает из него публичное свойство
- B) это параметр, доступный в теле типа; если его использует метод, компилятор создаёт скрытое поле, но публичного члена нет (для `record` — есть)
- C) это константа времени компиляции
- D) он доступен только в инициализаторах полей и свойств

<details><summary>Ответ</summary>

**B.** Публичное свойство из параметра создаёт только `record`. Для обычных `class`/`struct` параметр можно использовать в методах — тогда он превращается в скрытое поле (в проверенном примере `Deposit` изменяет `balance`), или явно скопировать в свойство. D неверно: доступ есть и в методах.
→ [Базовая теория](basics.ru.md#первичные-конструкторы)

</details>

## 4. 🟢 Выберите все верные утверждения

- [ ] A) `List<int> l = [1, 2, 3];` — корректный код
- [ ] B) `int[] a = [..b, 0];` вставляет элементы коллекции `b` в массив
- [ ] C) `required`-свойство можно не задавать, если у него есть `init`
- [ ] D) `init`-свойство можно менять в любой момент после создания объекта

<details><summary>Ответ</summary>

**A, B.** A — выражение коллекции с целевым типом `List<int>`. B — spread. C неверно: `required` как раз обязывает задать значение (иначе `CS9035`). D неверно: `init` разрешает присваивание только при создании (иначе `CS8852`; проверено).
→ [Базовая теория](basics.ru.md#required-и-init)

</details>

## 5. 🟢 Что делает `$$"""…"""`?

- A) создаёт строку, где `{{ }}` — интерполяция, а одиночные `{` — обычные символы
- B) создаёт строку, в которой `$` нужно экранировать
- C) создаёт две копии строки
- D) выбрасывает ошибку: такой литерал не существует

<details><summary>Ответ</summary>

**A.** Количество знаков `$` задаёт, сколько фигурных скобок открывают интерполяцию: при `$$` — две. Поэтому в JSON-шаблоне одиночные `{`/`}` не мешают.
→ [Базовая теория](basics.ru.md#сырые-строки-и-параметры-лямбд)

</details>

## 6. 🟡 Что выведет код?

```csharp
int[] arr = [1, 2, 3, 4, 5];
Console.WriteLine(arr is [1, _, 3, ..]);
Console.WriteLine(arr is [_, _]);
if (arr is [var first, .. var mid, var last])
    Console.WriteLine($"{first} {string.Join(",", mid)} {last}");
```

<details><summary>Ответ</summary>

```text
True
False
1 2,3,4 5
```

`[1, _, 3, ..]` — первые три элемента совпали, остальные любые. `[_, _]` требует ровно два элемента. В третьем образце `first` и `last` — крайние элементы, а `mid` — срез из остальных трёх.
→ [Продвинутая теория](advanced.ru.md#списочные-образцы)

</details>

## 7. 🟡 В каком порядке нужно расположить ветви, чтобы код компилировался?

```csharp
string s = n switch
{
    int => "int",
    1 => "one",
};
```

- A) код корректен
- B) частную ветвь `1` нужно поставить выше `int`
- C) нужно заменить `1` на `== 1`
- D) нужно заменить `int` на `_`

<details><summary>Ответ</summary>

**B.** Общий образец выше частного делает частный недостижимым — ошибка `CS8510` (проверено). Поставьте `1 => "one"` перед `int => "int"`. D не помогает: `_` тоже поглотит всё.
→ [Продвинутая теория](advanced.ru.md#вложенные-свойства-и-защитные-условия)

</details>

## 8. 🟡 Выберите все верные утверждения о выражениях коллекций

- [ ] A) `IEnumerable<int> e = [1, 2];` создаёт скрытый тип, приводить его к `List<int>` нельзя
- [ ] B) `[..a, ..b]` вычисляет каждое слагаемое один раз
- [ ] C) пустая `[]` для массива каждый раз создаёт новый массив
- [ ] D) свой тип может поддерживать `[…]` через `[CollectionBuilder]`

<details><summary>Ответ</summary>

**A, B, D.** A: в проверенном запуске создан `<>z__ReadOnlyArray`. B: каждое spread-выражение вычисляется один раз. C неверно: пустой массив — кэшированный `Array.Empty<T>()` (`ReferenceEquals` вернул `True`). D верно.
→ [Продвинутая теория](advanced.ru.md#выражения-коллекций-типы-и-spread)

</details>

## 9. 🟡 Что происходит при `h?.Value = 5`, если `h` равно `null`?

- A) `NullReferenceException`
- B) ничего: присваивание и вычисление правой части пропускаются
- C) создаётся новый объект `h`
- D) ошибка компиляции

<details><summary>Ответ</summary>

**B.** Null-условное присваивание (C# 14) вычисляет правую часть, только если `h` не `null`. В проверенном примере при `null` ничего не произошло, а после создания объекта `Value` стало `7`.
→ [Продвинутая теория](advanced.ru.md#null-условное-присваивание)

</details>

## 10. 🟡 Открытый вопрос: как с помощью `field` добавить в свойство проверку значения и зачем это лучше отдельного поля?

<details><summary>Ключевые пункты хорошего ответа</summary>

- `field` — ссылка на автоматическое поле свойства: `public double Celsius { get; set => field = Math.Max(value, -273.15); }`;
- нет отдельного закрытого поля, которое можно случайно изменить в обход проверки;
- работает с `get`, `set` и `init`; можно оставить один из аксессоров автоматическим;
- если в типе есть собственный член `field`, нужно писать `@field` или `this.field`;
- функция появилась в C# 14.

</details>

## 11. 🔴 Что выведет код?

```csharp
var w = new Weird();   // operator == always returns true
Console.WriteLine($"{w == null}; {w is null}");
```

- A) `True; True`
- B) `True; False`
- C) `False; False`
- D) `False; True`

<details><summary>Ответ</summary>

**B.** `w == null` вызывает перегруженный оператор, а `w is null` — образец, который проверяет ссылку на `null` напрямую и перегрузку игнорирует. Проверено запуском.
→ [Экспертная теория](expert.ru.md#как-компилируются-образцы)

</details>

## 12. 🔴 Найдите ошибку

```csharp
static T Create<T>() where T : new() => new T();

class Req { public required string Name { get; init; } }

var r = Create<Req>();
```

<details><summary>Ответ</summary>

Ошибка компиляции `CS9040`: тип с `required`-членами не соответствует ограничению `new()`, потому что обобщённый код не может задать обязательные свойства. Решения: убрать `required` у типа либо отказаться от `new()` и передавать фабрику `Func<T>`.
→ [Экспертная теория](expert.ru.md#как-компилируются-первичные-конструкторы-и-коллекции)

</details>
