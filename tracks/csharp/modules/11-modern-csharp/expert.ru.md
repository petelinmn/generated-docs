## Union-типы (C# 15)

Union объявляет тип, значение которого — ровно один из перечисленных **типов-вариантов**, и даёт компилятору проверить полноту `switch`:

```csharp
public union Pet(Cat, Dog);
public record Cat(string Name);
public record Dog(string Name);

Pet p = new Cat("Tom");                       // implicit conversion from a case type
string d = p switch { Cat c => $"cat {c.Name}", Dog g => $"dog {g.Name}" };   // exhaustive: no discard needed
Console.WriteLine(d);                         // cat Tom
Console.WriteLine(p.Value?.GetType().Name);   // Cat
```

Проверено на SDK 11.0.100 (без дополнительных флагов). Что выяснено запуском:

- union — **структура** (`IsValueType = True`), помеченная атрибутом `UnionAttribute` и реализующая `IUnion`;
- доступ к содержимому — свойство `Value` типа `object?`; у `default(Pet)` оно `null` — «пустой» union возможен, как и у любой структуры;
- `switch` без ветви `_` по двум вариантам не даёт предупреждения; если убрать один вариант, компилятор сообщает `CS8509` и называет непокрытый случай (`Dog`);
- `p is Dog` работает как обычная проверка типа.

Союзы обобщаются: `public union Result<T>(Ok<T>, Error);` — проверено в [упражнении 6](exercises.ru.md). Это наиболее значимое расширение системы типов за годы: до него варианты моделировали иерархиями с `abstract record` или библиотеками вроде OneOf. Возможность новая, поэтому сверяйтесь со страницей «What's new in C# 15» перед использованием в публичных API.

## Как компилируются образцы

- `switch`-выражение превращается в последовательность проверок или, для плотных целочисленных констант, в `switch` по таблице переходов; компилятор строит дерево решений и **не повторяет** одинаковые проверки между ветвями.
- Недостижимая ветвь — ошибка `CS8510`; неполное покрытие — предупреждение `CS8509`; на runtime оно превращается в `SwitchExpressionException`:

```csharp
static int Half(int x) => x switch { 0 => 0, 2 => 1 };
try { Console.WriteLine(Half(5)); }
catch (Exception e) { Console.WriteLine(e.GetType().Name + ": " + e.Message); }
```

```text
SwitchExpressionException: Non-exhaustive switch expression failed to match its input.
Unmatched value was 5.
```

- Для `enum` значения вне перечисления (`(Color)42`) — тоже «непокрытый» случай, поэтому и при перечислении всех констант `switch` без `_` компилятор выдаёт предупреждение `CS8524` (значение может быть любым `int`; проверено).
- Образцы `is null` и `is not null` **не вызывают** перегруженный `==`. Проверено на типе, у которого `==` всегда возвращает `true`: `w == null` — `True`, а `w is null` — `False`.

## Как компилируются первичные конструкторы и коллекции

- Параметр первичного конструктора, использованный вне инициализаторов, превращается в **скрытое поле** с непроизносимым именем; используйте как состояние осознанно (предупреждение `CS9124` об удвоении).
- `[a, ..b, c]` для массива вычисляет длину и копирует элементы напрямую, для `List<T>` и `Span<T>` — выделяет нужный объём и заполняет без промежуточных коллекций. Для `IEnumerable<T>`/`IReadOnlyList<T>` создаётся скрытый тип (в проверенном запуске — `<>z__ReadOnlyArray`).
- Пустая `[]` для массива — `Array.Empty<T>()` (проверено: `ReferenceEquals` даёт `True`); значит, проверка по ссылке на «пустой» массив ненадёжна.
- Тип без публичного конструктора без аргументов или с обязательными членами не соответствует ограничению `new()`: ошибка `CS9040` (проверено на типе с `required`).

## Подвохи

**1. `is null` против `== null`.** Образцы обходят перегруженный `==` (см. выше): для типов с кастомным равенством результаты расходятся.

**2. Порядок ветвей.** Общий образец выше частного делает частный недостижимым — `CS8510`:

```csharp
string s = n switch { int => "int", 1 => "one" };   // error CS8510: pattern already handled
```

**3. Параметр первичного конструктора не `readonly`.** Его можно присвоить внутри методов (`balance += amount` в [базовой теории](basics.ru.md)), и это меняет состояние объекта. Для неизменяемости копируйте в `readonly`-поле или свойство `{ get; }`.

**4. `required` ломает `new()`.** Обобщённый код с `where T : new()` не принимает типы с обязательными членами (`CS9040`).

**5. `init` не защищает от изменения через рефлексию и от присваивания внутри конструктора.** Это ограничение компиляции, а не времени выполнения.

**6. Один spread — один проход.** `[..Gen(), ..Gen()]` вызывает генератор два раза; результат `IEnumerable<T>` нельзя привести к `List<T>`.

**7. Присваивание `h?.Value = 5` не вычисляет правую часть при `null`.** Побочные эффекты в правой части не произойдут.

**8. `default(Pet)`.** У union-структуры по умолчанию `Value == null`: `switch` только по вариантам бросит `SwitchExpressionException`, а добавленная ветвь `null => "empty"` сработает (проверено).

## Компромиссы и альтернативы

| Задача | Современное решение | Классическая альтернатива |
|---|---|---|
| Варианты «или-или» | union-типы (C# 15) | иерархия `abstract record` + `switch` по типу |
| Разбор по форме данных | образцы | цепочки `if`/`as` |
| Неизменяемая модель | `record` / `required` + `init` | конструктор со всеми параметрами |
| Валидация в свойстве | `field` | явное закрытое поле |
| Конфигурируемый список | `[..]` | `new List<T> { }` |
| Добавить API к чужому типу | `extension` | статический метод расширения |

## Вопросы с собеседований

<details><summary>1. Чем `switch`-выражение отличается от `switch`-оператора?</summary>

Выражение возвращает значение, у каждой ветви есть результат, нет `break` и «проваливания», компилятор проверяет полноту (предупреждение `CS8509`). При отсутствии подходящей ветви на runtime — `SwitchExpressionException`.

</details>

<details><summary>2. Какие виды образцов есть в C#?</summary>

Тип, константа, реляционный, логический (`and`/`or`/`not`), свойств (включая вложенные), позиционный (деконструкция), `var`, discard `_`, списочный, `{ }` (не null).

</details>

<details><summary>3. Чем `x is null` отличается от `x == null`?</summary>

`is null` — образец, он не использует перегруженный оператор `==`; `== null` вызывает перегрузку, если она есть. Для обычных типов результат одинаков, для типов с кастомным равенством — может отличаться.

</details>

<details><summary>4. Что такое списочный образец и что делает `..`?</summary>

Сопоставление с последовательностью по длине и элементам: `[1, _, ..]`. Срез `..` соответствует любому числу элементов, может захватываться (`.. var rest`) и допускается один раз в образце.

</details>

<details><summary>5. Является ли параметр первичного конструктора свойством?</summary>

Нет. Это параметр, доступный во всём теле типа; если его использует метод, компилятор создаёт скрытое поле. В `record` параметры дополнительно становятся публичными свойствами.

</details>

<details><summary>6. Что за предупреждение CS9124?</summary>

Параметр первичного конструктора и захвачен в состояние типа, и использован для инициализации свойства или поля: значение хранится дважды и может разойтись.

</details>

<details><summary>7. Что умеют выражения коллекций?</summary>

Создают массив, `List<T>`, `Span<T>`, `ImmutableArray<T>`, `IEnumerable<T>` и любой тип с `[CollectionBuilder]` по целевому типу; поддерживают spread `..`; в C# 15 — элемент `with(...)` для аргументов конструктора.

</details>

<details><summary>8. Чем `required` отличается от конструктора с параметрами?</summary>

`required` заставляет задать свойство в инициализаторе объекта на стороне вызова, не требуя конструктора. Недостаток — не работает с `new()`-ограничением; конструкторы, которые сами задают все обязательные члены, помечают `[SetsRequiredMembers]`.

</details>

<details><summary>9. Что даёт `init` и чем отличается от `readonly`?</summary>

`init`-свойство задаётся только в инициализаторе объекта, `with`-выражении или конструкторе; после создания объект неизменяем на уровне компилятора. `readonly` относится к полям и задаётся только в конструкторе.

</details>

<details><summary>10. Для чего нужно ключевое слово `field`?</summary>

Обращается к автоматическому полю свойства, позволяя добавить логику в `get`/`set` без объявления своего поля (C# 14).

</details>

<details><summary>11. Что нового в extension members по сравнению с методами расширения?</summary>

Блок `extension` позволяет объявлять расширяющие **свойства**, **статические** члены и операторы, а не только методы. Обычные методы расширения с `this` продолжают работать.

</details>

<details><summary>12. Объясните `h?.Value = 5`.</summary>

Null-условное присваивание (C# 14): если `h` равно `null`, ничего не выполняется и правая часть не вычисляется; иначе присваивание происходит как обычно.

</details>

<details><summary>13. Что такое union-тип C# 15 и чем он лучше иерархии?</summary>

Значение одного из заранее перечисленных типов-вариантов, не требующих общего базового типа. Компилятор проверяет полноту `switch`; варианты могут быть любыми типами (в том числе из чужих библиотек). Под капотом — структура с полем `Value`.

</details>

<details><summary>14. Вопрос с подвохом: что выведет `int[] e = []; Console.WriteLine(ReferenceEquals(e, Array.Empty<int>()));`?</summary>

`True`: пустое выражение коллекции для массива использует кэшированный `Array.Empty<int>()` (проверено). Нельзя опираться на уникальность ссылки на пустой массив.

</details>

<details><summary>15. Вопрос с подвохом: почему `Create<Req>()` с `where T : new()` не компилируется, если `Req` содержит `required`-член?</summary>

Для `new()` компилятор не может гарантировать, что обязательные члены будут заданы: ошибка `CS9040`. Решение — убрать `required` или ограничение `new()` и передавать фабрику `Func<T>`.

</details>

<details><summary>16. Вопрос с подвохом: хватит ли `switch` без `_` по `enum` со всеми перечисленными значениями?</summary>

Компилятор всё равно предупреждает (`CS8524`): значение enum может быть любым числом базового типа (`(Color)42`), и на runtime будет `SwitchExpressionException`. Нужна ветвь `_`.

</details>
