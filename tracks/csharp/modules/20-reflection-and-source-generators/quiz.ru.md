# Квиз: Рефлексия и генераторы кода

## 1. 🟢 Какой код получит имена и типы публичных свойств класса `Person`?

- A) `typeof(Person).GetProperties()`
- B) `Person.Properties`
- C) `nameof(Person)`
- D) `Activator.CreateInstance(typeof(Person))`

<details><summary>Ответ</summary>

**A.** `GetProperties()` возвращает `PropertyInfo` с `Name` и `PropertyType`. `nameof` даёт только имя типа, `Activator` создаёт объект.
→ [Базовая теория](basics.ru.md#информация-о-типе)

</details>

## 2. 🟢 Что получит вызывающий, если метод, вызванный через `MethodInfo.Invoke`, бросил `InvalidOperationException`?

- A) `InvalidOperationException` напрямую
- B) `TargetInvocationException`, а исходная ошибка — в `InnerException`
- C) `null`
- D) ничего: исключение проглатывается

<details><summary>Ответ</summary>

**B.** Рефлексия оборачивает исключение вызванного метода (проверено: `TargetInvocationException -> inner InvalidOperationException`).
→ [Базовая теория](basics.ru.md#создание-объектов-и-вызов-членов)

</details>

## 3. 🟢 Что делает атрибут `[Label("The name")]` сам по себе?

- A) задаёт подпись в UI
- B) ничего: это метаданные, которые должен прочитать другой код (рефлексия или генератор)
- C) переименовывает свойство
- D) проверяет значение

<details><summary>Ответ</summary>

**B.** Атрибут — данные. Читает их код вроде `p.GetCustomAttribute<LabelAttribute>()`.
→ [Базовая теория](basics.ru.md#атрибуты)

</details>

## 4. 🟢 Чем `Expression<Func<int,int>> e = x => x * 2;` отличается от `Func<int,int> f = x => x * 2;`?

- A) ничем
- B) `e` — структура данных (дерево), которую можно изучить и скомпилировать; `f` — готовый делегат
- C) `e` быстрее
- D) `e` нельзя вызвать вообще

<details><summary>Ответ</summary>

**B.** У дерева есть `Body.NodeType`, его можно разобрать и вызвать `Compile()` (проверено: `x => ((x * 2) + 1)`, `Add`, результат `11`).
→ [Базовая теория](basics.ru.md#деревья-выражений)

</details>

## 5. 🟡 Что выделяют эти операции за вызов?

```csharp
_ = person.Name;                    // direct
_ = nameProp.GetValue(person);      // PropertyInfo
_ = greet.Invoke(person, ["x"]);    // MethodInfo
_ = getter(person);                 // a cached delegate
```

- A) 0, 0, 72, 0 байт
- B) 0, 24, 0, 0 байт
- C) 72 байта у всех
- D) у всех 0

<details><summary>Ответ</summary>

**A.** Проверено: `Invoke` выделил 72 байта (массив аргументов и упаковка), а `GetValue` для строки и делегат — 0. Горячие вызовы выносят в кэшированные делегаты.
→ [Продвинутая теория](advanced.ru.md#стоимость-рефлексии-и-ускорение)

</details>

## 6. 🟡 Зачем в примере с `Mapper` вынесен вложенный статический класс `Cache<TFrom, TTo>`?

- A) чтобы скрыть код
- B) у каждой пары типов своё статическое поле: делегат строится один раз и переиспользуется
- C) чтобы обойти ограничения AOT
- D) для потокобезопасности

<details><summary>Ответ</summary>

**B.** Статическое поле обобщённого типа создаётся отдельно для каждой закрытой пары. Скомпилированное копирование дало `0 Б` против `64 Б` у рефлексивного (проверено). В Native AOT `Compile()` недоступен.
→ [Продвинутая теория](advanced.ru.md#компиляция-выражений-для-быстрого-доступа)

</details>

## 7. 🟡 Выберите все верные утверждения о генераторе исходного кода

- [ ] A) работает на этапе компиляции и добавляет новые файлы
- [ ] B) может изменить существующий метод в вашем классе
- [ ] C) целевой класс должен быть `partial`, чтобы его дополнить
- [ ] D) собирается под `netstandard2.0` и подключается как анализатор

<details><summary>Ответ</summary>

**A, C, D.** B неверно: генератор только **добавляет** файлы, существующий код не меняет; поэтому нужен `partial`. Проверено: генератор `[AutoToString]` создал `ToString` для `Person` и `Point`.
→ [Продвинутая теория](advanced.ru.md#генераторы-исходного-кода)

</details>

## 8. 🟡 Почему в генераторе строка `" {{ "` вместо `" { "`?

- A) опечатка
- B) в сгенерированной интерполированной строке одиночные `{` — ошибка: фигурные скобки нужно удваивать
- C) так быстрее
- D) чтобы скрыть вывод

<details><summary>Ответ</summary>

**B.** Сгенерированный код — это `$"Person {{ Name = {Name}, … }}"`. С одиночными скобками компилятор выдал ошибки `CS1073`/`CS1525` в сгенерированном файле (проверено).
→ [Продвинутая теория](advanced.ru.md#генераторы-исходного-кода)

</details>

## 9. 🟡 Открытый вопрос: когда вместо рефлексии лучше source generator?

<details><summary>Ключевые пункты хорошего ответа</summary>

- когда набор типов известен при компиляции, а нужны сериализация, логирование, регулярные выражения, мапперы, регистрация;
- нет затрат на рефлексию при выполнении, код проверяется компилятором и читается в сгенерированных файлах;
- обязателен для Native AOT и обрезки (рефлексия и `Expression.Compile` там ограничены);
- когда нужны плагины или типы, неизвестные заранее (загрузка сборок), остаётся рефлексия.

</details>

## 10. 🔴 Что вернёт `typeof(int?)` и `boxed.GetType()` для `int? n = 5; object boxed = n;`?

- A) оба `Nullable<int>`
- B) `Nullable<int>` и `Int32`
- C) оба `Int32`
- D) `Int32` и `Nullable<int>`

<details><summary>Ответ</summary>

**B.** При упаковке `Nullable<int>` со значением упаковывается само значение, поэтому `GetType()` даёт `Int32` (проверено). Для исходного типа — `Nullable.GetUnderlyingType`.
→ [Экспертная теория](expert.ru.md#метаданные-и-объект-type)

</details>

## 11. 🔴 Приложение работает в Debug, а после `PublishTrimmed` падает: тип, найденный по строке, не существует. Почему и как исправить?

- A) баг в Windows
- B) обрезка удалила код, видимый только по строковым именам; нужны аннотации (`DynamicallyAccessedMembers`) или генератор вместо рефлексии
- C) `PublishTrimmed` отключает JIT
- D) нужно перезагрузить компьютер

<details><summary>Ответ</summary>

**B.** Обрезка анализирует статические вызовы; обращение по строке она не видит. Помечайте код аннотациями (`IL2026`/`IL3050` предупреждают) или переходите на генераторы (`JsonSerializerContext`, `[GeneratedRegex]`).
→ [Экспертная теория](expert.ru.md#trimming-и-native-aot)

</details>
