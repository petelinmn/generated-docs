# Span и Memory: экспертная теория

🌐 **Русский** · [English](expert.en.md)

**Уровни:** [обзор](overview.ru.md) · [1. Базовая](basics.ru.md) · [2. Продвинутая](advanced.ru.md) · **3. Экспертная** · [4. Квиз](quiz.ru.md)

**Пререквизиты:** [базовая](basics.ru.md) и [продвинутая](advanced.ru.md) теория. **Время:** ~1,5 ч.

## Устройство Span

`Span<T>` — структура из двух полей: **управляемая ссылка** (`ref T`) на первый элемент и длина (`int`). Проверено: `Unsafe.SizeOf<Span<int>>()` и `Unsafe.SizeOf<ReadOnlySpan<char>>()` — по 16 байт (8 + 4 + выравнивание). Поэтому `Span` дёшево передавать по значению.

Ссылка внутри `Span<T>` — **внутренний указатель** (interior pointer): он может указывать не только на начало массива, но и на элемент в середине объекта, поле класса или стековую память. Сборщик мусора умеет отслеживать такие ссылки и обновляет их при перемещении объектов в куче, а объект, на который указывает `Span`, остаётся живым. Проверено: `MemoryMarshal.CreateSpan(ref box.X, 1)` даёт `Span<int>` на поле объекта, запись в него меняет `box.X`.

`Memory<T>` — обычная структура: ссылка на объект-владелец (массив, `string` или `MemoryManager<T>`), смещение и длина (тоже 16 байт). Обычная ссылка и смещение допускают хранение в куче, но чтобы прочитать элементы, `Memory<T>` каждый раз превращают в `Span<T>`.

### Почему Span обязан быть ref struct

Внутренний указатель не может храниться в куче: GC не умеет трекать такие ссылки из объектов кучи, а структура со ссылкой на стековую память пережила бы свой кадр. Отсюда ограничения `ref struct`:

| Нельзя | Ошибка (проверено) |
|---|---|
| быть полем класса / обычной структуры | `CS8345` |
| попасть в замыкание | `CS8175` |
| упаковка в `object` | `CS0029` |
| жить через `await`/`yield` | `CS4007` |
| аргумент обобщения без `allows ref struct` | `CS9244` |
| вернуть `Span` на `stackalloc`-память из метода | `CS8352` |
| вызвать `Equals(object)` | не компилируется (`CS1503`): используйте `SequenceEqual` |

Что смягчено в новых версиях C#:

- **`scoped`** (C# 11) — параметр или локальная переменная не «убегает» из метода: `static int Sum(scoped Span<int> s)` принимает даже `stackalloc` без анализа времени жизни (проверено: `Sum(stackalloc int[] {1, 2, 3})` = 6);
- **`allows ref struct`** (C# 13) — обобщение допускает `ref struct`: `static void Print<T>(T t) where T : IHasN, allows ref struct`; ref struct при этом может реализовывать интерфейсы (проверено на `ref struct Counter : IHasN`);
- в **итераторах** и `async`-методах `Span` можно использовать, если он не пересекает `await`/`yield`: ошибка `CS4007` возникает именно при пересечении.

`readonly ref struct` гарантирует неизменяемость полей: компилятор не создаёт защитных копий при передаче `in`. `Span<T>` и `ReadOnlySpan<T>` объявлены так.

## Равенство и `ToString`

- Оператор `==` у `Span<T>` сравнивает **ссылку и длину**, а не содержимое: два `Span` на один массив равны, на разные массивы с одинаковыми данными — нет (проверено: `True` и `False`). Для сравнения содержимого — `SequenceEqual`.
- `ToString()` у `Span<char>`/`ReadOnlySpan<char>` возвращает строку с содержимым (`"abc"`), у остальных — описание типа: `System.Span<Int32>[3]` (проверено).
- Пустой `default` и `Span<T>.Empty` равны; `Span<int> s = (int[]?)null` даёт пустой span (проверено).

## Как JIT работает со Span

Доступ `span[i]` содержит проверку границ. JIT устраняет её там, где может доказать корректность индекса (например, в цикле `for (int i = 0; i < span.Length; i++)`), поэтому цикл по `Span` сравним с циклом по массиву. Методы вроде `IndexOf`, `SequenceEqual`, `Contains` и `SearchValues` используют SIMD-инструкции (`Vector128/256/512`) — выигрыш на длинных данных. Конкретные цифры зависят от процессора и версии — измеряйте BenchmarkDotNet (модуль «19 · Производительность» ещё не создан).

`stackalloc` по умолчанию обнуляет память; атрибут `[SkipLocalsInit]` и опция компилятора отключают обнуление ради скорости — тогда нельзя читать то, что вы не записали.

## Память без копирования: что ещё есть

| Тип / API | Назначение |
|---|---|
| `ReadOnlySequence<T>` | последовательность из нескольких сегментов; `Slice`, `PositionOf`, `GetPosition` |
| `MemoryPool<T>`, `IMemoryOwner<T>` | пул с владельцем (проверено: `Rent(10).Memory.Length >= 10`) |
| `MemoryManager<T>` | базовый класс для собственных владельцев памяти (нативная, закреплённая) |
| `Memory<T>.Pin()` | закрепить память для передачи в нативный код |
| `MemoryMarshal.Cast`, `CreateSpan`, `GetReference` | низкоуровневое приведение и доступ по ссылке |
| `Unsafe` | `As`, `Add`, `SizeOf`, `ReadUnaligned` — без проверок |
| `string.Create` | создать строку, заполнив её буфер через `Span<char>` — одно выделение |
| `Convert.ToHexStringLower` (.NET 9+) | готовая замена ручной шестнадцатеричной строки (проверено: `000fff`) |

## Подвохи

**1. `Span` над `List<T>` устаревает.** После `Add` с перевыделением старый `Span` пишет в брошенный массив (проверено в [продвинутой теории](advanced.ru.md#listt-и-collectionsmarshal)).

**2. Ковариантность массивов.** Создание `Span<object>` над `string[]` бросает `ArrayTypeMismatchException`: `Span<T>` не допускает ковариации массивов, чтобы запись не нарушила типобезопасность. Для чтения достаточно `ReadOnlySpan<object>` — он создаётся без ошибки (проверено).

**3. `Rent` возвращает массив большей длины.** Работайте с запрошенной длиной через `AsSpan(0, n)`, а не с `rented.Length`.

**4. `Span` и `async`.** Любая локальная переменная `Span` в `async`-методе, которая используется после `await`, — ошибка `CS4007`. В главной программе с top-level statements это проявляется неожиданно: `Span`, объявленный до `await`, не может использоваться после него.

**5. `stackalloc` в цикле.** Каждая итерация добавляет память на стек, и она освободится только при выходе из метода. Выделяйте буфер до цикла.

**6. `MemoryMarshal.Cast` и выравнивание.** Приведение `Span<byte>` к `Span<int>` требует, чтобы длина делилась на размер типа (лишние байты отбрасываются), и зависит от порядка байтов платформы.

**7. Микрооптимизация без измерений.** Проверено только одно: `AsSpan` не выделяет память, а `Substring` выделяет; выигрыш по времени надо мерить.

## Компромиссы и альтернативы

| Подход | Плюсы | Минусы |
|---|---|---|
| `Substring`/`Split`/копирование | просто, безопасно | выделения, нагрузка на GC |
| `ReadOnlySpan<char>` и срезы | нет выделений | ограничения `ref struct`, нельзя в `async`/поля |
| `Memory<T>` | хранится в полях, работает с `async` | нужен `.Span` для доступа |
| `ArrayPool<T>` | переиспользование больших буферов | надо вернуть, возможны утечки/гонки |
| `System.IO.Pipelines` | сеть, разбор потоков, управление буфером | сложнее `Stream`, подходит не всем |
| `unsafe`-указатели | максимум контроля | нет проверок безопасности |

## Вопросы с собеседований

<details><summary>1. Что такое `Span<T>` и какую проблему он решает?</summary>

Представление на непрерывный участок памяти (массив, строка, стек, нативная память) без копирования. Позволяет делать срезы и разбор без выделений в куче.

</details>

<details><summary>2. Почему `Span<T>` — `ref struct`?</summary>

Он содержит внутренний управляемый указатель, который не может жить в куче: так он мог бы пережить стековую память, на которую указывает. Поэтому он существует только на стеке — отсюда запрет на поля класса, замыкания, упаковку и `await`.

</details>

<details><summary>3. Чем `Memory<T>` отличается от `Span<T>`?</summary>

`Memory<T>` — обычная структура: можно хранить в поле, использовать в `async` и коллекциях; доступ к данным — через `.Span`. `Span<T>` быстрее и безопаснее на стеке, но с ограничениями.

</details>

<details><summary>4. Почему нельзя использовать `Span<T>` после `await`?</summary>

Метод превращается в конечный автомат, а локальные переменные, пережившие `await`, хранятся в его полях (в куче). `ref struct` в куче хранить нельзя — ошибка `CS4007`.

</details>

<details><summary>5. Что делает `stackalloc` и чем опасен?</summary>

Выделяет память на стеке вызовов (без GC, до выхода из метода). Опасности: переполнение стека при больших размерах (фатально для процесса) и накопление в циклах. Размер нужно ограничивать и переходить на массив.

</details>

<details><summary>6. Как разобрать строку без `Substring`/`Split`?</summary>

Через `ReadOnlySpan<char>`: `IndexOf` + срезы, `int.Parse(ReadOnlySpan<char>)`, `MemoryExtensions.Split` (диапазоны), `EnumerateLines()`.

</details>

<details><summary>7. Что делает `==` для `Span<T>`?</summary>

Сравнивает ссылку на начало и длину, а не содержимое. Для содержимого — `SequenceEqual`.

</details>

<details><summary>8. Что такое `ArrayPool<T>` и какие у него подводные камни?</summary>

Пул переиспользуемых массивов: `Rent`/`Return`. Возвращаемый массив может быть длиннее запрошенного и не обнуляется; нельзя использовать массив после `Return` и возвращать дважды; возврат нужно делать в `finally`.

</details>

<details><summary>9. Чем опасен `CollectionsMarshal.AsSpan(list)`?</summary>

Он отдаёт внутренний массив списка. Если список перевыделит массив (`Add` сверх ёмкости), `Span` продолжит указывать на старый массив, и записи в него потеряются (проверено).

</details>

<details><summary>10. Что такое `System.IO.Pipelines` и в чём смысл `AdvanceTo(consumed, examined)`?</summary>

`Pipe` соединяет производителя и потребителя через общий управляемый буфер. `consumed` — что обработано и может быть освобождено, `examined` — что просмотрено; непотреблённые данные остаются в буфере, и потребитель получит их вместе с новыми. Так обрабатываются сообщения, разорванные между блоками.

</details>

<details><summary>11. Что даёт `scoped` и `allows ref struct`?</summary>

`scoped` сообщает компилятору, что ссылка не покидает метод (можно передавать `stackalloc`-данные). `allows ref struct` разрешает использовать `ref struct` как аргумент обобщения.

</details>

<details><summary>12. Вопрос с подвохом: что произойдёт при `Span<object> s = new string[1];`?</summary>

`ArrayTypeMismatchException`: `Span<T>` не допускает ковариацию массивов (проверено). С `ReadOnlySpan<object>` то же присваивание допустимо.

</details>

<details><summary>13. Вопрос с подвохом: что вернёт `ToString()` у `Span<int>` с элементами `1, 2, 3`?</summary>

Не числа: `ToString()` возвращает описание типа `System.Span<Int32>[3]`, и только для `Span<char>`/`ReadOnlySpan<char>` — содержимое-строку (проверено).

</details>

<details><summary>14. Вопрос с подвохом: всегда ли `Span` быстрее массива?</summary>

Нет. Цикл по `Span` сравним с циклом по массиву: выигрыш даёт отсутствие копирования и выделений. Если копирование не узкое место, заметной разницы не будет; решение принимают по замеру.

</details>
