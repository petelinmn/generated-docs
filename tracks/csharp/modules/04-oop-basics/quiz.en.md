# Quiz: OOP: classes and objects

## 1. 🟢 What is the default access of a class field and of a top-level class without a modifier?

- A) `public` and `public`
- B) `private` and `internal`
- C) `private` and `private`
- D) `internal` and `public`

<details><summary>Answer</summary>

**B.** A class member without a modifier is `private`, a top-level type is `internal` (verified via reflection). The encapsulation principle: expose only what is needed from outside.
→ [Basics](basics.en.md#access-modifiers)

</details>

## 2. 🟢 What does the code print?

```csharp
public class Animal { public virtual string Speak() => "..."; }
public class Dog : Animal { public override string Speak() => "Woof"; }

Animal animal = new Dog();
Console.WriteLine(animal.Speak());
```

- A) `...`
- B) `Woof`
- C) a compile error
- D) `Dog`

<details><summary>Answer</summary>

**B.** For `virtual`/`override` the call is decided by the **actual type** of the object (`Dog`), not the variable type (`Animal`). This is polymorphism.
→ [Basics](basics.en.md#polymorphism)

</details>

## 3. 🟢 What does comparing two different class objects give, without overriding `Equals`, if all their fields are equal?

- A) `true`: the contents are compared
- B) `false`: references are compared by default
- C) an exception
- D) depends on the number of fields

<details><summary>Answer</summary>

**B.** `Equals` from `System.Object` compares references; for value equality, override `Equals`/`GetHashCode` (or use a record, see [05](../05-interfaces-structs-records/overview.en.md)). Verified by running.
→ [Basics](basics.en.md#inheritance)

</details>

## 4. 🟢 Select all correct statements

- [ ] A) a class can inherit from two base classes
- [ ] B) an `init` property is set in a constructor or an object initializer
- [ ] C) `required` forces the caller to set the property
- [ ] D) if you declare your own constructor, the parameterless one is still generated by the compiler

<details><summary>Answer</summary>

**B, C.** A is wrong: a class has one base class (several interfaces are fine). D is wrong: once you declare your own constructor, the default one is not generated.
→ [Basics](basics.en.md#constructors)

## 5. 🟡 In what order does the code run on `new Derived()`?

```csharp
class Base    { int f = Trace.Add("base field");    public Base()    { Trace.Add("base ctor"); } }
class Derived : Base { int g = Trace.Add("derived field"); public Derived() { Trace.Add("derived ctor"); } }
```

- A) `base field | base ctor | derived field | derived ctor`
- B) `derived field | base field | base ctor | derived ctor`
- C) `derived field | derived ctor | base field | base ctor`
- D) `base ctor | base field | derived ctor | derived field`

<details><summary>Answer</summary>

**B.** First the derived class's field initializers, then the base's, the base constructor body, the derived constructor body (verified by running). This is a C# peculiarity: Java and C++ order it differently.
→ [Advanced theory](advanced.en.md#object-initialization-order)

</details>

## 6. 🟡 What does the code print?

```csharp
class Animal { public virtual string Speak() => "..."; public string Name() => "Animal"; }
class Dog : Animal { public override string Speak() => "Woof"; public new string Name() => "Dog"; }

Animal a = new Dog();
Console.WriteLine($"{a.Speak()} {a.Name()} {((Dog)a).Name()}");
```

<details><summary>Answer</summary>

```text
Woof Animal Dog
```

`override` decides by the actual type, while `new` only **hides** the member: a call through an `Animal` variable picks the base `Name`. The cast to `Dog` gives the derived version.
→ [Advanced theory](advanced.en.md#virtual-override-and-new)

</details>

## 7. 🟡 What is called?

```csharp
class PrinterBase { public void Print(int x) => Console.WriteLine("int in base"); }
class Printer : PrinterBase { public void Print(double x) => Console.WriteLine("double in derived"); }

new Printer().Print(5);
```

- A) `int in base`
- B) `double in derived`
- C) an ambiguity error
- D) both methods

<details><summary>Answer</summary>

**B.** If the derived class has an applicable method (`5` converts implicitly to `double`), base-class methods are not considered in overload resolution. Do not mix overloads across hierarchies.
→ [Advanced theory](advanced.en.md#overloading-and-derived-class-methods)

</details>

## 8. 🟡 Select all correct statements

- [ ] A) a `static class` is both `abstract` and `sealed` in metadata
- [ ] B) `sealed override` forbids further overriding of a method
- [ ] C) an instance of an `abstract` class can be created with `new`
- [ ] D) a `const` value is substituted into the calling assembly's code at compile time

<details><summary>Answer</summary>

**A, B, D.** C is wrong: an abstract class cannot be instantiated. D: that is why consumers must be rebuilt after a constant changes in a library (unlike `static readonly`).
→ [Advanced theory](advanced.en.md#abstract-classes-and-sealing)

</details>

## 9. 🟡 Open question: when is composition better than inheritance?

<details><summary>Key points of a good answer</summary>

- inheritance only for an "is-a" relationship, when a subclass can replace the base without surprises;
- composition (a field of another type) gives flexibility: behavior changes by substituting an object, with no rigid tie to the base implementation;
- implementation inheritance exposes details of the base class (the fragile base class problem), and C# has only one base class;
- for a shared contract use interfaces, for code reuse — composition.

</details>

## 10. 🔴 What will `Seen` hold in this code, and what changes if `string name;` is replaced with `string name = "set";`?

```csharp
class A { public A() { Hook(); } protected virtual void Hook() { } }
class C : A
{
    string name;
    public string Seen = "-";
    public C() { name = "set"; }
    protected override void Hook() { Seen = name is null ? "null" : name; }
}
```

<details><summary>Answer</summary>

`new C().Seen` is `"null"`: the virtual method is called from the base constructor, when the assignment in the body of `C`'s constructor has not run yet. With the initializer `string name = "set";` the result becomes `"set"`, because the derived class's field initializers run before the base constructor (verified). Conclusion: do not call virtual methods from constructors.
→ [Expert theory](expert.en.md#a-virtual-method-in-a-constructor)

</details>
