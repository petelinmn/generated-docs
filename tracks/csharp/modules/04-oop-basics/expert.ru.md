# ООП: классы и объекты: экспертная теория

🌐 **Русский** · [English](expert.en.md)

**Уровни:** [обзор](overview.ru.md) · [1. Базовая](basics.ru.md) · [2. Продвинутая](advanced.ru.md) · **3. Экспертная** · [4. Квиз](quiz.ru.md)

## Под капотом

### Объект в памяти

Экземпляр класса — объект в управляемой куче ([12 · Память и GC](../12-memory-and-gc/basics.ru.md)). Перед полями лежит служебная часть: заголовок объекта и указатель на описание типа (в CoreCLR оно называется `MethodTable`). По указателю runtime узнаёт фактический тип объекта и находит реализации виртуальных методов. Поэтому самый маленький объект занимает 24 байта на 64-битной платформе (проверено: `new object()` выделил 24 байта), а `GetType()` и приведения типов работают по этому указателю.

### Как компилятор вызывает методы

Для вызова метода экземпляра класса по ссылке C# обычно генерирует инструкцию IL `callvirt`, **даже если метод не виртуальный**: так получатель проверяется на `null`. Когда компилятор знает, что получатель не `null`, для невиртуального метода он генерирует `call`: `this.M()` и `new T().M()`. `base.M()` тоже использует `call`, как и статические методы. Проверено чтением IL: `t.NonVirtual()` и `t.Virt()` через параметр компилируются в `callvirt`, а `Target.St()`, `new Target().Plain()` и вызов своего метода без получателя — в `call`.

Для виртуального метода runtime при выполнении `callvirt` смотрит в таблицу методов фактического типа и вызывает самую производную реализацию. Отсюда следует всё поведение полиморфизма: `override` подменяет запись в таблице, а `new` — нет.

### Что компилятор делает с `override` и `new`

В метаданных метод `Dog.Speak` помечен как виртуальный и **не** `newslot` — то есть занимает слот базового метода. Метод `Dog.Name` с `new` — невиртуальный, отдельный метод с тем же именем. Проверено через рефлексию: `Speak: virtual=True, newslot=False`, `Name: virtual=False`. Вызов через переменную `Animal` для `Name()` компилируется в вызов `Animal.Name`, поэтому и получается «Animal».

### Что скрывают свойства и новые возможности

- Автосвойство превращается в **пару методов `get_X`/`set_X` и закрытое поле** `<X>k__BackingField` (проверено, в том числе для свойства с ключевым словом `field`).
- Сеттер `init` — это обычный метод с особым **модификатором типа возврата** `IsExternalInit`. Именно этот модификатор запрещает вызывать сеттер вне инициализации объекта; обычный код без компилятора, например рефлексия, его обходит (проверено: через `PropertyInfo.SetValue` значение `init`-свойства изменилось с 30 на 31).
- `required` помечает свойство атрибутом `RequiredMemberAttribute`, а конструкторы типа — атрибутами `CompilerFeatureRequiredAttribute` и `ObsoleteAttribute`: старые компиляторы, не знающие о `required`, отказываются вызывать такие конструкторы. Это проверено через рефлексию.
- Параметр **первичного конструктора** становится скрытым полем `<start>P`, только если используется в членах (проверено: единственные члены класса — конструктор, метод `Next` и скрытое поле).

## Справочник

### Члены типа

| Член | Что это | Заметки |
|---|---|---|
| Поле | переменная в типе | `readonly`, `const`, `static`, `volatile` |
| Метод | именованный блок кода | `virtual`, `abstract`, `override`, `sealed`, `static`, `async`, `extern`, `partial` |
| Свойство | пара методов доступа | `get`, `set`, `init`; `required`; `field` |
| Индексатор | свойство с параметрами | называется `this[...]` |
| Событие | подписка на уведомления | см. [09 · Делегаты, события, лямбды](../09-delegates-events-lambdas/overview.ru.md) |
| Конструктор | инициализация экземпляра | первичный, цепочка `this(...)`/`base(...)` |
| Статический конструктор | инициализация типа | один раз, без параметров и модификаторов доступа |
| Финализатор | `~T()` | см. [12 · Память и GC](../12-memory-and-gc/advanced.ru.md#финализаторы) |
| Оператор | перегрузка `+`, `==`, … | `public static` |
| Вложенный тип | тип внутри типа | по умолчанию `private` |

### Модификаторы доступа

| | Тот же тип | Наследник в сборке | Другая сборка, наследник | Сборка | Другая сборка |
|---|---|---|---|---|---|
| `private` | ✅ | ❌ | ❌ | ❌ | ❌ |
| `private protected` | ✅ | ✅ | ❌ | ❌ | ❌ |
| `protected` | ✅ | ✅ | ✅ | ❌ | ❌ |
| `internal` | ✅ | ✅ | ❌ | ✅ | ❌ |
| `protected internal` | ✅ | ✅ | ✅ | ✅ | ❌ |
| `public` | ✅ | ✅ | ✅ | ✅ | ✅ |

Ещё есть `file` — тип виден только в одном файле исходного кода (для сгенерированного кода). По умолчанию: члены типа — `private`, типы верхнего уровня — `internal`, члены интерфейса — `public`. Через рефлексию проверено, что `protected internal` соответствует «семейство **или** сборка», а `private protected` — «семейство **и** сборка».

### Модификаторы классов и членов

| Модификатор | Применение | Значение |
|---|---|---|
| `abstract` | класс, член | нельзя создать / нет реализации |
| `sealed` | класс, override | запрещает наследование / переопределение |
| `static` | класс, член | принадлежит типу; статический класс — `abstract sealed` в метаданных |
| `partial` | тип, метод, свойство и индексатор (C# 13), конструктор и событие (C# 14) | определение в нескольких частях |
| `virtual` / `override` / `new` | член | заменяемый / заменяющий / скрывающий |
| `readonly` | поле | меняется только в конструкторе |
| `required` | свойство, поле | значение обязательно при инициализации |
| `unsafe`, `extern`, `volatile` | редко | небезопасный код, внешняя реализация, барьеры памяти |

### Методы System.Object

| Метод | По умолчанию | Когда переопределять |
|---|---|---|
| `ToString()` | имя типа (`Plain`) | для читаемого вывода и отладки |
| `Equals(object)` | сравнение ссылок | для равенства по значению |
| `GetHashCode()` | основан на идентичности объекта (у двух разных объектов в проверке — разный) | всегда вместе с `Equals` |
| `GetType()` | точный тип во время выполнения | не переопределяется |
| `MemberwiseClone()` | поверхностная копия (protected) | для клонирования |
| `Finalize()` | пусто | через синтаксис `~T()` |
| `Equals(a, b)`, `ReferenceEquals(a, b)` (статические) | первый учитывает `null` и вызывает `a.Equals(b)`; второй сравнивает ссылки | не переопределяются |

## Другие возможности классов

```csharp
Animal animal = new Cat();
Console.WriteLine(animal.Create().GetType().Name);   // Cat
Console.WriteLine(new Cat().Create().Name);          // cat — the static type is already Cat

var (x, y) = new Point(1, 2);                        // calls Deconstruct
double degrees = new Celsius(100);                   // implicit conversion
var back = (Celsius)36.6;                            // explicit conversion

var tag = new Tag("a");                              // no initializer needed
var id = Id.Create(5);                               // new Id(5) does not compile
Console.WriteLine(new Loud().Say());                 // HI!

class Animal { public virtual Animal Create() => new Animal(); }
class Cat : Animal
{
    public string Name => "cat";
    public override Cat Create() => new Cat();       // covariant return (C# 9)
}

class Point(int x, int y)
{
    public void Deconstruct(out int px, out int py) { px = x; py = y; }
}

class Celsius(double degrees)
{
    public double Degrees => degrees;
    public static implicit operator double(Celsius c) => c.Degrees;
    public static explicit operator Celsius(double d) => new(d);
}

class Tag
{
    public required string Name { get; init; }
    public Tag() { }
    [System.Diagnostics.CodeAnalysis.SetsRequiredMembers]
    public Tag(string name) => Name = name;
}

class Id
{
    public int Value { get; }
    private Id(int value) => Value = value;          // only the class itself can create
    public static Id Create(int value) => new(value);
}

class Quiet { public virtual string Say() => "hi"; }
class Loud : Quiet { public override string Say() => base.Say().ToUpper() + "!"; }
```

| Возможность | Правило |
|---|---|
| Ковариантный возврат | `override`-метод или свойство только для чтения может возвращать более производный тип |
| `base.M()` | вызывает реализацию базы, минуя переопределение |
| `Deconstruct` | параметры `out` дают запись `var (x, y) = obj` |
| `implicit` / `explicit operator` | пользовательские преобразования; `explicit` — если возможна потеря информации |
| `SetsRequiredMembers` | конструктор обещает задать все `required`-члены; компилятор это обещание не проверяет |
| Закрытый конструктор | создание только через фабричные методы |
| Первичный и другие конструкторы | каждый другой явный конструктор обязан вызывать `this(...)` |

## Подвохи

Каждый подвох проверен запуском.

### Виртуальный метод в конструкторе

Результат сложнее, чем кажется: инициализаторы полей наследника **уже** выполнены к моменту конструктора базы, а присваивания в теле конструктора наследника — ещё нет.

```csharp
class A { public A() { Hook(); } protected virtual void Hook() { } }
class C : A
{
    string name;
    public string Seen = "-";
    public C() { name = "set"; }
    protected override void Hook() { Seen = name is null ? "null" : name; }
}
// new C().Seen → "null"
```

Если заменить `string name;` на `string name = "set";`, результат станет `set`. Метод наследника выполняется на недостроенном объекте.

### new скрывает, а не заменяет

`Animal a = new Dog();` — `a.Name()` вернёт `Animal`, `((Dog)a).Name()` — `Dog`. Один и тот же объект, два ответа, в зависимости от типа переменной.

### Метод наследника затеняет перегрузки базы

`new Printer().Print(5)` вызвал `Print(double)` из наследника, хотя в базовом классе есть `Print(int)`. Подходящий метод наследника исключает методы базы из рассмотрения.

### Метод экземпляра сильнее метода расширения

`new Greeter().Hello()` вернул `instance`, хотя определён и `Hello` как расширение. Расширение вызывается, только если подходящего метода экземпляра нет.

### Доступ к protected через базовую ссылку

В классе `D : B` код `other.v`, где `other` имеет тип `B`, не компилируется: ошибка CS1540. Через ссылку **своего** типа (`D other`) — компилируется. Защищённый член доступен наследнику только через экземпляры наследника.

### Приведение к неверному типу

`(int)(object)"text"` бросает `InvalidCastException`, а `o as int?` для строки возвращает `null` без исключения.

### Порядок статических инициализаторов

В типе со статическим конструктором инициализаторы статических полей выполняются **до** тела статического конструктора (журнал: `field init, static ctor`), даже если конструктор в тексте написан раньше. Повторные обращения к типу их не запускают.

### const и ссылки между сборками

Значение `const` подставляется в код вызывающей сборки при компиляции, поэтому после изменения константы в библиотеке потребители остаются со старым значением, пока их не пересоберут. В метаданных константа — `static` и `literal` (проверено).

### required не защищает от рефлексии

`required` проверяет компилятор. При создании через `Activator.CreateInstance` обязательность не проверяется (проверено: `Name` остался `null`), а `init`-свойство меняется рефлексией (проверено: 30 → 31).

## Компромиссы и альтернативы

| Задача | Вариант | Цена |
|---|---|---|
| Повторное использование кода | наследование | жёсткая связь с базой, хрупкий базовый класс |
| | композиция | чуть больше кода делегирования |
| Общий контракт | интерфейс | нет состояния и конструкторов |
| | абстрактный класс | один базовый класс, зато общее состояние |
| Неизменяемые данные | `init` и `readonly` | копирование при изменении; для значений есть `record` ([05](../05-interfaces-structs-records/overview.ru.md)) |
| Расширение чужого типа | метод расширения | не виртуальный, не имеет доступа к закрытым членам |
| Запрет наследования | `sealed` | наследникам придётся использовать композицию |

## Вопросы с собеседований

**1. Чем класс отличается от объекта?**

<details><summary>Ответ</summary>

Класс — описание типа: поля, методы, свойства. Объект (экземпляр) — конкретная область памяти в куче, созданная по этому описанию через `new`. У класса может быть много объектов, у каждого своё состояние; статические члены принадлежат классу и общие для всех объектов.

</details>

**2. Назови три принципа ООП и приведи пример каждого в C#.**

<details><summary>Ответ</summary>

Инкапсуляция — закрытое поле `_balance` и метод `Deposit`, который проверяет аргумент. Наследование — `Dog : Animal`. Полиморфизм — переменная типа `Animal` вызывает `Speak()`, и выполняется реализация `Dog`. Иногда добавляют четвёртый — абстракцию (абстрактный класс `Shape`, который задаёт контракт, скрывая детали).

</details>

**3. Чем отличаются `override` и `new`?**

<details><summary>Ответ</summary>

`override` заменяет виртуальный метод: вызов через базовую переменную выполнит реализацию наследника. `new` скрывает невиртуальный (или виртуальный) член: вызов через переменную базового типа выполнит базовую реализацию. Проверено: `a.Speak()` → `Woof`, `a.Name()` → `Animal`.

</details>

**4. В каком порядке выполняются инициализаторы и конструкторы при `new Derived()`?**

<details><summary>Ответ</summary>

Инициализаторы полей наследника → инициализаторы полей базы → конструктор базы → конструктор наследника. Это отличие C# от Java и C++, где инициализаторы наследника идут после конструктора базы.

</details>

**5. Что случится, если вызвать виртуальный метод из конструктора базового класса?**

<details><summary>Ответ</summary>

Выполнится переопределённая версия наследника, хотя тело конструктора наследника ещё не выполнялось: поля, которые присваиваются в теле, будут `null` или `0` (проверено: `Seen == "null"`). Инициализаторы полей уже отработали. Поэтому виртуальные вызовы в конструкторах — источник трудных ошибок.

</details>

**6. Какие модификаторы доступа есть в C#? Чем `protected internal` отличается от `private protected`?**

<details><summary>Ответ</summary>

`public`, `private`, `protected`, `internal`, `protected internal`, `private protected` (и `file`). `protected internal` — «в сборке **или** в наследниках», `private protected` — «в наследниках **внутри своей сборки**» (пересечение условий). По умолчанию члены `private`, типы верхнего уровня — `internal`.

</details>

**7. Что такое автосвойство и во что оно превращается?**

<details><summary>Ответ</summary>

Свойство без тела аксессоров: `public int X { get; set; }`. Компилятор создаёт закрытое поле `<X>k__BackingField` и методы `get_X`, `set_X`. Преимущество перед публичным полем — можно позже добавить логику, не меняя двоичный контракт и код вызова; кроме того, свойства работают с привязкой данных и интерфейсами.

</details>

**8. Чем `init` отличается от `private set` и от `readonly`-поля?**

<details><summary>Ответ</summary>

`init` позволяет задать значение при создании (в конструкторе или инициализаторе объекта) и снаружи, но потом оно неизменно. `private set` меняется из любого метода внутри класса, но не снаружи. `readonly` поле меняется только в конструкторе или инициализаторе. Технически `init` защищён модификатором `IsExternalInit`, который проверяет компилятор: рефлексия его обходит (проверено).

</details>

**9. Что делает `required`?**

<details><summary>Ответ</summary>

Заставляет вызывающую сторону задать свойство или поле при создании через инициализатор объекта или конструктор с атрибутом `SetsRequiredMembers`; иначе ошибка компиляции. Это проверка компилятора: метаданные получают `RequiredMemberAttribute`, а конструкторы — защитные атрибуты для старых компиляторов.

</details>

**10. Что такое первичный конструктор класса? Создаёт ли он свойства?**

<details><summary>Ответ</summary>

Параметры в заголовке класса (`class Counter(int start)`), доступные во всём классе. В отличие от `record`, для обычного класса свойства **не создаются**: параметр — просто захваченная переменная; если он используется в членах, компилятор создаёт скрытое поле. Явные свойства нужно объявлять самому.

</details>

**11. Чем абстрактный класс отличается от интерфейса?**

<details><summary>Ответ</summary>

Абстрактный класс может содержать поля, конструкторы, реализованные члены с любым доступом, но от него можно унаследоваться только один раз. Интерфейс задаёт контракт (с C# 8 — ещё и реализации по умолчанию), класс реализует сколько угодно интерфейсов. Подробнее — в [05 · Интерфейсы, структуры, записи](../05-interfaces-structs-records/overview.ru.md).

</details>

**12. Зачем нужен `sealed`?**

<details><summary>Ответ</summary>

Запрещает наследовать от класса или переопределять метод дальше. Применяют, когда класс не рассчитан на наследование: его поведение проще гарантировать. По умолчанию классы C# **не** запечатаны.

</details>

**13. Подвох: метод экземпляра и метод расширения с одинаковой сигнатурой. Какой вызовется?**

<details><summary>Ответ</summary>

Метод экземпляра. Расширение вызывается, только если подходящего метода экземпляра нет (проверено: `instance`). Поэтому расширением нельзя «подменить» чужой метод, и добавление метода в класс может незаметно изменить, что вызывает чужой код.

</details>

**14. Подвох: в базе `Print(int)`, в наследнике `Print(double)`. Какой метод вызовет `derived.Print(5)`?**

<details><summary>Ответ</summary>

`Print(double)` из наследника. Правило перегрузки: если в наследнике есть подходящий метод, методы базового класса не рассматриваются (проверено).

</details>

**15. Когда выполняется статический конструктор?**

<details><summary>Ответ</summary>

Один раз для типа, до создания первого экземпляра или первого обращения к статическому члену. Порядок: сначала инициализаторы статических полей, затем тело конструктора (проверено). Без параметров, без модификатора доступа.

</details>

**16. Чем `const` отличается от `static readonly`?**

<details><summary>Ответ</summary>

`const` — константа времени компиляции, её значение подставляется в код (в метаданных поле `static literal`); возможна только для чисел, `bool`, `char`, перечислений, строк и `null` для ссылочных типов. `static readonly` вычисляется при выполнении, может иметь любой тип, и значение не «вшивается» в чужие сборки. Для значений, которые могут измениться, нужен `static readonly`.

</details>

**17. Зачем компилятор использует `callvirt` для невиртуальных методов?**

<details><summary>Ответ</summary>

Чтобы получить проверку на `null`: вызов метода на `null`-ссылке должен бросить `NullReferenceException`. Используется он не для всех вызовов: когда получатель не может быть `null` (`this.M()`, `new T().M()`), невиртуальный метод вызывается через `call`, как и `base.M()` и статические методы (проверено чтением IL).

</details>

**18. Что делает `partial` и зачем?**

<details><summary>Ответ</summary>

Позволяет описать класс (или метод) в нескольких частях и файлах; компилятор их объединяет. Нужно для сгенерированного кода: часть генерирует инструмент, часть пишет разработчик; изменения во второй не затираются при перегенерации первой.

</details>

## Шпаргалка

| Нужно | Решение |
|---|---|
| Скрыть состояние | `private` поле + свойство |
| Неизменяемое после создания | `{ get; init; }`, `readonly` |
| Обязательное значение | `required` |
| Заменить поведение | `virtual` + `override` |
| Запретить наследование | `sealed` |
| Общая заготовка | `abstract class` |
| Цепочка конструкторов | `: this(...)`, `: base(...)` |
| Логика в автосвойстве | `field` (C# 14) |
| Добавить метод чужому типу | метод расширения (метод экземпляра сильнее) |
| Константа, которая может поменяться | `static readonly` |
