# Квиз: ASP.NET Core: Minimal API

> Сначала ответь сам, потом раскрывай ответ. Отметка показывает, из какого уровня вопрос: 🟢 [базовая теория](basics.ru.md) · 🟡 [продвинутая](advanced.ru.md) · 🔴 [экспертная](expert.ru.md).

## 1. 🟢 Что вернёт `GET /items/abc` для маршрута `app.MapGet("/items/{id:int}", …)`?

- A) `400`
- B) `404`
- C) `500`
- D) `200` с `id = 0`

<details><summary>Ответ</summary>

**B.** Ограничение `:int` не пропускает значение `abc`, и маршрут просто не находится (проверено). `400` приходит, когда маршрут найден, но значение параметра запроса не приводится к типу.
→ [Базовая теория](basics.ru.md#маршрутизация)

</details>

## 2. 🟢 Откуда будет взят параметр `page`?

```csharp
app.MapGet("/search", (string? q, int page = 1) => $"q={q ?? "-"} page={page}");
```

- A) из тела запроса
- B) из строки запроса: `/search?q=x&page=3`
- C) из заголовка
- D) из DI

<details><summary>Ответ</summary>

**B.** Простой тип, которого нет в шаблоне маршрута, берётся из строки запроса; `/search?q=x&page=3` → `q=x page=3`, без параметров — `q=- page=1` (проверено).
→ [Базовая теория](basics.ru.md#привязка-параметров)

</details>

## 3. 🟢 Что будет при `GET /search?page=abc`?

- A) `page = 0`
- B) `400`
- C) `404`
- D) `500`

<details><summary>Ответ</summary>

**B.** Значение не приводится к `int` → `400 Bad Request` (проверено).
→ [Базовая теория](basics.ru.md#привязка-параметров)

</details>

## 4. 🟢 Что делает `TypedResults.Created("/todos/1", todo)`?

- A) ответ `200` с телом
- B) ответ `201` с заголовком `Location` и телом
- C) перенаправление `302`
- D) ответ `204`

<details><summary>Ответ</summary>

**B.** `Created` — `201` с адресом нового ресурса в `Location` и телом (проверено: `201 {"id":1,"title":"write docs"}`).
→ [Базовая теория](basics.ru.md#тело-запроса-и-json)

</details>

## 5. 🟡 Зачем нужен `Results<Ok<Todo>, NotFound>` вместо `IResult`?

- A) без него код не компилируется
- B) компилятор проверяет, что возвращаются только перечисленные варианты, а OpenAPI получает точные коды и схемы
- C) он ускоряет сериализацию
- D) он включает кэширование

<details><summary>Ответ</summary>

**B.** Объединение типов описывает контракт ответа: в проверенном OpenAPI-документе для маршрута есть `200` со схемой `Todo` и `404`.
→ [Продвинутая теория](advanced.ru.md#typedresults-и-описание-ответов)

</details>

## 6. 🟡 Что вернёт `POST /todos` с телом `{"title":""}`, если включены `AddValidation()` и `AddProblemDetails()`, а `CreateTodo` помечен `[Required, MinLength(1)]`?

- A) `201`
- B) `400` в формате `application/problem+json` с описанием ошибки поля `Title`
- C) `500`
- D) `422`

<details><summary>Ответ</summary>

**B.** Проверено: `400`, тело `{"title":"One or more validation errors occurred.","status":400,"errors":{"Title":["The Title field is required."]},…}`. Валидация атрибутами в Minimal API — с .NET 10.
→ [Продвинутая теория](advanced.ru.md#валидация-и-problemdetails)

</details>

## 7. 🟡 Что произойдёт с исключением внутри обработчика при `UseExceptionHandler()` и `AddProblemDetails()`?

- A) процесс завершится
- B) клиент получит `500` в формате ProblemDetails без текста исключения
- C) клиент получит трассировку стека
- D) запрос зависнет

<details><summary>Ответ</summary>

**B.** Проверено: `500`, тело не содержит «secret details», только общий заголовок и `traceId`. Подробности — в логе.
→ [Продвинутая теория](advanced.ru.md#обработка-ошибок)

</details>

## 8. 🟡 Выберите все верные утверждения о фильтрах конечных точек

- [ ] A) фильтр видит типизированные аргументы обработчика
- [ ] B) фильтр может вернуть собственный результат вместо вызова обработчика
- [ ] C) фильтр выполняется для запросов, которые не нашли маршрут
- [ ] D) фильтр можно добавить на группу маршрутов

<details><summary>Ответ</summary>

**A, B, D.** C неверно: фильтр срабатывает только после выбора конечной точки; для `404`/`405` нужны middleware. Проверено: `?v=bad` → `400 "filtered out"` без вызова обработчика.
→ [Продвинутая теория](advanced.ru.md#фильтры-конечных-точек)

</details>

## 9. 🟡 Открытый вопрос: как организовать код Minimal API, когда конечных точек становится много?

<details><summary>Ключевые пункты хорошего ответа</summary>

- группы `MapGroup("/todos")` с общим префиксом, тегами, фильтрами и политиками;
- методы расширения `MapTodoEndpoints(this IEndpointRouteBuilder)` в отдельных файлах, вызываемые из `Program.cs`;
- логика — в сервисах, зарегистрированных в DI, обработчики остаются тонкими;
- единый формат ошибок (ProblemDetails) и валидация на границе;
- DTO вместо возврата сущностей БД.

</details>

## 10. 🔴 Почему `POST` с `Content-Type: text/plain` на точку, принимающую JSON, возвращает `415`, а не `400`?

- A) `415` и `400` — одно и то же
- B) точка принимает только `application/json`: тип содержимого не поддерживается, а `400` — для некорректных данных
- C) из-за ошибки сервера
- D) только в Development

<details><summary>Ответ</summary>

**B.** `415 Unsupported Media Type` — несовпадение `Content-Type`; `400` — битый JSON или отсутствующее тело (проверено: `text/plain` → `415`, `{oops` → `400`). С `MapFallback` запрос с неподходящим типом уйдёт в запасной обработчик.
→ [Экспертная теория](expert.ru.md#правила-привязки-и-коды-ответов)

</details>

## 11. 🔴 Что случится, если дважды объявить `app.MapGet("/a", …)`?

- A) ошибка при `Build()`
- B) ошибка при старте
- C) приложение запустится, а запрос к `/a` вернёт `500`
- D) сработает последний обработчик

<details><summary>Ответ</summary>

**C.** Неоднозначное совпадение обнаруживается при сопоставлении запроса, а не при старте (проверено). Поэтому дубликаты маршрутов ловят тестами интеграционного уровня ([17](../17-testing-integration/overview.ru.md)).
→ [Экспертная теория](expert.ru.md#подвохи)

</details>
