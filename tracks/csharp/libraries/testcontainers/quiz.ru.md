# Квиз: Testcontainers

🌐 **Русский** · [English](quiz.en.md)

> Сначала ответьте, потом открывайте ответ. Метка: 🟢 [основы](basics.ru.md) · 🟡 [продвинутый](advanced.ru.md) · 🔴 [эксперт](expert.ru.md). Ответы выведены из материала, в котором Docker недоступен: проверенными считаются только пункты, помеченные в тексте как проверенные.

## 1. 🟢 Для чего нужен Testcontainers?

- A) для запуска production-контейнеров
- B) чтобы поднимать одноразовые Docker-контейнеры с реальными зависимостями из теста
- C) для замены Docker
- D) для сборки образов

<details><summary>Ответ</summary>

**B.** БД, Redis, брокеры — настоящие, удаляются после теста.
→ [Основы](basics.ru.md#что-это-и-зачем)

</details>

## 2. 🟢 Откуда брать строку подключения?

- A) зашить `localhost:5432`
- B) `container.GetConnectionString()` — порт хоста случаен
- C) из `appsettings.json`
- D) из переменной `PATH`

<details><summary>Ответ</summary>

**B.** Порт хоста назначается при старте.
→ [Основы](basics.ru.md#модуль-postgresql)

</details>

## 3. 🟢 Что будет при вызове `Build()` без Docker?

- A) вернётся пустой контейнер
- B) `DockerUnavailableException`
- C) тест будет пропущен автоматически
- D) запустится Podman

<details><summary>Ответ</summary>

**B.** Проверено запуском.
→ [Основы](basics.ru.md#что-будет-без-docker)

</details>

## 4. 🟢 Почему не стоит использовать тег `latest`?

- A) не существует
- B) ломает воспроизводимость: версия образа меняется
- C) медленнее
- D) нельзя в CI

<details><summary>Ответ</summary>

**B.** Фиксируйте версию (`postgres:16-alpine`).
→ [Основы](basics.ru.md#частые-ошибки-новичка)

</details>

## 5. 🟡 Как не поднимать контейнер на каждый тест?

- A) вызвать `GC.Collect`
- B) фикстура класса/набора (`IAsyncLifetime`) и очистка данных между тестами
- C) использовать `static` без освобождения
- D) нельзя

<details><summary>Ответ</summary>

**B.** Запуск — секунды; один контейнер на набор.
→ [Продвинутый](advanced.ru.md#время-жизни-контейнера)

</details>

## 6. 🟡 Как поступить в CI/локально без Docker?

- A) игнорировать падения
- B) условно пропускать интеграционные тесты
- C) удалить тесты
- D) использовать `latest`

<details><summary>Ответ</summary>

**B.** По правилам репозитория интеграционные тесты явно помечаются и пропускаются при недоступной среде.
→ [Продвинутый](advanced.ru.md#пропуск-тестов-без-docker)

</details>

## 7. 🟡 Выберите все верные утверждения

- [ ] A) стратегия ожидания определяет готовность контейнера
- [ ] B) порты хоста лучше зашить
- [ ] C) данные между тестами нужно изолировать
- [ ] D) `latest` рекомендуется для воспроизводимости

<details><summary>Ответ</summary>

**A, C.** B и D неверны.
→ [Продвинутый](advanced.ru.md#best-practices)

</details>

## 8. 🟡 Открытый вопрос: как вы организуете интеграционные тесты API с PostgreSQL?

<details><summary>Ключевые пункты хорошего ответа</summary>

- фикстура с контейнером PostgreSQL на набор тестов, фиксированная версия образа;
- `WebApplicationFactory` с подменой строки подключения;
- миграции на старте, очистка данных между тестами;
- условный пропуск без Docker, кэш образов в CI.

</details>

## 9. 🔴 Зачем нужен контейнер-«сторож» (Ryuk)?

- A) для логирования
- B) удалять оставшиеся контейнеры, если тестовый процесс аварийно завершился
- C) для сети
- D) для кэша образов

<details><summary>Ответ</summary>

**B.** По документации Testcontainers (в этой среде не воспроизводилось).
→ [Эксперт](expert.ru.md#внутреннее-устройство)

</details>

## 10. 🔴 Контейнер запущен, но первое подключение падает. Причина?

- A) неверный образ
- B) процесс внутри ещё не готов принимать соединения — нужна стратегия ожидания
- C) нет `Dispose`
- D) мало потоков

<details><summary>Ответ</summary>

**B.** «Запущен» ≠ «готов».
→ [Эксперт](expert.ru.md#грани-и-подвохи)

</details>
