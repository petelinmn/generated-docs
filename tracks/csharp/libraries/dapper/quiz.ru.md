# Квиз: Dapper

🌐 **Русский** · [English](quiz.en.md)

> Сначала ответьте, потом открывайте ответ. Метка: 🟢 [основы](basics.ru.md) · 🟡 [продвинутый](advanced.ru.md) · 🔴 [эксперт](expert.ru.md).

## 1. 🟢 Что такое Dapper?

- A) полноценный ORM с трекингом
- B) микро-ORM: методы расширения над `IDbConnection`, SQL пишется вручную
- C) генератор SQL из LINQ
- D) драйвер БД

<details><summary>Ответ</summary>

**B.** Dapper подставляет параметры и маппит строки в объекты; нет трекинга и миграций.
→ [Основы](basics.ru.md#что-это-и-зачем)

</details>

## 2. 🟢 Что вернёт `Execute` на INSERT массива из 3 объектов?

- A) `0`
- B) `3`
- C) `1`
- D) идентификаторы

<details><summary>Ответ</summary>

**B.** Проверено: `rows inserted: 3`.
→ [Основы](basics.ru.md#запросы-и-команды)

</details>

## 3. 🟢 Что вернёт `QueryFirstOrDefault` при отсутствии строки?

- A) исключение
- B) `null`
- C) пустой объект
- D) `0`

<details><summary>Ответ</summary>

**B.** Проверено; `QuerySingle` же бросает `InvalidOperationException`.
→ [Основы](basics.ru.md#запросы-и-команды)

</details>

## 4. 🟢 Как безопасно подставить пользовательский ввод в запрос?

- A) конкатенацией
- B) параметром (`@n` + `new { n = … }`)
- C) через `string.Format`
- D) экранированием кавычек вручную

<details><summary>Ответ</summary>

**B.** Проверено: параметр — 0 строк на `x' OR '1'='1`, конкатенация — все 3.
→ [Основы](basics.ru.md#параметры-защита-от-sql-инъекций)

</details>

## 5. 🟡 Почему `created_at` не попал в `CreatedAt`?

- A) баг
- B) Dapper сопоставляет по имени; нужна настройка (`MatchNamesWithUnderscores`) или алиас
- C) нужен `Include`
- D) тип `string` не поддерживается

<details><summary>Ответ</summary>

**B.** Проверено: без настройки `null`.
→ [Продвинутый](advanced.ru.md#сопоставление-имён)

</details>

## 6. 🟡 Включили `MatchNamesWithUnderscores` после первого запроса — результат для уже использованного типа?

- A) заработает
- B) останется `null`: настройка действует на ещё не сопоставленные типы
- C) исключение
- D) заработает после перезапуска БД

<details><summary>Ответ</summary>

**B.** Проверено; для нового типа значение подхватилось.
→ [Продвинутый](advanced.ru.md#сопоставление-имён)

</details>

## 7. 🟡 Выберите все верные утверждения

- [ ] A) транзакцию нужно передавать в каждый вызов через `transaction:`
- [ ] B) `splitOn` указывает, где начинается второй объект при multi-mapping
- [ ] C) Dapper сам отслеживает изменения объектов
- [ ] D) `IN @ids` принимает коллекцию

<details><summary>Ответ</summary>

**A, B, D.** C неверно: трекинга нет.
→ [Продвинутый](advanced.ru.md#транзакции)

</details>

## 8. 🟡 Открытый вопрос: загрузите заказы с пользователем одним запросом. Что учесть?

<details><summary>Ключевые пункты хорошего ответа</summary>

- `Query<Order, User, Order>` с `splitOn`;
- для «один ко многим» — группировка по родителю;
- явный список столбцов; параметры;
- индексы по связанным столбцам.

</details>

## 9. 🔴 Почему Dapper быстр?

- A) использует кэш в Redis
- B) генерирует и кэширует код разбора `IDataReader` (IL-эмит), без слоёв трекинга
- C) не обращается к БД
- D) использует рефлексию на каждый вызов

<details><summary>Ответ</summary>

**B.** Десериализатор кэшируется по идентичности запроса.
→ [Эксперт](expert.ru.md#внутреннее-устройство)

</details>

## 10. 🔴 Родитель повторяется в результате multi-mapping. Что делать?

- A) `Distinct()` по всему объекту
- B) сгруппировать по ключу родителя и собрать детей
- C) убрать `splitOn`
- D) использовать `QuerySingle`

<details><summary>Ответ</summary>

**B.** JOIN даёт строку на ребёнка.
→ [Эксперт](expert.ru.md#грани-и-подвохи)

</details>
