# Загрузка файлов: масштаб и грани

🌐 **Русский** · [English](expert.en.md)

**Уровни:** [обзор](overview.ru.md) · [1. Минимум](basics.ru.md) · [2. Production](advanced.ru.md) · **3. Масштаб и грани** · [4. Квиз](quiz.ru.md)

**Пререквизиты:** [минимум](basics.ru.md) и [production](advanced.ru.md). **Время:** ~30 мин.

## Масштаб

- **Локальный диск не масштабируется.** За балансировщиком несколько экземпляров: файл, загруженный на один, не виден другим. Нужно общее хранилище: объектное (S3/Blob), сетевой том.
- **Подписанные ссылки.** Клиент грузит/скачивает напрямую в объектное хранилище по короткоживущему URL, ваш API не пропускает байты через себя и не становится узким местом.
- **Возобновляемая загрузка.** Для гигабайтных файлов — загрузка частями (chunks) с повтором недостающих; протоколы вроде tus, multipart upload в S3.
- **Асинхронная постобработка.** После загрузки (сканирование, превью, перекодирование) задание уходит в очередь ([Фоновые задачи](../background-jobs/overview.ru.md)).
- **Дедупликация и хэши.** Хэш содержимого (SHA-256) как ключ — одинаковые файлы хранятся один раз.
- **Очистка.** Незавершённые загрузки и «осиротевшие» файлы удаляют фоновой задачей.

> ⚠️ Проверить: tus, S3 multipart upload и подписанные ссылки в этом материале не запускались; сверьтесь с документацией выбранного хранилища.

## Грани и подвохи

**1. Лимиты на нескольких уровнях.** Проверено: Kestrel (`MaxRequestBodySize`) вернул `413` на 2 МБ при лимите 1 МБ. Но у формы есть собственные лимиты (`FormOptions`), а перед приложением — лимиты прокси/балансировщика (например, в nginx свой `client_max_body_size`). Сработает самый строгий.

**2. Имя файла — это ввод.** `../../evil.txt` превратилось в `evil.txt` только благодаря `Path.GetFileName` (проверено). `Path.Combine` с абсолютным вторым аргументом отбрасывает первый — ещё один путь к traversal, если брать путь от клиента целиком.

**3. `Content-Type` и расширение — не доказательство.** Проверено: `x.png` с произвольными байтами прошла проверку расширения; только проверка сигнатуры её отклонила.

**4. `IFormFile` буферизует.** Большие формы попадают на диск/в память; для гигабайтов — `MultipartReader` и потоковая запись ([production](advanced.ru.md#потоковая-многочастная-загрузка)).

**5. Antiforgery.** Без токена форма вернёт `400` (проверено); бездумное `DisableAntiforgery()` для cookie-аутентификации открывает CSRF.

**6. Range-запросы.** `enableRangeProcessing: true` даёт `206` и `Content-Range` (проверено); без него клиент не сможет докачивать файл. Для потоков без длины range не работает.

**7. Отмена клиента.** При обрыве `HttpContext.RequestAborted` отменяется; недописанный файл нужно удалить, иначе остаются обломки.

**8. Гонка имён.** Серверный GUID исключает коллизии; имя от клиента — перезапись чужих файлов.

**9. Исполняемое содержимое.** Загруженный HTML/SVG, отданный как `text/html` с вашего домена, — XSS. Отдавайте как `attachment` или с домена без cookie.

## Компромиссы и альтернативы

| Подход | Плюсы | Минусы |
|---|---|---|
| `IFormFile` | просто | буферизация, лимиты формы |
| Потоковый `Request.Body` | минимум памяти | нет multipart-метаданных |
| `MultipartReader` | поток + метаданные | больше кода |
| Прямая загрузка в объектное хранилище | масштаб, нет нагрузки на API | подписанные ссылки, колбэки |
| Возобновляемая загрузка (tus) | надёжно для больших файлов | сложнее клиент и сервер |

## Вопросы с собеседований

<details><summary>1. Как принять файл в Minimal API?</summary>

Параметр `IFormFile` (или `IFormFileCollection`) из `multipart/form-data`; для API-эндпоинтов — `DisableAntiforgery()` либо токен.

</details>

<details><summary>2. Почему нельзя использовать имя файла от клиента как путь?</summary>

Path traversal: `../../…` позволяет писать за пределы каталога. Нужно генерировать имя на сервере; `Path.GetFileName` отбрасывает каталоговую часть (проверено).

</details>

<details><summary>3. Как ограничить размер загрузки?</summary>

`Kestrel.Limits.MaxRequestBodySize`, лимиты формы (`FormOptions`) и атрибуты/метаданные эндпоинта; на практике — ещё и лимиты прокси. Проверено: `413` при превышении.

</details>

<details><summary>4. Чем потоковая загрузка лучше `IFormFile`?</summary>

Не буферизует всё в памяти/временном файле; память не зависит от размера файла.

</details>

<details><summary>5. Как проверить настоящий тип файла?</summary>

Белый список расширений + сигнатура (магические байты) + при необходимости разбор/сканирование; `Content-Type` клиента недостоверен (проверено на фальшивом PNG).

</details>

<details><summary>6. Зачем нужен `enableRangeProcessing`?</summary>

Для `Range`-запросов: докачка, перемотка видео; ответ `206 Partial Content` с `Content-Range` (проверено).

</details>

<details><summary>7. Зачем antiforgery для загрузки файлов?</summary>

Для cookie-аутентификации форма уязвима к CSRF; без токена запрос получает `400` (проверено). Для API с токеном в заголовке CSRF неактуален.

</details>

<details><summary>8. Как масштабировать хранение файлов?</summary>

Объектное хранилище вместо локального диска, подписанные ссылки для прямой загрузки/скачивания, метаданные в БД, фоновая постобработка.

</details>

<details><summary>9. Подвох: файл `x.png` с расширением из белого списка — безопасен?</summary>

Нет: расширение не доказывает содержимое (проверено: произвольные байты пропустила проверка расширения). Нужна проверка сигнатуры и безопасная отдача.

</details>

<details><summary>10. Подвох: загрузка работает локально, а за балансировщиком «теряет» файлы. Почему?</summary>

Файл лежит на диске одного экземпляра, а следующий запрос попадает на другой. Нужно общее хранилище.

</details>
