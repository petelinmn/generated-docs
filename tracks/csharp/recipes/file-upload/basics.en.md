**Levels:** [overview](overview.en.md) · **1. Minimal** · [2. Production](advanced.en.md) · [3. Scale and edges](expert.en.md) · [4. Quiz](quiz.en.md)

**Prerequisites:** [10 · async/await](../../modules/10-async-await/overview.en.md), [14 · ASP.NET Core: Minimal API](../../modules/14-aspnet-core-minimal-api/overview.en.md). **Time:** ~30 min.

## The task

Accept a file from a client, save it to disk and serve it back. It is both a convenient and a dangerous feature: the client controls the name, size and content of the file. The recipe shows a basic solution; security is in [production](advanced.en.md).

## Upload with `IFormFile`

```csharp
app.MapPost("/upload", async (IFormFile file) =>
{
    var safe = Path.GetFileName(file.FileName);           // strips any directory part
    var id = Guid.NewGuid().ToString("N") + Path.GetExtension(safe);
    await using var fs = File.Create(Path.Combine(root, id));
    await file.CopyToAsync(fs);
    return Results.Ok(new { id, original = safe, size = file.Length, file.ContentType });
}).DisableAntiforgery();
```

An `IFormFile` parameter is bound from `multipart/form-data`. Verified: a file with the content `hello world` and the client name `../../evil.txt` → response `200`, `original = "evil.txt"` (the directory part was dropped by `Path.GetFileName`), `size = 11`; on disk a file with a **server** name (GUID + extension) lies, nothing was created outside the directory. A request without a `file` part → `400`.

The on-disk name is generated by the server — the client's original name is stored only as metadata.

> `DisableAntiforgery()` is needed for API endpoints that are not called from your site's HTML forms. For browser forms keep antiforgery on ([production](advanced.en.md#antiforgery)).

## Streaming upload

For large files do not read the whole form: write the request body straight to disk:

```csharp
app.MapPut("/stream/{name}", async (string name, HttpRequest req) =>
{
    var path = Path.Combine(root, Path.GetFileName(name));
    await using var fs = File.Create(path);
    await req.Body.CopyToAsync(fs);
    return Results.Ok(new { saved = fs.Length });
});
```

Verified: 500,000 bytes → `200`, `saved = 500000`. The body is read as a stream and is never entirely in memory.

## The size limit

Kestrel limits the request body by default (about 30 MB); set the value in configuration:

```csharp
builder.WebHost.ConfigureKestrel(k => k.Limits.MaxRequestBodySize = 1024 * 1024);   // 1 MB
```

Verified: with a 1 MB limit, uploading 2,000,000 bytes → `413 Payload Too Large`.

## Download

```csharp
app.MapGet("/download/{name}", (string name) =>
{
    var path = Path.Combine(root, Path.GetFileName(name));
    return File.Exists(path)
        ? Results.File(path, "application/octet-stream", name, enableRangeProcessing: true)
        : Results.NotFound();
});
```

Verified: response `200`, `Content-Length = 500000`, `Accept-Ranges: bytes`; a `Range: bytes=0-99` request → `206`, length 100, `Content-Range: bytes 0-99/500000`; a missing file → `404`. Range requests are needed for resuming downloads and video streaming.

## Beginner mistakes

- ❌ Saving a file under the client's name → ✅ generate the name on the server (path traversal: `../../…`).
- ❌ Reading the whole file into a `byte[]`/`MemoryStream` → ✅ copy as a stream.
- ❌ Trusting `ContentType` and the extension → ✅ check the content ([production](advanced.en.md#checking-the-file-type)).
- ❌ Not limiting the size → ✅ a request limit.
- ❌ Storing files in `wwwroot` → ✅ outside the public directory, serve through an endpoint with permission checks.
