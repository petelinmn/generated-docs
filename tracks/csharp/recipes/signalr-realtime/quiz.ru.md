# Квиз: Real-time через SignalR

🌐 **Русский** · [English](quiz.en.md)

> Сначала ответьте, потом открывайте ответ. Метка показывает уровень вопроса: 🟢 [минимум](basics.ru.md) · 🟡 [production](advanced.ru.md) · 🔴 [масштаб и грани](expert.ru.md).

## 1. 🟢 Что такое хаб в SignalR?

- A) HTTP-контроллер
- B) класс, методы которого вызывают клиенты и через который сервер вызывает методы клиентов
- C) очередь сообщений
- D) база данных

<details><summary>Ответ</summary>

**B.** `Hub` — точка двустороннего общения: `Clients.All/Group(...)` вызывают клиентов, клиенты вызывают публичные методы хаба.
→ [Минимум](basics.ru.md#хаб)

</details>

## 2. 🟢 Кто получил сообщение, когда `ann` вызвала `Send` через `Clients.All`?

- A) только `ann`
- B) только `bob`
- C) все подключённые клиенты (`ann`, `bob`, `cid`)
- D) никто

<details><summary>Ответ</summary>

**C.** Проверено: все трое.
→ [Минимум](basics.ru.md#клиент-net)

</details>

## 3. 🟢 Как отправить сообщение клиентам из эндпоинта, не из хаба?

- A) создать `new ChatHub()`
- B) внедрить `IHubContext<ChatHub>`
- C) через статическое поле
- D) никак

<details><summary>Ответ</summary>

**B.** Проверено: POST-эндпоинт через `IHubContext` доставил уведомление `bob`.
→ [Минимум](basics.ru.md#отправка-не-из-хаба)

</details>

## 4. 🟢 Что верно про экземпляр хаба?

- A) один на всё приложение
- B) создаётся на каждый вызов метода
- C) один на пользователя
- D) один на группу

<details><summary>Ответ</summary>

**B.** Поэтому поля хаба не хранят состояние; используйте сервисы и БД.
→ [Минимум](basics.ru.md#частые-ошибки-новичка)

</details>

## 5. 🟡 Что увидит клиент, если метод хаба бросил `InvalidOperationException("secret")`?

- A) текст `secret`
- B) общее сообщение `An unexpected error occurred invoking '…' on the server.`
- C) ничего
- D) стек вызовов

<details><summary>Ответ</summary>

**B.** Проверено; для видимых ошибок бросайте `HubException` — его сообщение доходит до клиента.
→ [Production](advanced.ru.md#ошибки-хаба)

</details>

## 6. 🟡 Как вернуть данные потоком из хаба?

- A) `List<T>`
- B) `IAsyncEnumerable<T>` и `StreamAsync` на клиенте
- C) только `Clients.All`
- D) нельзя

<details><summary>Ответ</summary>

**B.** Проверено: клиент получил `1,2,3,4,5`.
→ [Production](advanced.ru.md#потоки-с-сервера)

</details>

## 7. 🟡 Выберите все верные утверждения

- [ ] A) один пользователь может иметь несколько соединений
- [ ] B) SignalR выбирает транспорт автоматически (WebSockets → SSE → Long Polling)
- [ ] C) `ConnectionId` сохраняется после переподключения
- [ ] D) `EnableDetailedErrors` рекомендуется в production

<details><summary>Ответ</summary>

**A, B.** C неверно: после переподключения соединение новое (и группы нужно восстанавливать); D неверно: детали ошибок — только для разработки.
→ [Production](advanced.ru.md#переподключение)

</details>

## 8. 🟡 Открытый вопрос: как вы реализуете уведомления конкретному пользователю с несколькими вкладками?

<details><summary>Ключевые пункты хорошего ответа</summary>

- при подключении добавлять соединение в группу `user:<id>` (из аутентифицированного `Context.User`);
- слать из любого места через `IHubContext` в эту группу;
- аутентификация подключения (токен), проверка прав;
- история уведомлений в БД и догрузка после переподключения.

</details>

## 9. 🔴 Локально `Clients.All` доходит до всех, а в продакшне с тремя серверами — только до части. Почему?

- A) баг SignalR
- B) соединения распределены по серверам, а без backplane `All` — только клиенты текущего сервера
- C) ограничение браузера
- D) выключен WebSockets

<details><summary>Ответ</summary>

**B.** Нужен backplane (Redis) или Azure SignalR Service.
→ [Масштаб и грани](expert.ru.md#масштаб)

</details>

## 10. 🔴 Клиент был оффлайн во время рассылки. Получит ли он сообщение после возвращения?

- A) да, SignalR хранит всё
- B) нет: SignalR — не очередь; нужна история в БД и догрузка
- C) да, но только по `ConnectionId`
- D) да, если включён backplane

<details><summary>Ответ</summary>

**B.** Доставка не гарантируется; backplane лишь связывает серверы.
→ [Масштаб и грани](expert.ru.md#грани-и-подвохи)

</details>
