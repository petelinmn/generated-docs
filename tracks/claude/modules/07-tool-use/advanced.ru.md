# Tool use: продвинутый уровень

🌐 **Русский** · [English](advanced.en.md)

**Уровни:** [overview](overview.ru.md) · [1. Основы](basics.ru.md) · **2. Продвинутый** · [3. Эксперт](expert.ru.md) · [4. Квиз](quiz.ru.md)

Опирается на [базовую теорию](basics.ru.md). Код запускался на локальном mock-сервере (см. «Как проверялся код» в основах); страницы о strict tool use, веб-поиске и выполнении кода не читались, поэтому зависящее от них помечено.

## Клиентские и серверные инструменты

| | Клиентский | Серверный |
|---|---|---|
| Кто выполняет код | ваше приложение | серверы Anthropic |
| Блок в ответе | `tool_use` | `server_tool_use` (+ блок результата) |
| Ваша часть | выполнить, вернуть `tool_result` | ничего: результат приходит в том же ответе |
| Примеры | ваши функции, `bash`, `text_editor`, `memory` | веб-поиск, загрузка страниц, выполнение кода, поиск инструментов |
| Ошибки | `is_error: true` в `tool_result` | `is_error` не отправляют; ошибка внутри блока результата |

Инструмент объявляется типизированной записью, например `{"type": "web_search_20260209", "name": "web_search"}`. В одном ответе могут быть оба вида: `stop_reason: "tool_use"` с блоком `server_tool_use` и вашим `tool_use`. Имена типов и версии — в [экспертном справочнике](expert.ru.md#типы-серверных-инструментов).

> ⚠️ Проверить: формы запросов и ответов отдельных серверных инструментов (поиск, загрузка, выполнение кода) в этом материале не читались; даны только имена типов и общие правила со страниц обзора.

### `pause_turn`

Серверные инструменты работают на сервере в цикле. Когда он упирается в лимит итераций, ответ имеет `stop_reason: "pause_turn"`. Отправьте разговор снова, добавив `content` этого ответа без изменений как сообщение `assistant` (по пересказу документации лимит по умолчанию — 10 итераций, и сообщения пользователя после него нет). Если в ответе есть `container`, верните его идентификатор. Вызов **вашего** инструмента всегда заканчивается `tool_use`, никогда не `pause_turn`.

## Принудительный вызов и модели

`any` и `tool` заставляют вызвать инструмент: ответ начинается с `tool_use`, текста перед ним нет.

- С ручным extended thinking (`thinking: {type: "enabled"}`) они дают ошибку: используйте `auto` или `none`.
- С adaptive thinking они разрешены, но принудительный вызов пропускает размышление.
- На Claude Fable 5.2, Mythos 5.2, Opus 5.5, Sonnet 5.5, Fable 5.1 и Mythos 5.1 они дают 400; `none` работает. Альтернативы — `auto` со `strict`-инструментами или [structured outputs](../04-structured-output/advanced.ru.md).

Мок воспроизвёл это для идентификатора Opus 5.5 и пропустил `claude-opus-5`:

```text
claude-opus-5-5 400 Forced tool use is not supported for this model.
claude-opus-5 tool_use
```

Текст 400 выше — формулировка мока, не настоящая. Чтобы получить текст перед вызовом, используйте `auto` и попросите об этом в промпте. Смена `tool_choice` инвалидирует кэшированные блоки сообщений (описания инструментов и системный промпт остаются в кэше).

## Хорошие описания

Модель выбирает инструменты по именам и описаниям, так что это ваш промпт:

- пишите, **что** делает инструмент, **когда** применять и **когда нет**, что он возвращает;
- поясняйте каждый параметр (`description` в схеме), с единицами и форматами;
- имена — различимые и глагольные (`get_weather`, а не `weather2`);
- длинные указания — в описание, а не в десятки мелких инструментов;
- `input_examples` (список примеров входа, которые должны проходить схему) стоят около 100 токенов за плоский пример и около 200 за вложенный; работают на пользовательских инструментах, не на серверных.

Для `strict: true` (гарантированное соответствие схеме имён и входов) документация указывает, что он недопустим для `mcp_toolset` и наборов computer/browser.

> ⚠️ Проверить: полная семантика `strict` (поддерживаемое подмножество схем, лимиты) описана на странице strict tool use, которую здесь не читали.

## Стоимость в токенах

Инструменты добавляют входные токены тремя способами: **описания** (массив `tools`), автоматический **системный промпт** для tool use и блоки `tool_use`/`tool_result` в истории. Документированные накладные расходы системного промпта:

| Модель | `auto`, `none` | `any`, `tool` |
|---|---|---|
| Opus 5.5 | 286 | принудительный вызов не поддерживается |
| Opus 5 | 286 | 406 |
| Sonnet 5.5 | 286 | принудительный вызов не поддерживается |
| Sonnet 5 | 354 | 474 |
| Haiku 5.5 | 286 | 406 |

Без `tools` `tool_choice: none` ничего не добавляет. У серверных инструментов своя оплата по использованию на их страницах.

## Кэширование инструментов

`cache_control` можно поставить на описание инструмента (`{"type": "ephemeral"}`): кэшируется префикс до него включительно; порядок префикса — tools → system → messages ([модуль 05](../05-prompt-caching/advanced.ru.md)). Инструмент с `defer_loading: true` не может иметь `cache_control`. Держите описания стабильными и упорядоченными: любое изменение массива `tools` инвалидирует всё после него.

## Tool runner в SDK

SDK для Python может вести цикл за вас. Функция с docstring становится инструментом через `@beta_tool`; `client.beta.messages.tool_runner` отправляет запросы, выполняет функции и добавляет результаты, пока ответ не станет итоговым:

```python
from anthropic import beta_tool

@beta_tool
def get_weather(location: str) -> str:
    """Get the current weather in a city.

    Args:
        location: City name.
    """
    return f"15 degrees in {location}"

runner = client.beta.messages.tool_runner(model="claude-opus-5-5", max_tokens=1024,
                                          tools=[get_weather],
                                          messages=[{"role": "user", "content": "Weather in Paris?"}])
for msg in runner:
    print("runner", msg.stop_reason)
print(get_weather.to_dict()["input_schema"])
```

```text
runner tool_use
runner end_turn
{'additionalProperties': False, 'properties': {'location': {'description': 'City name.', 'title': 'Location', 'type': 'string'}}, 'required': ['location'], 'type': 'object'}
```

Схема сгенерирована из аннотаций типов и docstring. Ручной цикл даёт контроль (лимиты, логи, подтверждение рискованных вызовов); runner короче для простых случаев.

> В `anthropic` 2.14.0 runner на Claude API и Foundry по умолчанию хранит разговор на сервере (Message Threads, бета, не под ZDR). Чтобы отправлять всю историю самому, передайте `thread=False`. Подробнее — [Anthropic SDK](../../libraries/anthropic-sdk/advanced.ru.md).

## Безопасность

Результаты инструментов — **недоверенные данные**: веб-страница или файл могут содержать текст, похожий на инструкции (непрямая инъекция промпта). Держите их внутри блоков `tool_result` и не переносите в системный промпт. Проверяйте аргументы каждого вызова по правам, ограничивайте, до чего инструмент может дотянуться, и просите человека подтвердить необратимые действия.

## Лучшие практики

- Ограничивайте шаги и суммарные токены цикла; логируйте каждый вызов.
- Возвращайте компактные результаты: модель обращает внимание на всё, что вы присылаете.
- Пишите ошибки, с которыми модель может что-то сделать.
- Держите массив `tools` стабильным между запросами ради кэша.
- Независимые вызовы выполняйте параллельно (`asyncio.gather`, потоки), но возвращайте одним сообщением.
- Проверяйте `input` сами: даже хорошая схема не делает аргумент безопасным.

## Частые ошибки

- ❌ Принудительный вызов на Opus 5.5 / Sonnet 5.5 → ✅ `auto` со `strict`-инструментами или structured outputs.
- ❌ `is_error` для серверных инструментов → ✅ читать ошибку из блока результата.
- ❌ Считать `pause_turn` концом → ✅ отправить ответ снова и продолжить.
- ❌ Копировать вывод инструмента в системный промпт → ✅ держать в `tool_result`.
- ❌ Новый порядок инструментов в каждом запросе → ✅ стабильный массив.
