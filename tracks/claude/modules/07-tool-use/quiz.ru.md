# Квиз: tool use

🌐 **Русский** · [English](quiz.en.md)

> Сначала ответьте сами, потом откройте ответ. Метка показывает уровень вопроса: 🟢 [базовая](basics.ru.md) · 🟡 [продвинутая](advanced.ru.md) · 🔴 [экспертная](expert.ru.md).

## 1. 🟢 Кто выполняет клиентский инструмент?

- A) Claude, внутри модели
- B) Серверы Anthropic
- C) Ваше приложение
- D) SDK, всегда автоматически

<details><summary>Ответ</summary>

**C.** Модель лишь выдаёт блок `tool_use`. (D неверно: SDK выполняет функции, только если вы используете tool runner.)
→ [Базовая теория](basics.ru.md#зачем-это-нужно)

</details>

## 2. 🟢 Что сигнализирует о том, что инструмент нужно выполнить?

- A) `stop_reason: "tool_use"` и блоки `tool_use` в `content`
- B) Слово «tool» в тексте
- C) HTTP 202
- D) `stop_reason: "end_turn"`

<details><summary>Ответ</summary>

**A.** Это структурный сигнал: причина остановки `tool_use` и блоки с именем и аргументами. По словам в тексте и HTTP-коду судить нельзя, а `end_turn` означает, что модель закончила ответ.
→ [Базовая теория](basics.ru.md#цикл-из-четырёх-шагов)

</details>

## 3. 🟢 Что должно быть в сообщении ассистента в следующем запросе?

- A) Только текст ответа
- B) `content` ответа без изменений, включая блоки `tool_use`
- C) Ничего: API помнит
- D) Только блоки `tool_use`

<details><summary>Ответ</summary>

**B.** API не хранит состояние и проверяет соответствие по `id`.
→ [Базовая теория](basics.ru.md#вызов-и-результат)

</details>

## 4. 🟢 Модель сделала два параллельных вызова. Как вернуть результаты?

- A) Два сообщения пользователя по одному результату
- B) Одно сообщение пользователя с двумя блоками `tool_result`
- C) Только первый
- D) Текстом в системный промпт

<details><summary>Ответ</summary>

**B.** По одному `tool_result` на `tool_use`, все вместе.
→ [Базовая теория](basics.ru.md#параллельные-вызовы)

</details>

## 5. 🟡 Инструмент выбросил исключение. Что делать?

- A) Завершить разговор
- B) Ничего не отправлять и продолжить
- C) Отправить `tool_result` с `is_error: true` и понятным сообщением
- D) Повторить исходный запрос

<details><summary>Ответ</summary>

**C.** Вызов без ответа — 400, а от понятной ошибки модель может оправиться.
→ [Базовая теория](basics.ru.md#ошибки-инструментов)

</details>

## 6. 🟡 Что делает `tool_choice: {"type": "none"}`?

- A) Удаляет инструменты из запроса
- B) Запрещает модели вызывать инструменты в этом запросе
- C) Принуждает вызвать инструмент
- D) Отключает параллелизм

<details><summary>Ответ</summary>

**B.** Он доступен на всех моделях.
→ [Базовая теория](basics.ru.md#выбор-инструмента)

</details>

## 7. 🟡 Нужен гарантированный вызов инструмента на Opus 5.5. Как правильно?

- A) `tool_choice: any`
- B) `tool_choice: {"type": "tool", ...}`
- C) `auto` со `strict`-инструментами или structured outputs
- D) `disable_parallel_tool_use`

<details><summary>Ответ</summary>

**C.** По документации `any`/`tool` дают 400 на Opus 5.5 и Sonnet 5.5.
→ [Продвинутая теория](advanced.ru.md#принудительный-вызов-и-модели)

</details>

## 8. 🟡 Выберите все верные утверждения

- [ ] A) `disable_parallel_tool_use` — поле внутри `tool_choice`
- [ ] B) Ошибка серверного инструмента возвращается с `is_error: true`
- [ ] C) `pause_turn` означает повторную отправку ответа как хода ассистента
- [ ] D) Результаты инструментов можно копировать в системный промпт

<details><summary>Ответ</summary>

**A, C.** B неверно: ошибки серверных инструментов внутри блока результата. D неверно: результаты — недоверенные данные.
→ [Эксперт](expert.ru.md#tool_choice)

</details>

## 9. 🟡 Что делает смена `tool_choice` между запросами с кэшем?

- A) Ничего
- B) Инвалидирует кэшированные блоки сообщений (описания и системный промпт остаются в кэше)
- C) Инвалидирует всё
- D) Отключает кэширование

<details><summary>Ответ</summary>

**B.** Кэш строится по иерархии `tools` → `system` → `messages`, и смена `tool_choice` затрагивает только уровень сообщений. Поэтому она не бесследна, но и не сбрасывает всё и не отключает кэширование.
→ [Подвох 5](expert.ru.md#5-tool_choice-и-кэш)

</details>

## 10. 🔴 Найдите ошибку

```python
messages.append({"role": "user", "content": [
    {"type": "text", "text": "Here are the results:"},
    {"type": "tool_result", "tool_use_id": b.id, "content": "15"}]})
```

<details><summary>Ответ</summary>

Текст перед `tool_result`: API ответит 400 («tool_use ids were found without tool_result blocks immediately after»). Результаты — первыми; лучше отправлять их одни.
→ [Подвох 1](expert.ru.md#1-текст-перед-результатами)

</details>

## 11. 🔴 Что делать при `max_tokens` с недописанным `tool_use`?

- A) Выполнить с тем, что есть
- B) Не выполнять; повторить с большим `max_tokens`
- C) Переключиться на `pause_turn`
- D) Убрать инструмент

<details><summary>Ответ</summary>

**B.** Вход может быть неполным.
→ [Подвох 8](expert.ru.md#8-обрезанный-tool_use)

</details>

## 12. 🔴 Открытый вопрос

Спроектируйте цикл для помощника с инструментом базы данных и веб-поиском, который безопасно выпускать в продакшен.

<details><summary>Ключевые мысли хорошего ответа</summary>

- Цикл с лимитом шагов и токенов; журнал каждого вызова.
- Одно сообщение пользователя со всеми `tool_result`, результаты первыми; `is_error` с понятным текстом.
- `pause_turn` обрабатывается для серверных инструментов; `max_tokens` с неполным `tool_use` — повтор.
- Результаты недоверенные: в `tool_result`; аргументы проверяются по правам; роль базы только для чтения; подтверждение человека для записи.
- Стабильный массив `tools` и `cache_control` для кэша; компактные результаты.

</details>
