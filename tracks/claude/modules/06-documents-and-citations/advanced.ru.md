# Работа с документами и цитаты: продвинутый уровень

🌐 **Русский** · [English](advanced.en.md)

**Уровни:** [overview](overview.ru.md) · [1. Основы](basics.ru.md) · **2. Продвинутый** · [3. Эксперт](expert.ru.md) · [4. Квиз](quiz.ru.md)

Опирается на [базовую теорию](basics.ru.md). Код запускался против локального мок-сервера и локальных функций; обработка настоящими моделями и точность цитат не проверялись. Часть сведений о цитатах и изображениях взята из сокращённого пересказа страниц документации (помечено).

## Виды документов и цитат

Тип документа определяет, как он делится на единицы цитирования и какое расположение вернётся:

| Документ | Источник | Разбиение | Тип цитаты | Поля расположения |
|---|---|---|---|---|
| Обычный текст | `{"type": "text", "media_type": "text/plain", "data": …}` | по предложениям | `char_location` | `start_char_index`, `end_char_index` (с нуля, конец не включается) |
| PDF | base64, URL или `file_id` | по предложениям, по страницам | `page_location` | `start_page_number`, `end_page_number` (страницы с единицы, конец не включается) |
| Свои блоки | источник типа `content` | каждый текстовый блок — одна единица | `content_block_location` | `start_block_index`, `end_block_index` (с нуля, конец не включается) |

В опыте мок вернул для обычного текста цитаты `char_location` с `cited_text`, `document_index`, `document_title`, `start_char_index`, `end_char_index`. Для PDF и своих блоков поля расположения взяты из документации.

> ⚠️ Проверить: типы `page_location` и `content_block_location`, их поля и нумерация взяты из сокращённого пересказа страницы «Citations» и в опыте не воспроизводились (мок возвращал только `char_location`).

**Совет по RAG.** Фрагменты, найденные поиском, можно передавать как документы: обычным текстом — для цитирования на уровне предложений, своими блоками — для более тонкого контроля (каждый блок цитируется целиком). Модель сама выберет, на какие фрагменты сослаться.

## Как использовать цитаты в приложении

Из ответа удобно собрать список источников без повторов:

```python
def sources(message):
    seen, out = set(), []
    for b in message.content:
        if b.type != "text": continue
        for c in (b.citations or []):
            key = (c.document_index, c.start_char_index, c.end_char_index)
            if key not in seen:
                seen.add(key); out.append((c.document_title, c.cited_text))
    return out
```

```text
[('My Document', 'The grass is green. '), ('My Document', 'The sky is blue.')]
```

(Вывод — на ответе мока.) Для PDF ключ строят по `start_page_number`/`end_page_number`. Проверка на стороне приложения: убедитесь, что `cited_text` действительно есть в исходном документе, прежде чем показывать пользователю ссылку.

Свойства цитат:

- `cited_text` **не считается** выходными токенами и не считается входными, когда ответ передают обратно в следующих ходах; зато само включение цитат добавляет входные токены (подсказки системе и разбиение документа).
- `document_index` — номер документа **по всему запросу** (по всем сообщениям), с нуля.
- Цитировать можно текст, но не изображения.
- Просьба «верни только JSON» может дать мало цитат или ни одной.

## Несовместимости

| Сочетание | Результат |
|---|---|
| Цитаты (`citations.enabled`) + `output_config.format` (структурированный вывод) | 400 ([модуль 04](../04-structured-output/advanced.ru.md)) |
| Документы с цитатами и без них в одном запросе | не допускается |
| Цитаты и `cache_control` на самих блоках цитат | кэшируется только документ верхнего уровня |

Чтобы получить структурированные данные вместе с источниками, делают два шага: сначала ответ с цитатами, затем извлечение структуры из этого ответа вторым запросом.

## Стоимость в токенах

- **PDF:** страница — обычно 1500–3000 токенов текста плюс не более 1568 визуальных токенов изображения; отдельной платы за PDF нет.
- **Изображения:** считаются патчами 28×28 пикселей, токенов — `⌈ширина/28⌉ × ⌈высота/28⌉`:

```python
import math
def visual_tokens(w, h): return math.ceil(w / 28) * math.ceil(h / 28)
print(visual_tokens(1000, 1000), visual_tokens(28, 28), visual_tokens(29, 28))
```

```text
1296 1 2
```

Слишком большие изображения уменьшаются до предела модели (для «стандартного» уровня — порядка 1568 пикселей по длинной стороне, 1568 визуальных токенов; для новых моделей — выше), поэтому заранее изменяйте размер сами: это дешевле и сохраняет контроль над координатами.

> ⚠️ Проверить: точные уровни разрешения, число токенов и правила уменьшения взяты из сокращённого пересказа страницы «Vision».

## Кэширование документов

Большой документ, к которому задают много вопросов, стоит кэшировать: `cache_control` на блоке `document`.

```python
doc = {"type": "document", "source": {"type": "base64", "media_type": "application/pdf", "data": pdf},
       "cache_control": {"type": "ephemeral"}}
```

В опыте запрос содержал `{"type": "ephemeral"}` в блоке документа. Для цитат кэшируйте **документ верхнего уровня**, а не блоки цитат; пустые текстовые блоки кэшировать нельзя. Общие правила, TTL и порядок точек — в [модуле 05](../05-prompt-caching/advanced.ru.md).

## Files API в диалогах

Каждый ход диалога пересылает всю историю, поэтому base64-изображение или PDF раздувает запрос с каждым ходом. Загрузите файл один раз и ссылайтесь по `file_id` (блоки `document` и `image` принимают `{"type": "file", "file_id": …}`). Что нужно помнить:

- файлы привязаны к **рабочему пространству**; никогда не принимайте `file_id` от конечных пользователей;
- файл нельзя изменить или переименовать: загрузите новый и удалите старый; удаление необратимо;
- срок жизни задаётся при загрузке (`expires_in_seconds`, от 1 часа до 90 дней); после истечения запрос, ссылающийся на файл, завершается ошибкой;
- Files API не подходит для ZDR и HIPAA.

## Много изображений

Каждый блок `image` считается, включая изображения из прошлых ходов и внутри результатов инструментов. Когда их больше 20 в одном запросе, действуют более строгие ограничения на размер; при нарушении API возвращает `invalid_request_error` с упоминанием «many-image requests». Выходы: уменьшить стороны (не больше примерно 3000 пикселей), сократить число изображений и документов до 20 или меньше.

## Лучшие практики

- Документы и изображения — до вопроса; несколько — с подписями.
- Один файл в нескольких запросах — `file_id` и `cache_control`.
- Цитаты — на всех документах запроса; проверять `cited_text` в приложении.
- Сложный разбор + источники — два запроса, а не `output_config.format` с цитатами.
- Сканы без текста — сначала распознать текст.
- Изменять размеры изображений заранее.

## Частые ошибки

- ❌ Цитаты на части документов → ✅ на всех.
- ❌ Цитаты и structured outputs в одном запросе → ✅ два шага.
- ❌ Пересылать большие вложения base64 в каждом ходе → ✅ `file_id`.
- ❌ Доверять ссылке без проверки → ✅ сверять `cited_text` с документом.
- ❌ Неподдерживаемый формат (docx, xlsx) → ✅ конвертировать.
- ❌ Принимать `file_id` от пользователя → ✅ хранить идентификаторы на сервере.
