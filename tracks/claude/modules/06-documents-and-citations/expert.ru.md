# Работа с документами и цитаты: экспертный уровень

🌐 **Русский** · [English](expert.en.md)

**Уровни:** [overview](overview.ru.md) · [1. Основы](basics.ru.md) · [2. Продвинутый](advanced.ru.md) · **3. Эксперт** · [4. Квиз](quiz.ru.md)

Опирается на [базовую](basics.ru.md) и [продвинутую](advanced.ru.md) теорию. Справочные данные — со страниц документации на дату подготовки; страница Files API прочитана полностью, а страницы PDF, Vision и Citations — частично (остальное в пересказе); пункты, зависящие от пересказа, помечены «сверить».

## Справочник

### Блок document

| Поле | Значение |
|---|---|
| `type` | `document` |
| `source` | `base64` (`media_type`, `data`), `url` (`url`), `file` (`file_id`), `text` (`media_type: text/plain`, `data`), `content` (свои блоки) |
| `title`, `context` | необязательные; `context` передаётся модели, но не цитируется |
| `citations` | `{"enabled": true}` |
| `cache_control` | точка кэша для документа |

Поддерживаемые типы файлов в `document` через Files API: `application/pdf` и `text/plain`; изображения (`image/jpeg`, `image/png`, `image/gif`, `image/webp`) — в блоках `image`; другие типы — `container_upload` для выполнения кода.

### Лимиты запроса

| Лимит | Значение | Источник |
|---|---|---|
| Размер запроса (Claude API) | 128 МБ | документация |
| Страниц PDF | 600; 100 при окне контекста меньше 1M | документация |
| Токены страницы PDF | 1500–3000 текст + до 1568 визуальных | документация |
| Изображение | до 10 МБ (5 МБ на Bedrock); 8000×8000 пикселей | документация |
| Изображений в запросе | 100 (контекст 200K) или 600 | документация |
| Строгие лимиты при более чем 20 изображениях | уменьшать стороны (около 3000 пикселей) или оставить ≤ 20 блоков | сверить |
| Уровни разрешения | длинная сторона 1568 / 2576 пикселей | сверить |

### Files API

| Операция | Запрос |
|---|---|
| Загрузка | `POST /v1/files`, поле multipart `file`, необязательное `expires_in_seconds` (3600–7 776 000) |
| Список | `GET /v1/files` (`limit` по умолчанию 20, максимум 1000; `page`; `ids[]` до 100) |
| Метаданные | `GET /v1/files/{file_id}` |
| Скачивание | `GET /v1/files/{file_id}/content` — только для файлов, созданных навыками или выполнением кода (для загрузок — 400) |
| Удаление | `DELETE /v1/files/{file_id}` |

Лимиты: 500 МБ на файл, 1 ТБ на организацию, имя 1–255 символов без `< > : " | ? * \ /`. Бета-заголовок не нужен. Ошибки: 404 (нет файла), 400 (тип не подходит блоку, не скачивается, превышено хранилище), 413 (больше 500 МБ). Загрузка, скачивание, список, метаданные и удаление бесплатны; содержимое в сообщениях оплачивается входными токенами; ZDR и HIPAA не поддерживаются.

### Цитаты: структура

| Поле цитаты | Значение |
|---|---|
| `type` | `char_location`, `page_location`, `content_block_location` |
| `cited_text` | дословный фрагмент |
| `document_index` | с нуля, по всем документам запроса |
| `document_title` | заголовок |
| расположение | символы (`start_char_index`, `end_char_index`), страницы (`start_page_number`, `end_page_number`, с единицы), блоки (`start_block_index`, `end_block_index`) |

При стриминге цитаты приходят событиями `content_block_delta` с дельтой `citations_delta` (по одной цитате на дельту) (сверить).

## Внутреннее устройство

- **PDF — два представления.** Каждая страница превращается в изображение, и параллельно из неё извлекается текст; модель получает оба. Поэтому сканы без текстового слоя читаются «глазами» (как изображение), но **не цитируются**.
- **Фрагментация для цитат.** Текст и PDF режутся на предложения; свои блоки не режутся. Границы единиц — основа точности ссылок.
- **`document_index` глобален.** Нумерация идёт по всем блокам `document` запроса, а не внутри одного сообщения.
- **Файлы и рабочее пространство.** `file_id` действителен внутри рабочего пространства; после `expires_at` скачивание даёт 404, а сообщение со ссылкой на файл завершается ошибкой, хотя метаданные остаются читаемыми до 30 дней.
- **Токены цитат.** `cited_text` не входит в выходные токены, но включение цитат увеличивает входные.
- **Кэш.** Цитируемые блоки не кэшируются сами по себе; кэшируется документ верхнего уровня.

> ⚠️ Проверить: детали стриминга цитат, блоков `search_result`, ограничения на пакетные запросы и ZDR для PDF в этом материале не проверялись; часть лимитов изображений взята из сокращённого пересказа.

## Подвохи

### 1. Цитаты и structured outputs

Вместе дают 400.

### 2. Цитаты на части документов

Либо на всех документах запроса, либо ни на одном.

### 3. Скан без текста

Цитировать нечего; сначала распознайте текст.

### 4. `document_index` — глобальный

Считается по всем документам запроса, не по сообщению.

### 5. Base64 раздувает диалог

Каждый ход пересылает историю целиком: используйте `file_id`.

### 6. Файлы привязаны к рабочему пространству

Не принимайте `file_id` от пользователей.

### 7. Файлы нельзя править

Загрузите новый, удалите старый.

### 8. Вопрос перед документом

Ухудшает результат: документ — перед вопросом.

### 9. Много изображений

Более 20 — более строгие ограничения размера (`many-image requests`).

## Компромиссы и альтернативы

| Подход | Плюсы | Минусы |
|---|---|---|
| `document` с base64 | просто, без хранилища | раздувает запросы |
| Files API | загрузка один раз | управление жизненным циклом, привязка к рабочему пространству |
| URL-источник | нет загрузки на стороне клиента | нужна доступность URL (не на всех платформах) |
| Цитаты Claude | встроенные ссылки с границами | несовместимы со structured outputs |
| Извлечение текста самим (OCR, парсер) | полный контроль | потеря верстки и изображений |
| RAG с поиском | масштабируется на большие коллекции | инфраструктура ([LLM](../../../llm/overview.ru.md)) |

## Вопросы с собеседований

<details><summary>1. Какие способы передать PDF существуют?</summary>

Блок `document` с источником base64, URL или `file_id`; обычный текст — источник `text`.

→ [Базовая теория](basics.ru.md#блок-document-и-источники)

</details>

<details><summary>2. Какие лимиты у PDF?</summary>

До 600 страниц (100 при контексте меньше 1M) и 128 МБ на запрос; страница — 1500–3000 токенов текста плюс токены изображения.

→ [Базовая теория](basics.ru.md#лимиты-pdf)

</details>

<details><summary>3. Как включить цитаты и как выглядит ответ?</summary>

`"citations": {"enabled": true}` на документе; ответ — список блоков `text`, у некоторых есть массив `citations` с `cited_text` и расположением.

→ [Базовая теория](basics.ru.md#цитаты)

</details>

<details><summary>4. Подвох: почему вместе с цитатами не работает <code>output_config.format</code>?</summary>

Они несовместимы: запрос возвращает 400; нужно два шага.

→ [Подвох 1](#1-цитаты-и-structured-outputs)

</details>

<details><summary>5. Чем <code>char_location</code> отличается от <code>page_location</code>?</summary>

Первый — для текста (индексы символов с нуля), второй — для PDF (номера страниц с единицы); концы не включаются.

→ [Продвинутая теория](advanced.ru.md#виды-документов-и-цитат)

</details>

<details><summary>6. Зачем нужен Files API?</summary>

Загрузить файл один раз и ссылаться по `file_id`, не пересылая base64 в каждом ходе.

→ [Продвинутая теория](advanced.ru.md#files-api-в-диалогах)

</details>

<details><summary>7. Подвох: <code>cited_text</code> входит в выходные токены?</summary>

Нет, не входит.

→ [Справочник](#цитаты-структура)

</details>

<details><summary>8. Можно ли цитировать изображения и сканы?</summary>

Нет: цитируется только текст.

→ [Подвох 3](#3-скан-без-текста)

</details>

<details><summary>9. Как кэшировать документ?</summary>

`cache_control` на блоке `document` верхнего уровня.

→ [Продвинутая теория](advanced.ru.md#кэширование-документов)

</details>

<details><summary>10. Подвох: <code>file_id</code> пользователя можно передать в запрос?</summary>

Нельзя принимать `file_id` от пользователей: файлы привязаны к рабочему пространству.

→ [Подвох 6](#6-файлы-привязаны-к-рабочему-пространству)

</details>

<details><summary>11. Как посчитать токены изображения?</summary>

`⌈ширина/28⌉ × ⌈высота/28⌉`, с учётом уменьшения слишком больших изображений.

→ [Продвинутая теория](advanced.ru.md#стоимость-в-токенах)

</details>

<details><summary>12. Куда ставить документ относительно вопроса?</summary>

Перед вопросом: документы и изображения — до текста.

→ [Подвох 8](#8-вопрос-перед-документом)

</details>

## Шпаргалка

```text
{"type": "document", "source": {"type": "base64"|"url"|"file"|"text"|"content", …}, "title"?, "context"?, "citations": {"enabled": true}?, "cache_control"?}
{"type": "image", "source": {"type": "base64"|"url"|"file", …}}
PDF: ≤600 стр (100 при контексте <1M), ≤128 МБ; страница ≈1500–3000 токенов + изображение
цитаты: text-блоки с citations[]; char_location | page_location | content_block_location; несовместимы с output_config.format
Files API: POST/GET/DELETE /v1/files; expires_in_seconds; 500 МБ на файл
```

- Документ — перед вопросом.
- Цитаты — на всех документах или ни на одном.
- `file_id` — не от пользователей.
